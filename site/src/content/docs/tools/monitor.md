모니터는 DB 서버의 지금 상태를 읽어 보여 주는 도구입니다. 세션 모니터는 세션 목록과 블로킹 트리, SQL 모니터는 부하가 큰 SQL, Lock 모니터는 잠금 대기를 보여 줍니다. 상태 표시줄에는 다른 세션을 막고 있는 세션이 있는지 알려 주는 항목이 있습니다.

- 세션 모니터와 Lock 모니터는 **모니터** 메뉴에서, SQL 모니터는 **튜닝** 메뉴에서 엽니다. 기능이 꺼져 있으면 메뉴에 나타나지 않습니다. 설정 창의 「기능」 탭에서 주 업무를 바꾸거나 해당 기능을 켜세요. [설정](../../settings/options/)을 보세요.
- 모니터는 `V$` 뷰와 `gv$` 뷰를 읽습니다. 읽기만 하며, 세션 종료·트레이스처럼 DB에 쓰는 동작은 따로 표시합니다.

## 모니터 전용 세션과 접속

모니터는 작업 접속과 별개의 **모니터 전용 세션**을 엽니다. 작업 중인 SQL 탭이나 트랜잭션에 영향을 주지 않습니다.

- 기본은 지금 작업 접속의 접속 정보입니다. 저장된 비밀번호가 없으면 비밀번호를 묻습니다.
- 모니터 창 위쪽의 「다른 접속…」 단추로 저장된 접속 중에서 다른 접속을 고릅니다. 접속 고르기 창의 제목은 「{모니터 이름} 접속 고르기」이고 단추는 「열기」와 「취소」입니다. 목록에는 폴더, 접속 이름, 계정과 주소가 보이고 운영 접속에는 「운영」 표시가 붙습니다. 작업 접속은 그대로입니다.
- 모니터 창 머리에 「모니터 접속: …」이 보입니다. 운영 접속이면 환경 색으로 표시합니다.
- 다른 접속으로 연 접속은 다음에 그 모니터를 열 때의 기본 접속으로 기억합니다. 비밀번호는 기억하지 않습니다.
- 작업 접속이 없으면 접속 고르기 창이 바로 나옵니다. 저장된 접속이 없으면 열 수 없습니다.

### 권한 안내 띠

접속 계정이 `V$` 뷰를 읽을 수 없으면 창 위쪽에 띠가 나타납니다.

- 문구: 「이 접속({계정})은 V$ 뷰를 읽을 권한이 없어 모니터를 쓸 수 없습니다. DBA 가 `GRANT SELECT_CATALOG_ROLE TO {계정};` (또는 SELECT ANY DICTIONARY)를 주거나, 권한 있는 다른 접속으로 여세요.」
- 「다른 접속으로 열기…」: 권한 있는 접속을 골라 다시 엽니다.
- 「SQL 복사」: `GRANT` 문을 복사해 DBA에게 보냅니다.
- 점검을 통과해도 일부 뷰에서 `ORA-00942`나 `ORA-01031`이 나면 같은 띠가 나타납니다.

## 세션 모니터

**모니터 > 세션 모니터**나 도구 모음의 세션 단추로 엽니다. 접속하지 않았거나 모니터 세션을 열지 못하면 상태 줄에 이유가 나옵니다.

### 도구 모음과 목록

| 단추 | 하는 일 |
|---|---|
| 새로 고침 (F5) | 목록을 다시 읽습니다. |
| 자동 | 일정 간격으로 자동으로 다시 읽습니다. 간격은 설정 창의 「모니터」 탭에서 정합니다. |
| 델타 | 직전 새로 고침과의 차이로 봅니다. 목록의 「델타」 열에 보입니다. |
| 상세 | 고른 세션의 현재 SQL, 계획, 잠금, 통계를 「상세」 탭에 보입니다. 목록의 줄을 두 번 눌러도 됩니다. |
| 세션 종료 | `ALTER SYSTEM KILL SESSION … IMMEDIATE`를 보냅니다. |
| 연결 끊기 | `ALTER SYSTEM DISCONNECT SESSION … IMMEDIATE`를 보냅니다. |
| 트레이스 켜기, 끄기 | 고른 세션의 SQL 트레이스를 켜고 끕니다. 「waits」, 「binds」 확인란으로 트레이스에 넣을 것을 고릅니다. |
| 다른 접속… | 위의 「모니터 전용 세션과 접속」을 보세요. |

- 거르기 줄: 「사용자」, 「머신·프로그램·모듈·SQL ID」 칸과 「활성만」, 「백그라운드」 확인란입니다.
- 목록 열: SID,SERIAL#, 사용자, 상태, 경과(초), 블로커, 대기 이벤트, SQL ID, 프로그램, 델타입니다. 목록은 결과 그리드와 같아서 머리글을 눌러 정렬하고 열을 끌어 옮기며 열 필터를 쓸 수 있습니다.
- 도구 모음의 동작은 **모니터** 메뉴와 목록의 오른쪽 클릭 메뉴에도 있습니다.

| 메뉴 항목 | 단축키 | 켜지는 조건 |
|---|---|---|
| 모니터 새로 고침 | `F5` | 세션 모니터가 열려 있을 때 |
| 자동 새로 고침 켜기/끄기 | 없음 | 세션 모니터가 열려 있을 때 |
| 델타 모드 | 없음 | 세션 모니터가 열려 있을 때 |
| 블로킹 트리 | 없음 | 세션 모니터가 열려 있을 때 |
| 세션 상세 | 없음 | 세션을 골랐을 때 |
| 세션 종료(KILL)… | 없음 | 세션을 고르고 계정에 종료 권한이 있을 때 |
| 세션 연결 끊기(DISCONNECT)… | 없음 | 세션을 고르고 계정에 종료 권한이 있을 때 |
| SQL 트레이스 켜기, 끄기 | 없음 | 세션을 고르고 계정에 트레이스 권한이 있을 때 |

### 아래 탭

- 「블로킹 트리」: 세션을 막고 있는 세션과 막힌 세션을 트리로 보입니다.
- 「상세」: 고른 세션의 현재 SQL, 계획, 잠금, 통계를 글로 보입니다.
- 「튜닝 추천」: 지금 활성 세션이 실행 중인 SQL에 SQL 모니터와 같은 규칙을 적용합니다. 「검사」 단추를 눌러야 읽습니다. 걸린 규칙이 있는 SQL이 위에 나옵니다. 「SQL 모니터의 튜닝 추천에서 보기」 단추로 SQL 모니터의 추천 탭을 엽니다. 자세한 내용은 [SQL 튜닝](../../plan/tuning/)을 보세요.

### 세션 종료 확인

「세션 종료」와 「연결 끊기」는 DB에 씁니다. 누르면 확인 창이 나옵니다.

- 확인 창에는 대상 세션의 SID, SERIAL#, 인스턴스, 사용자, OS 사용자, 머신, 프로그램, 모듈, 상태, SQL ID가 나옵니다. 꼭 대상 세션인지 확인하세요.
- 확인하지 않거나 취소하면 보내지 않고 상태 줄에 「… 을(를) 취소했습니다.」가 나옵니다.
- 확인한 뒤에도 실행 엔진의 위험 명령 확인과 접속의 정책 관문을 거칩니다. 정책이 막으면 보내지 않습니다.
- 끝나면 상태 줄에 「SID {n}: … 을(를) 마쳤습니다.」가 나옵니다.
- 트레이스를 켜면 상태 줄에 트레이스 파일 경로가 나옵니다.

## SQL 모니터(Top SQL)

**튜닝 > SQL 모니터(Top SQL)**로 엽니다. 서버 캐시의 SQL을 소요 시간, 읽은 블록 같은 기준으로 위에서부터 보여 줍니다.

### 조건

도구 모음 위쪽의 선택입니다.

| 선택 | 설명 |
|---|---|
| 프리셋 | 「사용자 지정」, 「느린 SQL (1 s 이상, 1만 블록 이상)」, 「Critical (10 s 이상)」, 「OLTP (100회 이상 실행, 실행당 느린 순)」, 「Batch (60 s 이상, 읽은 블록 순)」입니다. 프리셋을 고르면 아래 조건 칸과 정렬이 채워집니다. |
| 정렬 | 「소요 시간」, 「CPU 시간」, 「읽은 블록」, 「디스크 읽기」, 「실행 횟수」, 「실행당 소요 시간」입니다. |
| 상위 | 보일 SQL 수입니다. 1부터 1000까지입니다. |

거르기 줄의 칸은 값이 있는 칸만 조건이 됩니다: 「SQL 텍스트·SQL ID」, 「스키마」, 「소요 시간(초) ≥」, 「읽은 블록 ≥」, 「실행 횟수 ≥」, 「최근 N분」입니다. 조건을 정하고 「검색」을 누릅니다.

### 도구 모음과 목록

| 단추 | 하는 일 |
|---|---|
| 검색 | 조건에 맞는 SQL을 읽습니다. 메뉴 이름은 「Top SQL 검색」입니다. |
| 실제 계획 | 고른 SQL의 실제 계획을 아래 탭에 보입니다. 메뉴 이름은 「선택 SQL 실제 계획」입니다. |
| 전문·바인드 | 고른 SQL의 전문과 캡처된 바인드를 아래 탭에 보입니다. 메뉴 이름은 「선택 SQL 바인드 캡처」입니다. |
| 자식 커서 | 고른 sql_id의 자식 커서와 따로 생긴 사유를 문서 탭으로 엽니다. |
| 튜닝 보고서… | 고른 sql_id의 계획, 통계, 커서, 후보를 HTML 파일 하나로 만듭니다. |
| Tuning Advisor 스크립트 | `DBMS_SQLTUNE` 문안을 새 편집기 탭에 넣습니다. 실행하지 않습니다. |
| baseline 고정 스크립트 | `DBMS_SPM.LOAD_PLANS_FROM_CURSOR_CACHE` 문안을 새 편집기 탭에 넣습니다. 실행하지 않습니다. |
| 다른 접속… | 모니터 전용 세션을 다른 접속으로 엽니다. |

- 목록 열: SQL ID, 자식, 소요(s), CPU(s), 실행, 읽은 블록, 디스크, 스키마, SQL(앞부분)입니다. 목록은 결과 그리드와 같아서 정렬, 열 끌기, 열 필터를 쓸 수 있습니다.
- 아래 탭은 「전문·바인드」, 「실제 계획」, 「대기 분해」, 「AWR 계획 이력」, 「계획 관리」, 「튜닝 추천」입니다. 뒤의 네 탭과 튜닝 도구는 [SQL 튜닝](../../plan/tuning/)에서 설명합니다.
- 「자식 커서」와 「튜닝 보고서…」 단추는 해당 기능이 켜져 있을 때만 보입니다.
- `DBMS_SQLTUNE`과 `DBMS_SPM` 스크립트는 실행하면 DB에 씁니다. 내용을 확인한 뒤 직접 실행하세요. Tuning Advisor 스크립트는 Tuning Pack이 필요합니다.
- ASH와 AWR을 읽는 탭은 접속에 해당 관리 팩 보유를 선언해야 씁니다. 선언은 접속 편집의 고급 설정에서 합니다.

## Lock 모니터

**모니터 > Lock 모니터**로 엽니다. 행 잠금 때문에 기다리는 세션과 막고 있는 세션을 보여 줍니다. 접속이 없으면 「접속이 없습니다」와 「접속 관리자 열기」 단추가 보입니다. 잠금 대기가 없으면 「대기 중인 잠금이 없습니다」가 보입니다.

### 도구 모음

| 단추 | 하는 일 |
|---|---|
| 새로 고침 (F5) | 다시 읽습니다. 읽는 동안 `Esc`나 「취소 (Esc)」로 멈춥니다. |
| 자동 | 자동으로 다시 읽습니다. 간격은 설정 창의 「모니터」 탭에서 정합니다. |
| 세션 종료 | 고른 세션에 `ALTER SYSTEM KILL SESSION … IMMEDIATE`를 보냅니다. `Delete` 키로도 보냅니다. 확인 창이 나옵니다. |
| 연결 끊기 | `ALTER SYSTEM DISCONNECT SESSION … IMMEDIATE`를 보냅니다. 확인 창이 나옵니다. |
| 세션 모니터로 | 고른 세션을 세션 모니터에서 고릅니다. |
| 복사 | 트리와 목록을 탭 구분 글로 복사합니다. |
| CSV 내보내기 | 잠금 목록을 CSV 파일로 저장합니다. |
| 알림 설정 | 임계치 알림과 이력 보관을 정합니다. |
| 다른 접속… | 모니터 전용 세션을 다른 접속으로 엽니다. |

거르기 줄에서는 「최소 대기」(초), 「3 초 이상」, 「사용자」, 「스키마」, 「대기·차단만」으로 목록을 줄입니다. 결과가 없으면 「거르기 풀기」나 「모든 잠금 보기」 단추가 나옵니다. 이름이 같은 명령은 메뉴와 명령 팔레트에도 있습니다.

| 메뉴 이름 | 하는 일 |
|---|---|
| Lock 새로 고침 | 다시 읽습니다. `F5` |
| 자동 새로 고침 켜기/끄기 | 자동 읽기를 켜고 끕니다. |
| 보유자·대기자 SQL 보기 | 「SQL 전문」 탭을 엽니다. |
| 잠긴 행 보기 | 「잠긴 행」 탭을 엽니다. |
| DDL 잠금 보기 | 「DDL 잠금」 탭을 엽니다. |
| 세션 종료(KILL)…, 세션 연결 끊기(DISCONNECT)… | 위 단추와 같습니다. |
| 세션 모니터에서 보기 | 위 「세션 모니터로」와 같습니다. |
| Lock 목록 CSV 내보내기… | 위 「CSV 내보내기」와 같습니다. |
| Lock 이력 띠 보이기/감추기 | 아래의 이력 띠를 보이거나 감춥니다. |

### 위쪽 탭

- 「대기 트리」: 보유자와 대기자를 트리로 보입니다. 열은 세션(인스턴스·SID), 사용자, 상태, 대기, 이벤트, 객체, sql_id입니다. 기다리는 세션이 없으면 「기다리는 세션이 없습니다. 아래 잠금 목록은 거른 조건의 잠금입니다.」가 나옵니다. 순환 대기가 있으면 위에 「순환 대기 감지:」 띠가 나오고 「트리에서 보기」 단추로 순환의 첫 세션을 고릅니다.
- 「보유자 영향 순위」: 막고 있는 세션을 영향 순으로 보입니다. 열은 #, 보유자, 사용자, 상태, 대기자, 최대 대기, 합계 대기, 트랜잭션 경과, 프로그램입니다.
- 「방치 트랜잭션」: 트랜잭션을 연 채 쉬는(INACTIVE) 세션을 경과 순으로 보입니다. 「60 초 이상만」 확인란을 끄면 짧게 쉰 세션도 봅니다. 커밋을 빠뜨린 세션을 찾을 때 씁니다.
- 「DDL 잠금」: `dba_ddl_locks`를 읽습니다. 권한이 없으면 안내와 `GRANT` 문이 나오고 「SQL 복사」로 복사합니다. 다른 탭은 그대로 동작합니다.
- 「데드락 기록」: 최근 24시간의 `ORA-00060`을 alert 로그에서 읽기 전용으로 보입니다. 행에서 `Enter`를 누르면 편집기로 엽니다. 이 버전이 읽지 못하는 서버에서는 「이 버전은 데드락 기록을 읽지 않습니다」가 나옵니다. 순환 대기 띠는 이 경우에도 동작합니다.
- 아래의 「잠금 목록」: 잠금 줄마다 보입니다. TM은 객체, TX는 트랜잭션 시작과 undo입니다.

### 오른쪽 탭

고른 세션에 대한 자세한 내용입니다.

- 「SQL 전문」: 보유자와 대기자의 SQL입니다. 보유자가 지금 실행 중인 SQL이 없으면 마지막 SQL(prev_sql_id)을 보이고 커밋이 빠졌을 수 있다고 알립니다. 「편집기로 열기」는 새 SQL 탭에 넣고 실행하지 않습니다. 「복사」는 SQL을 복사합니다. 「실제 계획」은 대기자 SQL의 실제 계획을 계획 창에 엽니다.
- 「잠긴 행」: 대기 이벤트가 `enq: TX - row lock contention`일 때만 보입니다. 값은 SELECT로만 읽습니다. 「SELECT 문 복사」 단추가 있습니다.
- 「바인드」: `gv$sql_bind_capture`가 남긴 값입니다. 일정 간격(기본 15분)으로만 남기므로 지금 대기 중인 실행의 값과 다를 수 있습니다.
- 「원인 힌트」: 상황에 맞는 원인과 「할 일」을 보입니다. 「확인 SELECT 복사」 단추로 확인용 SELECT를 복사합니다.

### 이력 띠

창 아래의 이력 띠는 새로 고침마다 쌓은 대기자 수와 최대 대기를 그림으로 보입니다. 이력은 앱 메모리에만 쌓이고 DB에 쓰지 않습니다. 새로 고침을 여러 번 해야 점이 쌓입니다.

### 임계치 알림

「알림 설정」을 누르면 나오는 창에서 정합니다. 이 설정은 앱 설정 파일에만 저장하고 DB에 쓰지 않습니다.

| 항목 | 설명 |
|---|---|
| 임계치 알림 켜기 | 알림을 켭니다. |
| 대기 … 초 이상 또는 대기자 … 개 이상 | 둘 중 하나를 넘으면 알립니다. 처음 값은 120초와 5개입니다. |
| 그 시점 보유자·대기자 SQL 스냅샷 저장 | 알린 때의 SQL을 저장합니다. 처음 값은 켜짐입니다. |
| 창이 뒤에 있어도 알림 띄우기 | 처음 값은 켜짐입니다. |
| 이력 보관 | 이력을 남길 시간(분)입니다. 5분부터 720분까지이고 처음 값은 30분입니다. |
| 로컬 파일로도 저장 | 앱 데이터 폴더의 `lock-history` 폴더에 저장합니다. 처음 값은 꺼짐입니다. 「스냅샷 폴더 열기」로 폴더를 엽니다. |

기준을 넘으면 「잠금 대기가 기준을 넘었습니다」 알림이 나옵니다.

### 세션 종료 확인

Lock 모니터의 「세션 종료」와 「연결 끊기」도 확인 창이 나옵니다. 창 제목은 「{동작} 확인」입니다.

- 위쪽 띠에 접속 환경(운영, 테스트, 개발)이 색으로 보입니다.
- 질문, 대상 세션 정보, 이 세션이 막고 있는 세션이 있을 때의 경고, 실제로 보낼 문장이 나옵니다. 「종료하면 열린 트랜잭션은 롤백됩니다. undo 가 크면 롤백에 시간이 걸리고 그동안 잠금이 남을 수 있습니다.」라는 안내와 「이 명령은 DB 에 씁니다(세션 상태 바꿈).」도 있습니다. 연결 끊기도 같은 뜻의 안내가 나옵니다.
- 「취소」가 기본 단추이므로 `Enter`를 누르면 취소됩니다. 동작 이름의 단추를 눌러야 보냅니다.
- 취소하면 상태 줄에 「… 을(를) 취소했습니다.」가 나옵니다.

## 상태 표시줄의 막음 알림

상태 표시줄의 항목이 작업 접속의 세션이 다른 세션을 막고 있는지 알려 줍니다.

| 표시 | 뜻 |
|---|---|
| {n} 세션 막음(빨강) | 이 세션이 n개 세션을 막고 있습니다. |
| 미커밋 {n}분(주황) | 미커밋 상태가 10분을 넘었습니다. 커밋하거나 롤백하세요. |
| ⚠ {n} 세션 막음 · {m} 초(빨강) | Lock 모니터의 임계치 알림 기준을 넘었습니다. |
| {n}분 뒤 서버가 이 세션을 끊음 | 서버의 `MAX_IDLE_BLOCKER_TIME` 설정에 따라 서버가 이 세션을 끊습니다. |
| 감시 꺼짐(회색) | 권한이 없거나 비밀번호가 저장되지 않아 감시하지 못합니다. 비밀번호가 없으면 항목을 눌러 비밀번호를 넣고 켭니다. |

- 항목에 마우스를 올리면 자세한 설명이 나옵니다. 항목을 누르면 Lock 모니터가 열립니다. 이미 열려 있으면 앞으로 가져와 다시 읽습니다.
- Lock 모니터 기능이 꺼져 있으면 「Lock 모니터 기능이 꺼져 있습니다. 설정 > 기능에서 켤 수 있습니다.」와 「설정 열기」 단추가 나옵니다.
- 이 항목은 막음 감시 기능이 꺼져 있으면 보이지 않습니다.

## 설정

- 설정 창의 「모니터」 탭에서 「새로 고침(초)」을 정합니다. 처음 값은 5초이고 2초부터 60초까지입니다. 세션 모니터와 Lock 모니터의 자동 새로 고침에 씁니다. [설정](../../settings/options/)을 보세요.

## 자주 하는 작업

### 오래 걸리는 쿼리를 찾아 계획 보기

1. **튜닝 > SQL 모니터(Top SQL)**를 엽니다.
2. 프리셋 「느린 SQL (1 s 이상, 1만 블록 이상)」을 고르고 「검색」을 누릅니다.
3. 목록에서 SQL을 고릅니다.
4. 「전문·바인드」 탭에서 SQL 전문을 확인합니다.
5. 「실제 계획」을 눌러 계획을 확인합니다.

### 다른 세션을 막고 있는 세션 찾기

1. 상태 표시줄에 막음 알림이 있으면 항목을 눌러 Lock 모니터를 엽니다. 없으면 **모니터 > Lock 모니터**를 엽니다.
2. 「대기 트리」에서 맨 위의 보유자를 고릅니다.
3. 오른쪽의 「SQL 전문」 탭에서 보유자가 무엇을 하고 있는지 봅니다. 실행 중인 SQL이 없고 트랜잭션만 열려 있으면 커밋이 빠졌을 수 있습니다.
4. 보유자 사용자에게 커밋이나 롤백을 요청합니다.
5. 더 기다릴 수 없으면 「세션 종료」를 누르고 확인 창의 대상 세션을 확인한 뒤 보냅니다.

### 세션 하나의 SQL 트레이스 켜기

1. **모니터 > 세션 모니터**를 엽니다.
2. 목록에서 세션을 고릅니다.
3. 필요하면 「waits」, 「binds」를 체크합니다.
4. 「트레이스 켜기」를 누릅니다. 상태 줄에 트레이스 파일 경로가 나옵니다.
5. 끝나면 「끄기」를 누릅니다.

트레이스를 읽는 방법은 [SQL 튜닝](../../plan/tuning/)의 「옵티마이저 트레이스와 트레이스 보기」를 보세요.

## 문제가 생길 때

| 증상 | 원인과 해결 |
|---|---|
| 「… V$ 뷰를 읽을 권한이 없어 모니터를 쓸 수 없습니다」 띠가 나옵니다 | 접속 계정에 권한이 없습니다. 띠의 「SQL 복사」로 `GRANT` 문을 복사해 DBA에게 요청하거나 「다른 접속으로 열기…」로 권한 있는 접속을 고르세요. |
| 「세션 종료」, 「연결 끊기」, 「트레이스 켜기」가 회색입니다 | 세션을 고르지 않았거나 계정에 해당 권한이 없습니다. |
| 「모니터 세션을 열지 못했습니다: …」가 나옵니다 | 접속 정보나 네트워크를 확인하세요. 접속 정보가 없으면 접속 관리자에서 접속을 먼저 만듭니다. |
| 상태 표시줄에 「감시 꺼짐」이 나옵니다 | 계정에 `V$` 조회 권한이 없거나 비밀번호가 저장되지 않았습니다. 항목에 마우스를 올려 이유를 확인하세요. |
| Lock 모니터의 「DDL 잠금」 탭에 권한 안내가 나옵니다 | `dba_ddl_locks`를 읽을 권한이 없습니다. 안내의 `GRANT` 문을 DBA에게 요청하세요. 다른 탭은 그대로 씁니다. |
| Lock 모니터 「바인드」 탭의 값이 지금 실행과 다릅니다 | 바인드 값은 일정 간격으로만 캡처됩니다. 지금 값과 다를 수 있습니다. |
