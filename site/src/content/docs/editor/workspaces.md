작업 공간은 SQL 탭 여러 개를 하나로 묶은 단위이고, 작업 공간 하나가 문서 영역의 문서 탭 하나입니다. 이 쪽에서는 작업 공간을 만들고, 이름을 바꾸고, 파일로 저장하고, 다시 여는 방법을 설명합니다.

## 작업 공간이 보존되는 방법

SQL 탭 자체는 [SQL 편집기](../sql-editor/)를 보세요. 작업 공간은 두 가지 방법으로 보존됩니다.

- 앱이 자동으로 보존합니다. 작업 공간을 닫거나 앱을 끝내면 앱의 저장 폴더에 남고, 편집 중에는 주기적으로 임시본을 남깁니다.
- 사용자가 파일로 저장합니다. `이름.workspace.md` 파일 하나에 SQL 탭이 모두 들어가므로 다른 PC로 옮기거나 버전 관리에 올릴 수 있습니다.

## 파일 메뉴의 작업 공간 명령

작업 공간 명령은 **파일 > 작업 공간**에 모여 있습니다. 이 명령들에는 기본 단축키가 없습니다. 필요하면 [단축키와 명령 팔레트](../../settings/shortcuts/)에서 지정하세요.

| 메뉴 | 하는 일 |
|---|---|
| 새 작업 공간 | 빈 SQL 탭이 하나 있는 작업 공간을 새로 엽니다. 도구 모음에도 같은 이름의 단추가 있습니다. |
| 작업 공간 열기… | 작업 공간 파일을 고르는 창을 엽니다. |
| 최근 작업 공간 | 최근에 열거나 저장한 작업 공간 파일을 보입니다. 맨 아래의 「목록 지우기」는 목록을 비웁니다. |
| 작업 공간 저장 | 작업 공간을 `.workspace.md` 파일로 저장합니다. 도구 모음에도 같은 이름의 단추가 있습니다. |
| 작업 공간 다른 이름으로 저장… | 저장 위치를 항상 묻고 저장합니다. |
| 작업 공간 이름 바꾸기 | 작업 공간 이름을 바꿉니다. |
| 작업 공간 닫기 | 작업 공간을 닫습니다. |

- 「작업 공간 저장」과 「작업 공간 다른 이름으로 저장…」은 열린 문서가 있어야 켜지고, MyBatis 작업 공간에서는 쓸 수 없습니다. 자세한 내용은 [MyBatis 작업 공간](../mybatis/)을 보세요.
- 「작업 공간 이름 바꾸기」와 「작업 공간 닫기」는 SQL 작업 공간이 있어야 켜집니다. 이유는 「SQL 작업 공간이 있어야 쓸 수 있습니다」입니다.
- 새 작업 공간의 이름은 「작업 공간 2」, 「작업 공간 3」처럼 쓰고 있지 않은 번호를 붙입니다. 앱을 처음 실행하면 「기본」이라는 작업 공간 하나가 만들어집니다.

## 작업 공간 문서 탭

작업 공간 이름은 문서 영역 위쪽의 문서 탭에 보입니다. 고친 SQL 탭이 있으면 이름 앞에 `* `가 붙습니다. 파일에서 연 작업 공간이면 이름 뒤에 `(md)`, `(sqd)`, `(MyBatis)`가 붙습니다.

- 문서 탭을 두 번 누르면 이름 바꾸기 창이 열립니다.
- 문서 탭을 오른쪽 클릭하면 「이름 바꾸기」와 「닫기」가 나옵니다. MyBatis 기능이 켜져 있으면 그 아래에 MyBatis 관련 명령이 더 나올 수 있습니다.
- SQL 작업 공간 문서 탭은 따로 떼어 내 새 창으로 만들 수 없습니다.

## 작업 공간 이름 바꾸기 창

이름 바꾸기 창의 제목은 「작업 공간 이름 바꾸기」입니다. 입력 칸에 현재 이름이 들어 있고 전체가 선택돼 있습니다. 새 이름을 입력하고 「확인」을 누르면 이름이 바뀝니다. 「취소」를 누르면 이름을 바꾸지 않고 닫습니다.

- 이름의 앞뒤 공백은 지웁니다. 이름을 비워 두고 확인하면 아무것도 바뀌지 않습니다.
- 이름을 바꿔도 작업 공간이 쓰는 파일은 바로 바뀌지 않습니다.
- 작업 공간이 `.workspace.md` 파일에 묶여 있으면, 다음 **작업 공간 저장** 때 파일도 같은 폴더의 새 이름으로 옮깁니다. 그 이름의 파일이 이미 있으면 덮어쓰지 않고 저장 위치를 다시 묻습니다.

## 작업 공간 파일

작업 공간 파일은 Markdown 파일입니다. 이름은 `이름.workspace.md` 형식입니다. 아래는 SQL 탭이 둘인 작업 공간 파일의 예입니다.

````markdown
# 주문 점검

<!-- oranda-workspace 1 -->

## 부서별 사원

```sql
SELECT dept_id, COUNT(*)
  FROM employees
 GROUP BY dept_id
```

## 미취소 주문

```sql
SELECT order_id, status, total_amount
  FROM orders
 WHERE status <> 'CANCELLED'
```
````

- 첫 줄의 `# 이름`이 작업 공간 이름입니다. `## 제목`이 SQL 탭 이름이고, 그 아래의 `sql` 코드 블록이 탭의 SQL입니다.
- 둘째 줄의 `<!-- oranda-workspace 1 -->`는 표지입니다. 손으로 쓴 Markdown 파일에는 없어도 열립니다.
- SQL 탭에 접속이 묶여 있으면 `## 제목` 아래에 `<!-- connection: 번호 -->` 줄이 들어갑니다. 번호는 접속마다 Oranda가 붙인 내부 번호이고 비밀번호는 들어가지 않습니다.
- SQL 안에 백틱 세 개가 연달아 나오면 코드 블록의 울타리를 그보다 길게 씁니다.
- 바인드 변수 값도 저장합니다. 값이 있으면 코드 블록 끝에 `-- @oranda-binds v1`로 시작하는 주석 줄이 붙습니다.

:::caution[바인드 값이 평문으로 들어갑니다]
이름에 `pass`, `pwd`, `secret`, `token`이 들어 있는 바인드 변수도 값이 그대로 파일에 저장됩니다. 파일을 공유하거나 버전 관리에 올리기 전에 바인드 값을 확인하세요.
:::

손으로 쓴 Markdown 파일도 작업 공간으로 열 수 있습니다. 읽는 규칙은 다음과 같습니다.

- 파일의 첫 `# 제목`이 작업 공간 이름입니다. 없으면 파일 이름을 씁니다.
- `## 제목` 아래의 첫 코드 블록이 그 제목을 이름으로 가진 SQL 탭이 됩니다. 같은 제목 아래의 둘째 코드 블록은 설명용으로 보고 건너뜁니다.
- 제목이 없는 코드 블록은 「SQL 1」, 「SQL 2」 같은 이름의 탭이 됩니다.
- 코드 블록이 하나도 없으면 파일 전체가 탭 하나가 됩니다.
- 코드 블록의 울타리는 백틱 세 개 이상이나 물결표 세 개 이상입니다.

예전에 `이름.md`로 저장한 파일도 그대로 열립니다. 이미 있는 `.md` 파일에 저장할 때는 그 이름을 유지합니다. 새 `.md` 이름은 `.workspace.md`로 바꿔 저장합니다.

## 작업 공간 저장과 열기

### 저장

**작업 공간 저장**은 현재 작업 공간의 모든 SQL 탭을 파일 하나에 씁니다.

- 처음 저장하면 「작업 공간 파일로 저장」 창이 뜹니다. 파일 종류는 「Oranda 작업 공간 (*.workspace.md)」와 「Markdown 파일 (*.md)」입니다. 제안하는 이름은 작업 공간 이름에 `.workspace.md`를 붙인 것입니다.
- 이미 파일에 묶인 작업 공간은 창 없이 그 파일에 바로 씁니다.
- Orange `.sqd` 파일이나 MyBatis 매퍼 `.xml` 파일에서 연 작업 공간은 원본에 쓰지 않습니다. 저장하면 저장 위치를 묻고 새 `.workspace.md` 파일을 만듭니다.
- **작업 공간 다른 이름으로 저장…**은 항상 저장 위치를 묻습니다.
- 저장하고 나면 작업 공간 이름이 파일 이름으로 바뀌고 문서 탭에 `(md)`가 붙습니다.
- 파일에 묶이지 않은 SQL 탭은 저장 후 변경 표시(`* `)가 사라집니다. 파일에 묶인 SQL 탭은 작업 공간 파일에 글이 들어가지만 변경 표시가 그대로입니다. 그 탭은 따로 저장하세요.

### 열기

**작업 공간 열기…**를 고르면 「작업 공간 파일 열기」 창이 뜹니다. 고를 수 있는 파일은 `.md`, `.markdown`, `.xml`, `.sqd`입니다.

| 파일 | 열리는 방식 |
|---|---|
| `.workspace.md`, `.md` | 파일의 `##` 제목마다 SQL 탭을 만듭니다. 탭에 묶인 접속과 바인드 값도 되살립니다. |
| `.sqd` (Orange 작업 공간) | 탭마다 SQL 탭을 만듭니다. 읽은 내용에 문제가 있으면 「작업 공간 열기」 창에 알림이 뜹니다. |
| MyBatis 매퍼 `.xml` | MyBatis 기능이 켜져 있으면 MyBatis 작업 공간으로 열립니다. [MyBatis 작업 공간](../mybatis/)을 보세요. |
| `.plsql-workspace.md` | PL/SQL 작업 공간으로 엽니다. [PL/SQL](../../schema/plsql/)을 보세요. |

- 같은 파일에서 연 작업 공간이 이미 열려 있으면 새로 열지 않고 그 작업 공간으로 옮겨 갑니다.
- 파일을 읽지 못하면 「작업 공간 열기」 창에 「파일을 열지 못했다: 이유」가 뜹니다.
- **파일 > 파일 열기**로 `.workspace.md`나 `.sqd`를 골라도 작업 공간으로 열립니다.
- 창에 `.sqd` 파일이나 MyBatis 매퍼 `.xml` 파일을 끌어 놓아도 작업 공간으로 열립니다.

### 최근 작업 공간

- **파일 > 작업 공간 > 최근 작업 공간**은 최근에 열거나 저장한 작업 공간 파일 10개를 보입니다. 맨 위가 가장 최근입니다.
- 줄에는 파일 이름과 흐린 글씨의 폴더 경로가 보입니다. 마우스를 올리면 전체 경로가 나옵니다.
- 문서가 하나도 없을 때 보이는 시작 화면에도 같은 목록이 나옵니다.
- 고른 파일이 없어졌으면 목록에서 빼고 상태 표시줄에 「이름 을(를) 찾을 수 없어 최근 목록에서 뺐습니다.」를 보입니다.
- 「목록 지우기」는 최근 작업 공간 목록만 비웁니다. 최근 파일 목록은 그대로 둡니다. 파일은 지우지 않습니다.

## 닫기, 끝내기, 복구

### 작업 공간을 닫을 때

**작업 공간 닫기**나 문서 탭의 닫기는 작업 공간을 닫고, 그 내용을 앱의 저장 폴더에 남깁니다. 고친 SQL 탭이 있으면 탭마다 「저장 / 저장 안 함 / 취소」를 묻습니다. 고친 탭이 없으면 묻지 않고 바로 닫습니다.

- 「저장 안 함」을 고르면 파일에는 쓰지 않지만, 그 내용은 앱의 저장 폴더의 작업 공간에 남습니다.
- 「취소」를 고르면 작업 공간을 닫지 않습니다.
- MyBatis 작업 공간은 지금처럼 저장 안 한 문장이 있을 때 한 번만 묻습니다. **끝내기**는 묻지 않습니다(아래 참고).

:::caution[닫은 작업 공간을 다시 여는 메뉴는 없습니다]
메뉴, 도구 모음, 명령 팔레트, 시작 화면 어디에도 이렇게 닫은 작업 공간을 앱의 저장 폴더에서 다시 여는 항목이 없습니다. 나중에 다시 쓰려면 닫기 전에 **작업 공간 저장**으로 파일에 저장하세요. 파일로 저장해 두면 **작업 공간 열기…**나 **최근 작업 공간**으로 다시 열 수 있습니다. 이미 닫은 작업 공간은 [숨은 명령](#숨은-명령)의 「작업 공간 열기(저장소)」로 다시 열 수 있습니다.
:::

- **모든 탭 닫기**는 문서 영역의 모든 문서를 닫습니다. SQL 작업 공간은 위와 같이 앱의 저장 폴더에 남습니다. 확인이 필요한 문서는 하나씩 차례로 묻고, 「취소」를 고르면 그 문서와 남은 문서는 닫지 않습니다.
- **탭 닫기**는 SQL 탭 하나를 닫습니다. SQL 탭이 하나도 남지 않은 작업 공간에서 한 번 더 쓰면 작업 공간을 닫습니다. 닫은 SQL 탭은 **닫은 탭 다시 열기**로 되살립니다.

### 앱을 끝낼 때와 시작할 때

- **끝내기**를 하면 열려 있던 작업 공간을 모두 앱의 저장 폴더에 남기고, 어느 작업 공간을 보고 있었는지도 기억합니다.
- 다음에 시작하면 그 작업 공간들을 같은 순서로 다시 열고, 보고 있던 작업 공간을 앞에 둡니다.
- 시작할 때 다시 열지 않으려면 **설정 > 일반**의 작업 공간 항목에서 「시작할 때 마지막 작업 공간 열기」를 끄세요.
- **설정 > 일반**의 작업 공간 항목에는 「워크스페이스마다 새 세션」도 있습니다. 켜면 새 작업 공간이 처음 실행할 때 같은 DB에 자기 세션을 엽니다. 다른 작업 공간이 실행 중이어도 바로 실행되고 트랜잭션이 따로입니다. 끄면 지금 접속의 세션을 함께 씁니다. 접속과 세션은 [접속 관리](../../connect/manage/)를, 설정 창은 [설정](../../settings/options/)을 보세요.

### 자동 저장과 복구

- 편집 중에는 작업 공간마다 임시본을 자동으로 남깁니다. 기본 간격은 10초입니다. **설정 > 일반**의 「자동 저장(초)」에서 1-10초로 바꿉니다.
- 임시본은 마지막 임시본 이후에 이름, 파일, 활성 탭, SQL 글, 바인드 값이 바뀐 작업 공간에만 새로 남깁니다.
- 앱이 정상 종료되지 않았으면 다음 시작 때 임시본이 남아 있습니다. 그러면 복구 확인 창이 뜹니다.

복구 확인 창은 제목이 「Oranda」이고 「지난 실행이 정상 종료되지 않았다. 저장하지 않은 편집 내용을 복구할까요?」가 나옵니다.

- 「확인」을 누르면 임시본이 있는 작업 공간을 모두 복구합니다.
- 「취소」를 누르면 임시본을 지우고 복구하지 않습니다.

:::danger[「취소」를 누르면 임시본이 지워집니다]
복구 확인 창에서 「취소」를 누르면 임시본이 모두 지워지고 되돌릴 수 없습니다. 저장하지 않은 내용이 필요하면 「확인」을 누르세요.
:::

복구하지 않기로 했고 「시작할 때 마지막 작업 공간 열기」가 켜져 있으면, 마지막 정상 종료 때 저장한 작업 공간이 열립니다.

## 숨은 명령

메뉴, 도구 모음, 명령 팔레트에는 없고 단축키 설정 창의 명령 목록에만 있는 명령이 둘 있습니다. 설정 창은 [단축키와 명령 팔레트](../../settings/shortcuts/)를 보세요.

| 명령 | 하는 일 |
|---|---|
| 작업 공간 저장(저장소) | 「작업 공간 이름」 창을 열고, 입력한 이름으로 앱의 저장 폴더에 저장합니다. 저장 파일 이름은 입력한 이름에서 만들고, 겹치면 번호를 붙입니다. |
| 작업 공간 열기(저장소) | 「작업 공간 열기」 창에 앱의 저장 폴더에 저장된 작업 공간의 ID 목록을 보입니다. 하나를 고르면 엽니다. 이미 열려 있으면 그 작업 공간으로 옮겨 갑니다. |

작업 공간을 다시 쓰려면 위에서 설명한 파일 저장을 쓰세요. 이미 닫은 작업 공간을 앱의 저장 폴더에서 다시 열어야 하면 다음과 같이 합니다.

1. **도구 > 단축키 설정**을 고르세요.
2. 명령 목록에서 「작업 공간 열기(저장소)」를 찾으세요.
3. 이 명령에 키를 지정하세요. 방법은 [단축키와 명령 팔레트](../../settings/shortcuts/)를 보세요.
4. 지정한 키를 누르세요.
5. 「작업 공간 열기」 창에서 작업 공간 ID를 고르세요.

## 자주 하는 작업

### 새 작업 공간을 만들고 이름 붙이기

1. **파일 > 작업 공간 > 새 작업 공간**을 고르세요.
2. 새 작업 공간의 문서 탭을 두 번 누르세요.
3. 이름 바꾸기 창에 이름을 입력하세요.
4. 「확인」을 누르세요.

### 작업 공간을 파일로 저장하기

1. 저장할 작업 공간의 문서 탭을 누르세요.
2. **파일 > 작업 공간 > 작업 공간 저장**을 고르세요.
3. 저장 위치를 고르세요.
4. 파일 이름을 확인하고 「저장」을 누르세요.

문서 탭에 `(md)`가 붙으면 저장이 끝난 것입니다.

### 저장한 작업 공간 파일 열기

1. **파일 > 작업 공간 > 작업 공간 열기…**를 고르세요.
2. `.workspace.md` 파일을 고르세요.
3. 「열기」를 누르세요.

최근에 쓴 파일이면 **파일 > 작업 공간 > 최근 작업 공간**에서 이름을 고르세요.

### 작업 공간 이름과 파일 이름을 함께 바꾸기

1. **파일 > 작업 공간 > 작업 공간 이름 바꾸기**를 고르세요.
2. 새 이름을 입력하고 「확인」을 누르세요.
3. **파일 > 작업 공간 > 작업 공간 저장**을 고르세요.

같은 폴더의 파일 이름이 새 이름으로 바뀝니다. 새 이름의 파일이 이미 있으면 저장 위치를 다시 묻습니다.

### Orange 작업 공간 가져오기

1. **파일 > 작업 공간 > 작업 공간 열기…**를 고르세요.
2. `.sqd` 파일을 고르세요.
3. 「작업 공간 열기」 창에 알림이 뜨면 내용을 읽고 「확인」을 누르세요.
4. 가져온 SQL 탭을 확인하세요.
5. **작업 공간 저장**으로 `.workspace.md`로 저장하세요.

`.sqd` 원본 파일은 바뀌지 않습니다.

### 최근 작업 공간 목록 지우기

1. **파일 > 작업 공간 > 최근 작업 공간 > 목록 지우기**를 고르세요.

### 비정상 종료 뒤 편집 내용 복구하기

1. Oranda를 다시 시작하세요.
2. 복구 확인 창에서 「확인」을 누르세요.
3. 복구된 SQL 탭을 확인하세요.
4. 필요한 내용을 **작업 공간 저장**으로 파일에 저장하세요.

## 문제가 생길 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 「작업 공간 열기」 창에 「파일을 열지 못했다: 이유」가 뜹니다 | 파일을 읽지 못했거나 형식이 맞지 않습니다. | 파일 경로와 읽기 권한을 확인하세요. |
| `.sqd`를 열었더니 「COUNT 를 읽지 못했다. 읽은 만큼 열었다.」 같은 알림이 뜹니다 | Orange 파일의 일부가 비어 있거나 깨졌습니다. | 열린 SQL 탭이 원본과 같은지 확인하세요. |
| `.sqd` 알림에 「탭이 없다.」가 나옵니다 | 파일에서 탭을 하나도 읽지 못했습니다. | 원본 파일을 확인하세요. |
| 앱을 다시 켰는데 이전 작업 공간이 열리지 않습니다 | 「시작할 때 마지막 작업 공간 열기」가 꺼져 있거나, 직접 닫은 작업 공간입니다. | **설정 > 일반**에서 항목을 켜세요. 닫은 작업 공간은 위의 주의 글을 보세요. |
| 「작업 공간 저장」이 회색입니다 | 열린 문서가 없거나 MyBatis 작업 공간입니다. | SQL 작업 공간을 연 뒤 다시 시도하세요. |
| 이름을 바꿨는데 파일 이름은 그대로입니다 | 이름 바꾸기는 다음 저장 때 파일에 반영됩니다. | **작업 공간 저장**을 하세요. |
| 저장했더니 작업 공간 이름이 파일 이름으로 바뀌었습니다 | 저장하면 작업 공간 이름을 파일 이름에 맞춥니다. | 이름이 마음에 들지 않으면 이름을 바꾼 뒤 다시 저장하세요. |
| 저장할 때 저장 위치를 다시 묻습니다 | 새 이름과 같은 파일이 같은 폴더에 있습니다. | 다른 이름으로 저장하거나 기존 파일을 옮기세요. |
| 손으로 쓴 `.md` 파일의 SQL 일부가 탭에 없습니다 | 같은 `##` 제목 아래의 둘째 코드 블록은 건너뜁니다. | 코드 블록마다 `##` 제목을 붙이세요. |
| 최근 작업 공간 줄을 눌렀더니 목록에서 사라집니다 | 파일이 옮겨졌거나 지워졌습니다. | 파일 위치를 확인하고 **작업 공간 열기…**로 다시 여세요. |
