Oranda 밖에서 쓰는 LLM CLI(Claude Code, Codex, Antigravity의 `agy`, opencode)가 실행 중인 Oranda를 다룰 수 있습니다. CLI는 `orandactl` 명령으로 편집기 탭을 읽고, 바꿀 글을 제안하고, 새 탭에 SQL을 넣고, 접속의 객체를 찾고, SELECT를 실행합니다. 이 쪽에서는 연결을 켜는 창, CLI가 읽는 `oranda` 스킬, 탭 실행과 파일 저장, 자동 튜닝, 메뉴 명령, 매뉴얼 링크, 운영 접속에서 쓸 때의 주의, 상태 표시줄의 외부 에이전트 띠를 설명합니다.

- AI 튜닝 기능이 켜져 있어야 합니다. 꺼져 있으면 설정 「AI」 탭 3 「밖의 AI 에이전트」에 「AI 기능이 꺼져 있어 연결할 수 없습니다.」가 나오고 **연결…**이 눌리지 않습니다. 탭 맨 위 큰 칸의 **기능 탭에서 켜기**로 켭니다. [AI 모델 설정](../models/#ai-기능이-꺼져-있거나-조회만-쓸-때)을 보세요.
- 접속의 AI 허용 수준은 [AI 기능 개요](../overview/)를 보세요. 외부 에이전트도 같은 수준을 따릅니다.

## 외부 에이전트가 할 수 있는 일

| 일 | 설명 |
|---|---|
| 읽기 | 탭 목록, 탭의 글, 접속 목록, 객체·열·DDL, 결과 그리드에 이미 가져온 행, 마지막 오류를 읽습니다. |
| 제안 | 열려 있는 탭의 글을 바꾸려면 제안만 합니다. 사용자가 비교 창에서 받아들여야 들어갑니다. |
| 새 탭 | 새 탭을 열고 SQL을 넣습니다. 있는 글을 덮지 않습니다. |
| 실행 | SELECT 한 문장, 실행 계획, 통계만 실행합니다. 탭의 SELECT를 사용자의 결과 그리드에서 실행할 수도 있습니다. INSERT·UPDATE·DELETE·DDL·PL/SQL은 탭에 넣기만 하고 사용자가 직접 실행합니다. |
| 파일 저장 | 결과 그리드의 전체 행을 Oranda가 xlsx·csv 새 파일로 씁니다. 행 값은 에이전트에게 가지 않습니다. |
| 메뉴 명령 | 창·패널을 여는 메뉴 명령을 실행합니다. 파일에 쓰는 명령은 사용자에게 한 번 묻고, 글을 바꾸거나 SQL을 실행하는 명령은 거부합니다. |
| 매뉴얼 | Oranda 기능을 물으면 이 설명서에서 찾아 링크로 답합니다. |

- 운영 접속에서도 에이전트가 SELECT를 자동 실행하고(`query`·`tab run`·튜닝 벤치마크) 결과를 파일로 저장할 수 있습니다. 운영 접속은 연결 창에서 처음부터 골라져 있지 않습니다.
- 클라우드 모델이면 운영 접속의 결과 행 값은 보내지 않고 행 수와 열 형만 보냅니다. 민감 컬럼은 `***`로, SQL 글의 리터럴과 오류 글은 가려서 보내고, 운영 탭의 글은 주지 않습니다.
- 연결 창에서 「로컬 모델(가리지 않음)」을 켜면 운영 접속을 포함해 아무것도 가리지 않고 그대로 보냅니다.
- 운영 접속의 외부 호출은 판단과 관계없이 모두 감사 기록에 남습니다. 실행한 호출은 행 수도 남습니다.
- DB에서 온 글(주석, 소스, 오류, 행 값)은 에이전트에게 지시가 아니라 데이터로 전달됩니다.

## 외부 에이전트 연결 켜기

**도구 > AI 설정…**을 누르고 「AI」 탭의 3 「밖의 AI 에이전트」에서 **연결…**을 누릅니다. 같은 묶음에 지금 연결 상태, 스킬 설치 상태, **스킬 설치…** 단추가 있습니다. 창마다 따로 켭니다. 켠 창만 CLI가 찾을 수 있습니다.

- 외부 에이전트는 자기 프로그램(CLI)과 자기 로그인을 씁니다. Oranda 는 접속마다 어디까지 볼지만 정합니다. 그 수준은 설정 「AI」 탭 1 「AI 가 볼 수 있는 접속」 한 표에서 정하고, Oranda 안의 AI 와 같은 표를 씁니다. 운영 접속은 외부 상한까지만 받습니다.
- 연결 창은 「이번 연결에 쓸 접속」만 고릅니다. 표 「에이전트가 볼 수 있는 접속」의 줄마다 이름·환경·실제로 받는 수준이 글자로 나옵니다. 운영 줄은 「(외부 상한 · 고르려면 접속 이름을 다시 입력)」입니다. 수준을 바꾸려면 표 아래 「수준 바꾸기: 설정 > AI 의 접속 표 열기」를 누릅니다. 예전의 「조회 허용」 확인란은 없어졌습니다. 개발·시험 접속을 「조회+행 값」으로 올리는 일은 그 표에서 합니다.

[AI 연결 도우미](../setup/#해-보기)의 마지막 단계 「해 보기」에서 「검은 창의 Claude Code 에서도 Oranda 시키기(고급)」를 켜고 끝내도 이 창이 열립니다.

1. 「에이전트가 볼 수 있는 접속」에서 이번 연결에 쓸 접속을 고릅니다. 개발 접속은 처음부터 골라져 있습니다. 시험 접속은 직접 고릅니다.
2. 운영 접속은 빨간색으로 표시되고 처음에는 골라져 있지 않습니다. 고르면 「운영 접속 — LLM 이 SELECT 를 자동 실행합니다」 경고와 이름 칸이 생깁니다. 접속 이름을 그대로 다시 입력해야 「연결」이 눌립니다.
3. 필요하면 아래 확인란을 고릅니다.
4. 「연결」을 누릅니다. 위쪽에 「연결됨」과 붙은 CLI 이름, 끊기는 시각이 보입니다.

| 확인란 | 설명 |
|---|---|
| 로컬 모델(가리지 않음) | 처음에는 꺼져 있습니다. 켜면 민감 컬럼, 리터럴, 오류 글을 가리지 않고 결과 값을 그대로 보냅니다. 운영 접속도 같습니다. 켜면 아래에 경고가 보이고, 운영 접속을 함께 고르면 「운영 값이 가리지 않고 나갑니다」 경고가 한 줄 더 보입니다. Oranda는 모델이 정말 로컬인지 확인하지 못하므로 이 컴퓨터나 사내에서 도는 모델일 때만 켭니다. |
| 8시간 뒤 끊기 | 처음부터 골라져 있습니다. 끄면 앱을 끌 때까지 연결됩니다. |
| 접속 없는 탭의 글 읽기 허용 | 처음부터 골라져 있습니다. 접속을 고르지 않은 탭의 글을 에이전트가 읽을 수 있습니다. |

- 접속 목록의 수준은 그 접속에서 에이전트가 쓸 수 있는 가장 높은 수준입니다. AI 허용 수준이 「끔」인 접속은 고를 수 없습니다.
- 「연결」을 다시 누르면 옛 연결을 끊고 새로 연결합니다. 붙어 있던 CLI는 다시 붙어야 합니다.
- 「끊기」를 누르면 바로 끊습니다. 「연장」을 누르면 지금부터 다시 8시간 연결됩니다.
- 연결 정보(토큰)는 사용자 데이터 폴더의 `run/agents/` 아래 파일에만 씁니다. 같은 PC의 다른 사용자는 읽을 수 없습니다. 끊거나 앱을 끄면 지웁니다.

## CLI에서 쓰기

CLI는 스킬을 읽고 `orandactl` 을 부릅니다. 직접 불러 볼 수도 있습니다.

```text
orandactl status
orandactl tabs
orandactl tab get --tab <탭 id> --scope statement
orandactl query --conn <접속 별칭> - < new.sql
```

- 결과는 JSON 한 개입니다. `--text` 를 붙이면 사람이 읽는 글로 나옵니다.
- 상태 표시줄과 연결 창에는 부른 CLI 이름(Claude Code·Codex·opencode·Antigravity)이 보입니다. `orandactl` 이 CLI 가 셸에 넣는 표식으로 알아내므로 따로 줄 것은 없습니다. 다른 이름으로 보이게 하려면 환경 변수 `ORANDA_CLIENT` 를 정해 둡니다(명령 앞에 붙이면 Claude Code 의 실행 허락 규칙과 맞지 않으니 셸 설정에 둡니다).
- Oranda 창이 여럿 연결돼 있으면 `--instance <pid>` 로 고릅니다. `orandactl status --all` 이 창 목록을 보입니다.

### CLI 별 실행 허락

`orandactl` 은 이 PC 안의 통로로 Oranda 에 붙습니다. CLI 가 명령을 샌드박스에 가두면 붙지 못하므로 아래처럼 허락합니다. 스킬에도 같은 안내가 들어 있습니다.

| CLI | 허락 방법 |
|---|---|
| Claude Code | 처음 실행 때 묻는 창에서 허락합니다. 미리 허락하려면 `--allowedTools 'Bash("<orandactl 전체 경로>":*)'` 처럼 따옴표째 줍니다(경로에 공백이 있어도 맞습니다). |
| Codex | 읽기 전용·작업 폴더 쓰기 샌드박스에서는 통로가 막힙니다. `-c sandbox_workspace_write.network_access=true` 로 시작하거나 `orandactl` 을 샌드박스 밖에서 돌리도록 허락합니다. |
| Antigravity (`agy`) | 셸 명령을 먼저 샌드박스에서 돌립니다. `sandbox_blocked` 오류가 나면 같은 명령을 샌드박스 밖에서 다시 돌리도록 허락합니다. |

## oranda 스킬

LLM CLI는 스킬 파일(`SKILL.md`)을 읽고 `orandactl` 쓰는 법을 압니다. Oranda는 사용자 폴더 세 곳에 같은 스킬을 씁니다.

| 폴더 | 읽는 CLI |
|---|---|
| `~/.claude/skills/oranda/` | Claude Code, opencode |
| `~/.agents/skills/oranda/` | Codex, opencode |
| `~/.gemini/config/skills/oranda/` | Antigravity (`agy`) |

- 스킬에는 이 PC의 `orandactl` 전체 경로가 들어갑니다. PATH는 바꾸지 않습니다.
- Oranda가 쓴 스킬 파일은 머리말에 `# Oranda-managed: v1` 줄이 있습니다. 이 줄이 있는 파일만 Oranda가 다시 쓰거나 지웁니다. 스킬을 직접 고쳐 쓰려면 이 줄을 지우세요.
- 같은 자리에 이 줄이 없는 다른 `oranda` 스킬이 있으면 덮어쓰지 않습니다.
- Oranda가 띄우는 AI 튜닝·대화 실행은 이 스킬을 읽지 않습니다.

### 스킬 설치

연결 창의 「스킬 설치…」를 누릅니다.

1. 폴더마다 확인란, 읽는 CLI, 파일 경로, 지금 상태가 보입니다. 그 CLI의 설정 폴더가 있거나 이미 Oranda 스킬이 있는 줄은 처음부터 골라져 있습니다.
2. 「설치」를 누르면 고른 곳에 씁니다. 「지우기」를 누르면 고른 곳에서 Oranda가 쓴 스킬만 지웁니다.
3. 다른 `oranda` 스킬이 있어 건너뛴 줄에는 「덮어쓰기」가 생깁니다. 그 파일을 Oranda 스킬로 바꾸려면 누릅니다.

창 아래에 스킬이 부를 `orandactl` 경로와 결과가 보입니다.

macOS 에서 내려받은 앱을 응용 프로그램 폴더로 옮기지 않고 열면, 앱이 임시 위치(AppTranslocation)에서 실행됩니다. 이때는 스킬에 임시 경로가 적히므로 설치하지 않고 안내만 보입니다. 앱을 응용 프로그램 폴더로 옮겨 다시 연 뒤 설치합니다.

## 탭 실행과 파일 저장

에이전트가 만든 SQL을 새 탭에 넣고, 실행하고, 전체 결과를 엑셀 파일로 저장하는 일을 한 번에 맡길 수 있습니다.

```text
orandactl tab new --conn <접속 별칭> - < new.sql
orandactl tab run --tab <탭 id> --base-version <판 번호>
orandactl result export --tab <탭 id> --format xlsx --out <절대 경로>
```

- `tab run`은 탭의 SELECT(또는 WITH로 시작하는 조회) 한 문장을 사용자가 F5를 누른 것처럼 그 탭의 결과 그리드에서 실행합니다. 실행하는 글은 에이전트가 보낸 글이 아니라 탭의 글입니다.
- INSERT·UPDATE·DELETE·DDL·PL/SQL은 실행하지 않습니다. `FOR UPDATE`, DB 링크, 시퀀스, Oracle 제공 패키지를 쓰는 문장도 실행하지 않습니다. 사용자 함수는 읽기만 하는 것으로 확인된 것만 실행합니다.
- 문장에 바인드 변수(`:BASE_DT` 같은)가 있으면 에이전트가 값을 함께 넘깁니다. 사용자가 「바인드 변수」 창에 값을 직접 넣을 필요가 없습니다. 날짜·기간·코드처럼 요청에서 값이 분명하지 않을 때만 에이전트가 그 값이 맞는지 묻습니다.

  ```text
  orandactl tab run --tab <탭 id> --base-version <판 번호> --binds-json '{"BASE_DT":"20261101"}'
  orandactl tab binds set --tab <탭 id> --binds-json '{"BASE_DT":"20261101"}'
  ```

  `tab run --binds-json`은 값을 그 탭의 「바인드 변수」 목록에 넣은 뒤 실행하고, `tab binds set`은 넣기만 하고 실행하지 않습니다. 넣은 값은 사람이 친 값처럼 「바인드 변수」 창에 보이고 작업 공간에 저장됩니다. 메시지 창에는 「[에이전트] … 바인드 값을 채웠습니다 · :BASE_DT」 줄이 남습니다(값은 바인드 창에만 보입니다).
- 값은 목록 줄의 형식(VARCHAR2·NUMBER·DATE 등)을 따릅니다. 사람이 칸을 떠날 때처럼 정리하므로 DATE 줄에 `20261101`을 넣으면 `2026-11-01 00:00:00`이 되고, NUMBER 줄의 `1,000`은 `1000`이 됩니다. 아직 줄이 없는 이름은 글이면 VARCHAR2, 숫자면 NUMBER 줄로 만듭니다. 형식에 맞지 않는 값, 탭에 없는 이름, OUT 바인드에 준 값은 `bind_invalid`로 거부하고 목록의 값을 하나도 바꾸지 않습니다.
- 에이전트는 형식을 함께 줄 수 있습니다: `{"BASE_DT":{"value":"20261101","type":"date"}}`(형식은 `varchar2`·`number`·`date`·`timestamp`). 날짜는 이렇게 `date` 로 넘기도록 스킬에 적혀 있습니다. 줄이 없거나, 값이 비어 있고 형식을 아직 고르지 않은(VARCHAR2 그대로인) 줄이면 그 형식으로 만듭니다. 사람이 다른 형식을 골라 둔 줄이면 말없이 바꾸지 않고 `bind_invalid`로 거부합니다.
- 값을 넣는 일도 실행과 같은 허가를 따릅니다. 허가 밖 접속의 탭은 `locked`, 수준이 Query보다 낮으면 `level`로 거부하고, `--base-version`이 지금 판과 다르면 넣지 않고 `stale`을 돌려줍니다. 에이전트가 넘긴 값은 개발·시험 접속이면 감사 기록에 `query --binds-json`과 같은 꼴(`binds={…}`)로 남습니다. 운영 접속(그리고 접속을 알 수 없는 호출)이면 값 없이 이름과 형식만 남습니다(예: `binds={PAK_PST_DD:date}`). `query --binds-json` 도 운영 접속에서는 같습니다. 실행 이력에는 사람이 실행할 때와 같은 규칙(바인드 값 저장 설정)으로 남습니다.
- 탭 글을 읽을 수 없는 연결(운영 탭 + 「로컬 모델」이 아닌 연결 등)에서는 바인드 값을 넣지 않고 `tab get`과 같은 까닭(`environment` 등)으로 거부합니다. 이름이 있는지 없는지도 알려 주지 않습니다. 이때는 사용자가 「바인드 변수」 창에 값을 넣습니다.
- 값 없이 `tab run`을 부르고 목록에도 값이 없으면 실행하지 않습니다.
- 탭에 문장이 여럿이면 `--range statement`로 커서가 있는 문장만 실행합니다. 에이전트가 읽은 뒤 사용자가 탭을 고쳤으면(`--base-version`이 다르면) 실행하지 않고 `stale`을 돌려줍니다.
- 탭의 접속이 열려 있지 않으면 접속을 묻는 창을 띄우지 않고 `connection`으로 거부합니다. 먼저 사용자가 탭에서 접속합니다.
- 실행은 30초(최대 60초)가 지나면 취소됩니다. 그 탭의 세션이 실행 중이거나 파일로 저장하는 중이면 기다리지 않고 `tab_busy`를 돌려줍니다.
- 에이전트에게는 행 값이 가지 않고 그리드에 가져온 행 수(`fetched`)와 남은 행이 있는지(`more`)만 갑니다. 행이 필요하면 에이전트가 `result get`으로 읽습니다.
- 실행하는 동안 탭 위 띠에 「Claude Code 가 이 문장을 실행하는 중입니다 [취소]」가 보이고, 끝나면 「… 실행했습니다 · 12행 [닫기]」로 바뀝니다. 메시지 창에는 「[에이전트] …」 줄이 남고, 결과 탭 제목 앞에 `AI·`가 붙습니다. 실행 이력에는 출처가 에이전트로 남습니다.
- `result export`는 그 결과의 문장을 서버에서 다시 읽어 전체 행을 Oranda가 직접 파일에 씁니다. 행 수 한도와 시간 상한은 없고, 에이전트에게는 파일 경로와 행 수(`rows`)만 갑니다. 문장 검사는 `tab run`과 같습니다.
- 저장하는 동안 탭 위 띠에 「… 가 파일로 저장하는 중 … N행 [취소]」가 보이고, 끝나면 「저장함 · 경로 · N행 [폴더 열기] [닫기]」로 바뀝니다. 저장하는 동안 그 세션은 실행 중으로 잡혀 다른 실행이 끼어들지 않습니다.
- 저장할 경로는 절대 경로여야 하고, 폴더가 있어야 하고, 확장자가 형식(`xlsx`·`csv`)과 맞아야 합니다. 아니면 `path_invalid`로 거부합니다. 같은 이름의 파일이 있으면 덮지 않고 `file_exists`로 거부합니다. 임시 이름으로 쓰고 끝나면 바꿔 넣으므로, 실패하거나 취소하면 파일이 남지 않습니다.

## 자동 튜닝

느린 SQL을 튜닝해 달라고 하면 CLI가 스킬의 튜닝 절차를 처음부터 끝까지 진행합니다. 중간에 묻지 않습니다.

1. 문장의 튜닝 정보(`tune context`)를 읽습니다.
2. 실행 계획(`tune plan`·`tune explain`)과 실행 통계(`tune sqlstats`)를 봅니다.
3. 계획에서 문제가 되는 테이블의 통계(`tune stats`), 인덱스(`tune index`), 히스토그램(`tune histogram`)을 봅니다.
4. 후보 문장을 4개까지 만들고 문법을 검사(`sql check`)합니다.
5. 원래 문장과 후보를 함께 벤치마크(`tune bench`)합니다. 결과 행 수가 원래 문장과 다른 후보는 버리고, 논리 읽기가 가장 적은 문장을 고릅니다.
6. 가장 나은 문장을 새 탭에 넣고 바뀐 점을 한 줄로 알립니다. 원래 탭은 바꾸지 않습니다.

- 벤치마크는 문장을 실제로 여러 번 실행합니다. 운영 접속보다 스키마가 같은 개발·시험 접속을 먼저 쓰도록 스킬에 적혀 있습니다.
- 새 인덱스가 필요하다는 결론이면 `CREATE INDEX` 문을 새 탭의 주석에만 적습니다. 실행은 사용자가 합니다.
- 접속의 허용 수준이 모자라 거부되면 CLI는 그 이유를 알리고 멈춥니다.
- Oranda 안의 AI 튜닝으로 이어 보려면 에이전트에게 「Oranda에서 튜닝을 시작해」라고 합니다. 에이전트가 `orandactl tune start --tab <탭 id>`를 부르면 Oranda가 그 탭을 앞으로 내고 [AI 튜닝 시작 창](../../plan/tuning/#ai-튜닝-시작-창)을 띄웁니다. 시작은 사용자가 창에서 확정합니다. 탭 접속의 허용 수준이 「계획」 이상이어야 합니다.

## 메뉴 명령

에이전트가 Oranda의 메뉴 명령을 실행할 수 있습니다. `orandactl ui commands`가 명령 id, 메뉴 경로, 등급, 지금 쓸 수 있는지를 보이고, `orandactl ui run <명령 id>`가 실행합니다.

| 등급 | 명령 | 실행 |
|---|---|---|
| 바로 | 창·패널 열기, 보기 바꾸기, 정렬·거르기, 대화상자 열기처럼 화면만 바뀌는 명령 | 바로 실행합니다. |
| 확인 | 파일 저장, 탭·작업 공간 닫기, 연결 끊기처럼 디스크에 쓰거나 고친 글을 잃을 수 있는 명령 | 띠로 한 번 묻고 사용자가 고르면 실행합니다. |
| 거부 | 글 바꾸기, SQL 실행, 커밋, 세션 끊기, 클립보드, 앱 끝내기, AI 시작, 비밀번호, 목록에 없는 명령 | 실행하지 않습니다. 글은 제안으로, 실행은 `tab run`으로 합니다. |

## 기능 질문과 매뉴얼 링크

에이전트에게 Oranda 기능의 사용법을 물으면 이 설명서에서 찾아 링크로 답합니다. 스킬에 설명서 쪽 목록이 들어 있고, CLI는 `orandactl docs`로 제목과 절 제목을 찾습니다. Oranda를 켜지 않아도 됩니다.

```text
orandactl docs 실행 계획
orandactl docs --text 외부 에이전트
```

- 결과에는 쪽 제목, 주소, 설명과 검색어가 들어 있는 절의 주소(`#` 뒤 절 이름)가 나옵니다.
- 설명서가 한국어이므로 쪽 제목에 있는 한국어 낱말로 찾으면 잘 맞습니다.

## 운영 접속에서 쓸 때

- 운영 접속을 고르면 에이전트가 운영 DB에서 SELECT를 자동으로 실행합니다. 문장 검사는 개발 접속과 같고(SELECT·WITH 한 문장, `FOR UPDATE`·DB 링크·확인 못 한 함수 거부), 실행 시간 상한도 같습니다. 파일 저장은 행 수 한도가 없으니 띠의 「취소」로 멈춥니다.
- 처음에는 스키마가 같은 개발·시험 접속으로 써 보세요. 스킬도 개발·시험 접속을 먼저 쓰도록 적혀 있습니다.
- 운영 접속이 허가에 들어 있으면 상태 표시줄 띠가 운영 색(빨강)으로 바뀌고 「운영 포함」이 붙습니다.
- 회사 DB 접근 통제 솔루션 정책에 따라 에이전트의 자동 실행이 막히거나 기록될 수 있습니다. 운영 접속에 쓰기 전에 사내 정책을 확인하세요.

## 상태 표시줄의 외부 에이전트 띠

외부 에이전트가 연결되면 상태 표시줄에 띠가 생깁니다.

```text
에이전트 연결됨 · Claude Code · 최근 호출 12초 전 · 7시간 40분 남음  [끊기]
```

- 붙은 CLI 이름, 마지막 호출이 얼마 전인지, 연결이 끊길 때까지 남은 시간을 보입니다. 남은 시간이 없으면 앱을 끌 때까지 연결됩니다.
- 허가에 운영 접속이 들어 있으면 띠가 운영 색(빨강)으로 바뀌고 「에이전트 연결됨 · 운영 포함 · …」처럼 보입니다.
- 「끊기」를 누르면 바로 연결을 끊습니다. 에이전트의 다음 명령은 거부됩니다.
- 띠를 누르면 최근 호출 20개(시각, 도구, 판단, 돌려준 글 길이)가 보입니다. 판단은 「허용」·「가림」·「거부」·「실패」입니다.
- 끊길 때까지 10분이 남으면 목록 아래에 「연장」이 생깁니다. 누르면 지금부터 다시 8시간 연결됩니다.

### 스킬 다시 설치

Oranda를 다른 폴더에 다시 설치하거나 업데이트로 `orandactl` 위치가 바뀌면, 설치해 둔 스킬이 옛 경로를 가리킵니다. 이때 상태 표시줄에 「에이전트 스킬 다시 설치 필요」가 뜹니다. 띠를 누르고 「스킬 다시 설치」를 누르면 Oranda가 쓴 스킬만 새 경로로 다시 씁니다.
