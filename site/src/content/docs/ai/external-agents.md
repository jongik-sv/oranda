Oranda 밖에서 쓰는 LLM CLI(Claude Code, Codex, Antigravity의 `agy`, opencode)가 실행 중인 Oranda를 다룰 수 있습니다. CLI는 `orandactl` 명령으로 편집기 탭을 읽고, 바꿀 글을 제안하고, 새 탭에 SQL을 넣고, 접속의 객체를 찾고, SELECT를 실행합니다. 이 쪽에서는 CLI가 읽는 `oranda` 스킬과 상태 표시줄의 외부 에이전트 띠를 설명합니다.

- AI 튜닝 기능이 켜져 있어야 합니다. 기능은 **설정 > 기능**에서 켜고 끕니다. [설정](../../settings/options/#기능)을 보세요.
- 접속의 AI 허용 수준은 [AI 기능 개요](../overview/)를 보세요. 외부 에이전트도 같은 수준을 따릅니다.

## 외부 에이전트가 할 수 있는 일

| 일 | 설명 |
|---|---|
| 읽기 | 탭 목록, 탭의 글, 접속 목록, 객체·열·DDL, 결과 그리드에 이미 가져온 행, 마지막 오류를 읽습니다. |
| 제안 | 열려 있는 탭의 글을 바꾸려면 제안만 합니다. 사용자가 비교 창에서 받아들여야 들어갑니다. |
| 새 탭 | 새 탭을 열고 SQL을 넣습니다. 있는 글을 덮지 않습니다. |
| 실행 | SELECT 한 문장, 실행 계획, 통계만 실행합니다. INSERT·UPDATE·DELETE·DDL·PL/SQL은 탭에 넣기만 하고 사용자가 직접 실행합니다. |

- 운영 접속은 외부 에이전트에게 메타데이터만 줍니다. 탭의 글, 결과 행, 이력, 오류 글은 주지 않습니다.
- DB에서 온 글(주석, 소스, 오류, 행 값)은 에이전트에게 지시가 아니라 데이터로 전달됩니다.

## oranda 스킬

LLM CLI는 스킬 파일(`SKILL.md`)을 읽고 `orandactl` 쓰는 법을 압니다. Oranda는 사용자 폴더 세 곳에 같은 스킬을 씁니다.

| 폴더 | 읽는 CLI |
|---|---|
| `~/.claude/skills/oranda/` | Claude Code, opencode |
| `~/.agents/skills/oranda/` | Codex, opencode |
| `~/.gemini/config/skills/oranda/` | Antigravity (`agy`) |

- 스킬에는 이 PC의 `orandactl` 전체 경로가 들어갑니다. PATH는 바꾸지 않습니다.
- Oranda가 쓴 스킬 파일은 머리말에 `# Oranda-managed: v1` 줄이 있습니다. 이 줄이 있는 파일만 Oranda가 다시 쓰거나 지웁니다. 스킬을 직접 고쳐 쓰려면 이 줄을 지우세요.
- 같은 자리에 이 줄이 없는 다른 `oranda` 스킬이 있으면 덮어쓰지 않습니다.
- Oranda가 띄우는 AI 튜닝·대화 실행은 이 스킬을 읽지 않습니다.

## 상태 표시줄의 외부 에이전트 띠

외부 에이전트가 연결되면 상태 표시줄에 띠가 생깁니다.

```text
에이전트 연결됨 · Claude Code · 최근 호출 12초 전 · 7시간 40분 남음  [끊기]
```

- 붙은 CLI 이름, 마지막 호출이 얼마 전인지, 연결이 끊길 때까지 남은 시간을 보입니다. 남은 시간이 없으면 앱을 끌 때까지 연결됩니다.
- 「끊기」를 누르면 바로 연결을 끊습니다. 에이전트의 다음 명령은 거부됩니다.
- 띠를 누르면 최근 호출 20개(시각, 도구, 판단, 돌려준 글 길이)가 보입니다. 판단은 「허용」·「가림」·「거부」·「실패」입니다.
- 끊길 때까지 10분이 남으면 목록 아래에 「연장」이 생깁니다. 누르면 지금부터 다시 8시간 연결됩니다.

### 스킬 다시 설치

Oranda를 다른 폴더에 다시 설치하거나 업데이트로 `orandactl` 위치가 바뀌면, 설치해 둔 스킬이 옛 경로를 가리킵니다. 이때 상태 표시줄에 「에이전트 스킬 다시 설치 필요」가 뜹니다. 띠를 누르고 「스킬 다시 설치」를 누르면 Oranda가 쓴 스킬만 새 경로로 다시 씁니다.
