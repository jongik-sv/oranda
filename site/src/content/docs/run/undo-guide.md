데이터를 잘못 바꿨을 때 어떤 기능으로 되돌릴지 고르는 쪽입니다. Oranda의 되돌리기 기능은 여러 쪽에 나뉘어 있습니다. 이 쪽은 상황별로 쓸 기능을 고르고 짧은 절차를 보입니다. 기능마다 자세한 설명은 이어진 쪽을 보세요.

:::caution[되돌리기도 DB 데이터를 바꿉니다]
되돌리기는 모두 커밋하지 않고 반영합니다. 결과를 확인한 뒤 커밋이나 롤백을 직접 하세요. 운영 DB에서는 되돌리기 전에 같은 DML을 개발 DB에서 먼저 연습하세요.
:::

## 상황별로 고르기

| 상황 | 쓸 기능 | 기준 | 자세한 쪽 |
|---|---|---|---|
| 그리드에서 값을 고쳤지만 아직 반영하지 않았습니다. | 「행 되돌리기」, 「모두 되돌리기」 | 화면의 편집만 버립니다. DB는 그대로입니다. | [그리드 편집](../grid-edit/#되돌리기) |
| 문장을 실행했지만 아직 커밋하지 않았습니다(상태 표시줄 「미커밋」). | **SQL > 롤백** | 그 세션의 커밋하지 않은 변경 전부 | [SQL 실행](../execute/#커밋과-롤백) |
| 운영 접속에서 커밋했습니다. | 「원복 스크립트 열기」 → 「원복 실행 (커밋 안 함)」 | 실행할 때 남긴 원복 스크립트(커밋 묶음 단위) | [되돌리기 지점](../rollback/#원복-스크립트-열기와-실행) |
| 개발·테스트 접속에서 커밋했거나, 원복 스크립트가 없거나 불완전합니다. | 변경 일지의 「이 실행 전과 비교…」 | 실행 직전 시점(SCN)과 지금 데이터의 차이 | [되돌리기 지점](../rollback/#이-실행-전과-비교) |
| 몇 분 전 값이 어땠는지 보고, 고른 행만 그때 값으로 돌리고 싶습니다. | 플래시백 「N분 전 값 보기…」로 보고, 「이전 값으로 되돌리기…」로 돌립니다. | N분 전, 커밋 묶음, 직접 정한 시각 | [이전 값으로 되돌리기](../grid-edit/#이전-값으로-되돌리기) |
| 한 행의 여러 버전 가운데 특정 버전으로 돌리고 싶습니다. 지운 행을 되살리고 싶습니다. | 플래시백 「이 행 변경 이력」으로 보고, 「이 행 상태로 되돌리기…」로 돌립니다. | 고른 과거 행 한 줄 | [이 행 상태로 되돌리기](../grid-edit/#이-행-상태로-되돌리기) |
| 되돌린 것을 다시 원래대로 하고 싶습니다. | 변경 일지에 새로 남은 묶음에서 다시 되돌리기 | 되돌릴 때 남긴 반대 문장 | [되돌린 것을 다시 되돌리기](#되돌린-것을-다시-되돌리기) |
| 테이블이나 PL/SQL 정의를 잘못 바꿨습니다. | 변경 일지의 「이 DDL 을 새 편집기에 열기」 | 바꾸기 직전에 보관한 DDL | [변경 일지](../../tools/db-tools/#이전-ddl로-되돌리기) |
| 테이블을 `DROP` 했습니다. | 객체 검색의 「휴지통」 탭 「되살리기」 | DB의 휴지통 | [휴지통 탭](../../schema/browser/#휴지통-탭) |
| `TRUNCATE`나 `DROP COLUMN`을 하려 합니다. | 실행 확인 창의 「먼저 백업 테이블 만들기」 | 실행 직전에 만든 백업 테이블 | [실행 확인 창의 원복 줄](../rollback/#실행-확인-창의-원복-줄) |
| 데이터 복사가 도중에 실패했습니다. | 커밋 방식 「모두 끝난 뒤 한 번」이면 저절로 모두 되돌립니다. | 실행 전 대상 | [데이터 복사](../../transfer/data-copy/#커밋-방식) |
| 며칠이 지났습니다. | 운영 접속이면 원복 스크립트(보관 기간 안). 그 밖에는 [안 되는 경우](#안-되는-경우와-대안)를 보세요. | | |

- 커밋 전이면 롤백이 가장 확실합니다. 커밋한 뒤의 되돌리기는 모두 「그 뒤 다른 사람이 다시 바꾼 행」을 덮어쓰지 않습니다. 그런 행은 0행이나 「충돌」로 알려 줍니다.
- 원복 스크립트는 이 PC 에 보관하므로 시간이 지나도 쓸 수 있습니다(보관 기간 처음 값 30일). 시점 비교와 플래시백은 서버의 undo 에서 지난 값을 읽으므로 보통 몇 분에서 몇 시간 안에만 됩니다. 얼마나 남는지는 DB의 `undo_retention`에 달려 있습니다.

## 기능별 절차

### 커밋 전: 롤백

1. 상태 표시줄에 「미커밋」이 보이는지 확인합니다.
2. **SQL > 롤백**이나 도구 모음의 「롤백」을 누릅니다.
3. 메시지 창에 「롤백했습니다.」가 남습니다.

- 자동 커밋을 켰거나 DDL(`CREATE`, `ALTER`, `DROP`, `TRUNCATE`)을 실행했으면 이미 커밋된 것입니다. 롤백으로 되돌릴 수 없습니다.
- 둘 이상의 작업 공간이 같은 세션을 쓰면 「공유 세션」 창이 나오고, 다른 작업 공간의 변경도 함께 되돌립니다.

### 반영 전 그리드 편집 버리기

편집 모드 도구 줄의 「행 되돌리기」는 고른 행의 고친 내용·지울 행 표시·새 행을 버리고, 「모두 되돌리기」는 모든 변경을 버립니다. 결과 그리드를 오른쪽 클릭한 **행 편집** 메뉴에도 있습니다. DB에는 아무것도 보내지 않습니다.

이미 「반영(커밋 안 함)」을 눌렀으면 DB 트랜잭션에 들어갔으므로 위의 롤백을 씁니다. 「반영 후 커밋」을 눌렀으면 아래의 커밋한 뒤 방법을 씁니다.

### 운영 접속에서 커밋한 뒤: 원복 스크립트

운영 접속에서 UPDATE, DELETE, INSERT 를 실행하면 실행 확인 창의 「원복 스크립트 만들기」가 켜진 채 나옵니다. 켜고 실행했으면 원복 스크립트가 남습니다.

1. **도구 > 변경 일지**를 엽니다.
2. 「원인」에서 「DML」을 골라 커밋 묶음만 봅니다.
3. 되돌릴 커밋 묶음을 고릅니다. 오른쪽 아래 칸에 원복 스크립트가 미리 보입니다.
4. 「원복 스크립트 열기」를 누릅니다. 읽기 전용 탭이 열립니다.
5. 「원복 실행 (커밋 안 함)」을 누르고, 운영 접속이면 한 번 더 확인합니다.
6. 「되돌림 14 · 0행 1 · 충돌 1 · 오류 0. …」 같은 요약을 확인한 뒤 커밋하거나 롤백합니다.

- 묶음 안 일부 문장만 되돌리려면 「일반 SQL 탭으로 복사」를 누르고 그 부분만 골라 실행합니다.
- 원복 스크립트 칸이 「불완전」이면 이유를 보고, 빠진 부분은 「이 실행 전과 비교…」로 채웁니다.
- 원복 스크립트가 없는 이유(만들지 않음 · 개발 접속, 상한 넘음 등)는 미리 보기 칸 제목에 나옵니다.

### 커밋한 뒤: 이 실행 전과 비교

모든 접속에서 쓰기 문장을 보내기 직전의 시점(Oracle 은 SCN, Tibero 는 TSN)을 변경 일지에 남깁니다. 이 시점과 지금 데이터를 견줘 되돌립니다.

1. **도구 > 변경 일지**에서 커밋 묶음을 고릅니다. 묶음 줄을 두 번 눌러 펼치면 문장 하나를 고를 수도 있습니다.
2. 「이 실행 전과 비교…」를 누릅니다.
3. 묶음이 테이블 여럿을 바꿨으면 테이블을 고르고 「비교」를 누릅니다.
4. 요약 줄과 「바뀐 행」 표에서 되돌림·되살림·지움·충돌을 확인합니다. 충돌 행은 처음에 빠집니다. 넣으려면 「충돌 행도 되돌리기」를 켭니다.
5. 「만들어진 DML」을 확인하고 「반영(커밋 안 함)」을 누릅니다. 바로 실행하지 않고 고쳐 쓰려면 「스크립트를 새 편집기에 열기」를 누릅니다.
6. 결과를 확인한 뒤 커밋하거나 롤백합니다.

- 커밋 뒤 시간이 오래 지나면 undo 에서 기준 시점을 읽지 못합니다(ORA-01555). 창의 안내 줄이 undo 보존 기간과 지난 시간을 알려 줍니다.
- 그 사이 테이블 정의가 바뀌었거나(DDL) 뷰이면 쓸 수 없습니다.

### 몇 분~몇 시간 전 값으로: N분 전 값 보기, 이전 값으로 되돌리기

1. 테이블을 결과 편집 모드로 조회합니다(`F9`, macOS 는 `Ctrl+Enter`).
2. 결과 그리드를 오른쪽 클릭해 **플래시백 > N분 전 값 보기…**를 고르고 분을 넣습니다. 새 결과 탭에서 지금 값과 다른 칸이 노란색으로 보입니다.
3. 원래 결과 탭으로 돌아와 되돌릴 행을 고릅니다. 여러 행도 됩니다(최대 200행).
4. **플래시백 > 이전 값으로 되돌리기…**를 고릅니다. 「이 실행 전과 비교」 창이 「10분 전」 값과 견준 결과로 열립니다.
5. 다른 시점이면 「기준 시점」 목록에서 커밋 묶음이나 「시각 직접 지정…」을 고르고 「비교」를 누릅니다.
6. 「반영(커밋 안 함)」을 누르고, 결과를 확인한 뒤 커밋하거나 롤백합니다.

- 고른 행 범위에서는 UPDATE 만 만듭니다. 지운 행까지 되살리려면 커밋 묶음을 고른 뒤 「이 커밋 묶음 전체 보기」를 누릅니다.
- 같은 메뉴는 메뉴 막대의 **결과 > 플래시백**에도 있습니다.

### 한 행의 특정 버전으로: 이 행 변경 이력, 이 행 상태로 되돌리기

1. 결과 그리드에서 그 행의 셀을 고르고 **플래시백 > 이 행 변경 이력**을 고릅니다. 새 SQL 탭에 `VERSIONS BETWEEN` 질의가 실행됩니다.
2. 결과는 최신 버전이 맨 위이고, 바로 앞 버전과 값이 다른 칸은 보라색 바탕입니다. `VERSIONS_OPERATION`은 I(넣음), U(바꿈), D(지움)입니다.
3. 돌아갈 모습의 행에서 셀 하나를 고르고 **플래시백 > 이 행 상태로 되돌리기…**를 고릅니다.
4. 창의 「만들어진 DML」을 확인합니다. 지금 행이 있으면 다른 열만 바꾸는 UPDATE, 지금 없는 행(지운 행)이면 INSERT 입니다.
5. 「반영(커밋 안 함)」을 누르고, 결과를 확인한 뒤 커밋하거나 롤백합니다.

- `SELECT * FROM emp AS OF TIMESTAMP SYSTIMESTAMP - INTERVAL '1' HOUR`처럼 직접 쓴 플래시백 질의 결과에서도 됩니다. 테이블 하나를 조회하고 기본 키 열이 결과에 있어야 합니다.
- Tibero 는 `VERSIONS BETWEEN`을 지원하지 않습니다. `AS OF` 결과에서 씁니다.

### 되돌린 것을 다시 되돌리기

되돌리기로 1행을 바꾼 문장마다 반대 문장이 변경 일지에 새 커밋 묶음으로 남고, 그 세션을 커밋하면 확정됩니다.

- 「원복 실행 (커밋 안 함)」: 반대 문장이 새 커밋 묶음으로 남습니다. 그 묶음의 문장 줄에는 실제로 실행한 원복 문장 원문과 실행 직전 시점이 남고, 원인은 「원복 실행(#번호)」입니다.
- 「이 실행 전과 비교」의 반영, 「이전 값으로 되돌리기」, 「이 행 상태로 되돌리기」: 「비교 반영」 묶음으로 남습니다.

되돌린 것이 틀렸으면 이 묶음을 골라 위와 같이 되돌립니다.

### 정의(DDL)를 되돌리기

1. **도구 > 변경 일지**를 엽니다. 스키마 브라우저에서 객체를 오른쪽 클릭해 **변경 일지 보기**를 고르면 그 객체의 보관본만 나옵니다.
2. 되돌릴 보관본을 고릅니다. 아래 칸에 바로 앞 보관본과의 차이가 보입니다.
3. 「이 DDL 을 새 편집기에 열기」를 누르고, 내용을 확인한 뒤 직접 실행합니다.

DDL 보관본은 정의만 돌립니다. `ALTER TABLE … DROP COLUMN`으로 잃은 열의 값은 돌아오지 않습니다. 이럴 때를 위해 실행 확인 창의 「먼저 백업 테이블 만들기」를 켜고 실행하세요.

### 지운 테이블 되살리기

1. **데이터베이스 > 객체 검색**의 「휴지통」 탭을 엽니다.
2. 「새로 고침」을 누르고 되살릴 항목을 고릅니다.
3. 이름이 겹치면 「되살릴 때 새 이름(선택)」 칸에 다른 이름을 씁니다.
4. 「되살리기」를 누릅니다.

`DROP TABLE … PURGE`나 「비우기(Purge)」로 지운 테이블은 휴지통에 없습니다. 데이터 복사의 「테이블 다시 만들기」로 지운 옛 테이블도 휴지통에 남고, 알림 줄에 되살리는 문장이 나옵니다([끝난 뒤](../../transfer/data-copy/#끝난-뒤)).

## 미리 켜 둘 것

되돌리기는 실행할 때 남긴 기록을 씁니다. 실행한 뒤에 켜면 그 실행은 되돌릴 수 없으므로 미리 확인해 두세요.

| 할 일 | 곳 | 처음 값 |
|---|---|---|
| 운영 DB 접속의 환경을 「운영」으로 정하기 | 접속 편집([접속 편집 영역의 나머지 칸](../../connect/manage/#접속-편집-영역의-나머지-칸)) | 「개발」 |
| 직전 시점(SCN) 기록 켜기 | **설정 > 되돌리기** 「쓰기 문장을 실행할 때 직전 시점(SCN) 기록」 | 켜짐 |
| 운영 접속 원복 스크립트 켜기 | **설정 > 되돌리기** 「운영 접속에서 원복 스크립트 만들기」 | 켜짐 |
| 원복 스크립트를 만들 행 수 상한 | **설정 > 되돌리기** 「문장당 상한」 | 100,000행 |
| 원복 스크립트 보관 기간 | **설정 > 되돌리기** 「보관 기간」(1~365일) | 30일 |
| 백업 테이블 권하기 | **설정 > 되돌리기** 「TRUNCATE·DROP COLUMN·DROP … PURGE 앞에서 백업 테이블 만들기 권하기」 | 켜짐 |
| 이 행 변경 이력 쓰기 | **설정 > 결과 그리드** 「변경 추적하기」, 「변경 추적 기간」 | 켜짐, 최근 1.5일 |
| 자동 커밋 끄기 | **SQL > 자동 커밋 켜기/끄기 (이번 실행)** | 꺼짐 |

- 환경을 정하지 않은 접속은 「개발」 접속으로 다룹니다. 개발 접속에서는 원복 스크립트를 만들지 않고 실행 확인 창도 나오지 않습니다. 운영 DB 접속은 반드시 환경을 「운영」으로 정하세요.
- 원복 스크립트는 이 PC 의 OS 보안 저장소(Windows 는 DPAPI, macOS 는 키체인)로 암호화해 보관합니다. 보안 저장소가 없는 PC 에서는 만들지 않습니다.
- 플래시백과 시점 비교로 다른 스키마의 테이블을 다루려면 그 테이블의 FLASHBACK 권한이 필요합니다. 미리 DBA에게 받아 두세요.
- 설정 항목은 [설정](../../settings/options/#되돌리기)에서 설명합니다.

## 안 되는 경우와 대안

| 안 되는 경우 | 이유 | 대안 |
|---|---|---|
| 개발·테스트 접속에서 원복 스크립트가 없습니다. | 원복 스크립트는 운영 접속에서만 만듭니다. | 「이 실행 전과 비교…」를 씁니다. |
| 「기준 시점의 값을 undo 에서 잃었습니다」, ORA-01555 | 서버의 undo 보존 기간이 지났습니다. | 운영 접속이면 원복 스크립트를 씁니다. 그 밖에는 백업이나 다른 DB의 사본에서 값을 찾아야 합니다. |
| 원복 스크립트가 「불완전」입니다. | 트리거·`ON DELETE CASCADE`로 함께 바뀐 테이블, LOB 같은 큰 열, 잠근 행 수와 실행한 행 수가 다른 문장이 있습니다. | 빠진 부분을 「이 실행 전과 비교…」로 견주거나 직접 고칩니다. |
| MERGE, `INSERT … SELECT`, PL/SQL 블록 안의 DML 을 되돌리려 합니다. | 원복 스크립트를 만들지 않는 문장입니다. | 실행 직전 시점은 남으므로 「이 실행 전과 비교…」를 씁니다. |
| 원복 실행의 문장이 0행으로 끝납니다. | 그 뒤 다른 사람이 값을 바꿨습니다. 덮어쓰지 않으려고 건너뜁니다. | 「이 실행 전과 비교…」로 지금 값을 보고, 덮어써야 하면 「충돌 행도 되돌리기」를 켭니다. |
| 보관 기간(처음 값 30일)이 지났습니다. | 원복 스크립트와 커밋 묶음을 지웠습니다. | 되돌릴 기록이 없습니다. 보관 기간을 늘려 두세요. |
| 자동 커밋으로 실행했습니다. | 문장마다 바로 커밋했습니다. | 롤백은 안 됩니다. 커밋한 뒤와 같은 방법(원복 스크립트, 이 실행 전과 비교)을 씁니다. |
| `TRUNCATE` 뒤 이전 데이터를 찾습니다. | `TRUNCATE`는 DDL이라 플래시백(AS OF)으로도 읽을 수 없습니다. | 백업 테이블을 만들었으면 거기서 다시 넣습니다. 없으면 되돌릴 수 없습니다. |
| 뷰를 통해 바꾼 데이터를 되돌리려 합니다. | 시점 비교와 원복 스크립트는 뷰를 다루지 않습니다. | 뷰의 바탕 테이블을 조회해 플래시백으로 되돌립니다. |
| 다른 스키마 테이블에서 ORA-01031, ORA-41900 이 납니다. | FLASHBACK 권한이 없습니다. | 소유자나 DBA에게 `GRANT FLASHBACK ON 소유자.테이블 TO 접속 사용자`를 받습니다. |
| Tibero 에서 「이 행 변경 이력」이 TBR-8022 로 실패합니다. | Tibero 는 `VERSIONS BETWEEN`을 지원하지 않습니다. | `AS OF` 질의 결과에서 「이 행 상태로 되돌리기…」를 씁니다. |

Oranda는 `FLASHBACK TABLE`, Flashback Transaction Query, LogMiner 를 쓰지 않습니다. 추가 권한 없이 동작하게 하려는 것입니다. 이런 서버 기능이 필요하면 DBA와 상의하세요.
