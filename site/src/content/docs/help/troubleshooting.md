이 쪽은 문제를 찾는 출발점입니다. 기능별 증상과 해결은 각 쪽의 「문제가 생길 때」 절에 있습니다. 아래 표에서 증상에 맞는 쪽을 찾으세요. 앱 전체와 관련한 확인 방법과 로그 위치는 이 쪽에서 설명합니다.

## 먼저 확인할 것

1. 도움말 메뉴의 **Oranda 정보**로 버전을 확인합니다. 문제를 보고할 때도 이 버전을 알려 주세요.
2. **도움말 > 업데이트 확인…**으로 새 버전이 있는지 확인합니다. 새 버전에서 고쳐졌을 수 있습니다. [업데이트와 릴리스 노트](../../install/update/)를 보세요.
3. 같은 일이 다른 접속에서도 생기는지 확인합니다. 한 접속에서만 생기면 그 접속의 계정 권한이나 설정 문제일 수 있습니다.
4. 같은 일이 새 SQL 탭에서도 생기는지 확인합니다.

## 메뉴나 도구가 보이지 않을 때

기능이 꺼져 있으면 그 기능의 메뉴와 도구 창이 보이지 않습니다.

1. **도구 > 설정**을 열고 「기능」 탭으로 갑니다.
2. 「주 업무」를 확인합니다. 처음 설치한 상태는 「SQL 개발」입니다. 튜닝, 모니터, 운영 도구가 필요하면 「튜닝」, 「운영 DBA」, 「모든 기능」 중에서 고릅니다.
3. PL/SQL이나 MyBatis가 필요하면 「함께 하는 일」을 덧붙입니다.
4. 일부 기능은 앱을 다시 시작해야 적용됩니다. 「재시작하면 적용됩니다」가 나오면 다시 시작하세요.

도구 창이 보이지 않으면 **보기 > 도구 창**에서 켜거나 **창 > 레이아웃 초기화**를 씁니다. [창 배치와 도구 창](../../settings/layout/)을 보세요.

## 단축키가 동작하지 않을 때

- 단축키는 범위가 있습니다. 편집기, SQL 탭, 결과 그리드 같은 자리에 포커스가 있어야 동작하는 키가 많습니다. [단축키와 명령 팔레트](../../settings/shortcuts/)의 표에서 범위를 확인하세요.
- 키맵 프리셋이 바뀌었는지 **도구 > 단축키 설정**에서 확인합니다.
- 키가 충돌하면 단축키 설정 창 아래에 「충돌: …」이 나옵니다.
- 명령 팔레트(`Ctrl+Shift+P`, macOS `Cmd+Shift+P`)에서 명령 이름으로 찾아 실행할 수 있습니다. 명령 이름 옆에 그 명령의 단축키가 보입니다.
- 흐리게 보이는 명령은 지금 쓸 수 없는 명령입니다. 접속이 없거나 SQL 탭이 아닌 경우가 많습니다.

## 설정을 되돌리고 싶을 때

- 단축키는 단축키 설정 창의 **모두 되돌리기**로 프리셋 그대로 되돌립니다.
- 도구 창 배치는 **창 > 레이아웃 초기화**로 되돌립니다.
- 기능 구성은 설정 창 「기능」 탭의 **기본값으로 되돌리기**로 되돌립니다.
- 다른 PC에서 쓰던 설정은 **도구 > 설정 가져오기**로 옮깁니다. 가져오기 전에 **설정 내보내기**로 지금 설정을 보관하세요. [설정](../../settings/options/)을 보세요.
- 설정 파일이 손상되었으면 Oranda가 손상된 파일을 백업하고 처음 값으로 시작하면서 알려 줍니다.
- 새 버전 Oranda가 만든 설정 파일이나 배치 파일은 읽기 전용으로 다룹니다. 이 경우 설정 창의 「저장」이 꺼지고 설정 창 아래에 이유가 나옵니다. 앱을 새 버전으로 맞추세요.

## 로그 파일

Oranda는 명령 실행 실패와 처리하지 못한 예외를 로그 파일에 남깁니다. 문제를 보고할 때 이 파일을 함께 보내면 원인을 찾기 쉽습니다.

- 파일 이름은 `oranda-yyyyMMdd.log`입니다. 날마다 파일이 하나입니다. 예: `oranda-20261104.log`.
- 위치는 데이터 폴더 안의 `logs` 폴더입니다.
- 로그에는 SQL 문장이나 오류 내용이 들어 있을 수 있습니다. 보내기 전에 파일을 열어 회사 정보나 접속 정보가 없는지 확인하세요.

## 데이터 폴더

설정, 접속 목록, 작업 공간, 배치 파일은 데이터 폴더에 있습니다.

| 운영체제 | 데이터 폴더 |
|---|---|
| Windows | `%APPDATA%\Oranda` |
| macOS | `~/Library/Application Support/Oranda` |

- 환경 변수 `ORANDA_DATA_DIR`에 폴더를 지정하면 그 폴더를 데이터 폴더로 씁니다. 다른 폴더에서 휴대용으로 쓸 때 유용합니다.
- 폴더 안의 주요 항목은 다음과 같습니다.

| 이름 | 내용 |
|---|---|
| `settings.json` | 설정 |
| `connections.json` | 접속 목록 |
| `layout.json` | 창 배치 |
| `workspaces` | 작업 공간 |
| `autosave` | 자동 저장 |
| `keymaps` | 사용자 키맵 |
| `formatter` | 포매터 프로필 |
| `layouts` | 이름 붙인 배치 |
| `logs` | 로그 |
| `backup` | 손상되어 옮겨 둔 파일(`이름.corrupt-시각`) |

- 파일을 직접 고치기 전에는 Oranda를 끄고 폴더를 복사해 두세요.
- 접속 목록을 다른 곳으로 옮길 때는 접속 관리자의 내보내기와 가져오기를 쓰세요. 내보낸 파일에는 비밀번호가 들어가지 않습니다. [접속 관리](../../connect/manage/)를 보세요.

## 그래도 해결되지 않을 때

1. 증상이 생기기 직전에 한 일, 화면에 나온 오류 글, Oranda 버전, 운영체제를 적습니다.
2. 위의 로그 파일을 확인합니다.
3. 1번의 내용과 로그를 Oranda를 배포한 담당자에게 전달합니다. 소스 저장소는 `https://github.com/jongik-sv/oranda`입니다. 접속 주소, 계정 이름, 비밀번호, 회사 정보는 지우고 보내세요.
