#### macOS 시스템 메뉴 막대

- macOS 에서는 창 안 `Menu` 를 숨기고(`IsVisible=false`, 키보드 이동에서도 제외) 같은 `MenuNode` 모델에서 만든 `NativeMenu` 를 창에 붙인다(`MenuControls.BuildNativeMenu`). Windows·Linux 는 창 안 메뉴 그대로다. 메뉴 원본은 명령 레지스트리 하나이며 새 명령은 두 쪽에 모두 나온다.
- 이름: 앱 이름 `Application.Name = "Oranda"`(`App.axaml`). 최상위 메뉴는 접근 키 표기 없이 「파일」「편집」…「도움말」. 항목 글자는 창 안 메뉴와 같은 문자열 표를 쓴다.
- 앱 메뉴(Oranda): 「Oranda 정보」(`oranda.help.about`), 「설정…」(`oranda.tools.settings`, ⌘,), 그 뒤에 Avalonia 가 서비스·숨기기·모두 보기·종료를 붙인다(`MacAppMenu`). 도구 > 설정 항목은 그대로 둔다.
- 단축키: `NativeMenuItem.Gesture` 가 표시와 실행을 함께 맡는다. AppKit 이 ⌘ 키를 창보다 먼저 메뉴에서 찾고, 활성 항목에 맞으면 이벤트를 소비하므로 키맵 `KeyDispatcher` 로는 가지 않는다(한 번만 실행). 항목이 비활성이면 키는 창으로 내려가 키맵이 처리한다. 입력 칸(TextBox)에 포커스가 있을 때의 글자 편집 키(⌘C·X·V·A·Z·⇧⌘Z)는 `NativeMenuCommand` 가 그 입력 칸에 직접 전달한다.
- 활성·체크 갱신: 메뉴를 열거나 단축키를 찾을 때(`NativeMenu.NeedsUpdate`) 그리고 문맥 키가 바뀔 때 `RegistryCommand.CanExecute` 로 다시 계산한다. 보기 > 도구 창은 `ToggleType=CheckBox` 로 보임 상태를 체크한다.
- 떠 있는 도킹 창(`FloatHostWindow`)도 key 창일 때 같은 메뉴가 시스템 막대에 보이도록, 창마다 자기 `NativeMenu` 뿌리를 가진다(`FloatHostWindow.Presenting` → `MainWindow.AttachFloatMenu`). 대화상자(모달)는 앱 메뉴만 남아도 된다.
- 앱 메뉴 기본 항목(서비스·Oranda 가리기·기타 가리기·모두 보기·Oranda 종료)은 Avalonia 가 영어로 붙이지만 우리가 넘긴 `NativeMenu` 안에 들어 있어, `MacAppMenu` 가 UI 언어에 맞춰 글자를 바꾼다(`Menu.app.*`). 「기타 가리기」 단축키는 표준 ⌥⌘H 로 바로잡는다.
- 아이콘은 시스템 메뉴에 그리지 않는다(글자만).

## 2. 도킹 배치와 도구 창 목록

### 2.1 기본 배치

| 위치 | 기본 폭/높이 | 들어가는 도구 창(탭 순서) |
|---|---|---|
| 왼쪽 | 280 DIP, 창 전체 높이 | 스키마 브라우저(아래에 속성 창), 이름 붙인 스크립트 |
| 오른쪽 | 300 DIP, 문서 영역 옆(아래 묶음 위). 바인드 변수(위)·템플릿(아래)은 한 열에 쌓아 기본으로 열고, 나머지는 기본 숨김(자동 숨김 막대). 예전 layout.json 은 `migrations` 표지(`rightToolsOpen`)로 한 번만 옮긴다(TSK-13-16) | 문서 개요, 템플릿, 바인드 변수, 행 보기, 확장 시험 패널(개발 빌드) |
| 아래 | 220 DIP, 문서 영역 밑(왼쪽 묶음 오른쪽 열 안) | 조회 결과, 메시지, DBMS 출력, 실행 계획, 실행 이력, 컴파일 오류(오렌지 Output 창의 Message·Server Output, SQL Developer 의 Query Result·Script Output 순서) |
| 문서 영역 | 나머지 | 문서 탭(편집기, 객체 상세, 모니터, DB 정보 등) |

- 트리 모양: `가로[왼쪽 묶음, 세로[문서(+오른쪽 묶음), 아래 묶음]]`. 왼쪽 묶음(스키마 브라우저)은 창 위에서 아래까지 다 쓰고, 아래 묶음은 편집기 밑에만 놓인다(오렌지·SQL Developer 와 같다).
- `layout.json` 버전 1 의 예전 기본 모양 `세로[가로[왼쪽 묶음, 문서, …], 아래 묶음]` 은 읽을 때 한 번 새 모양으로 옮긴다(`LayoutLeftFullHeightMigration`, 왼쪽 폭·아래 높이 비율 유지). 사용자가 다른 모양으로 바꾼 배치는 그대로 둔다.

- 첫 실행 = 위 배치. 사용자가 바꾼 배치는 종료 때 `layout.json`(앱 DTO, 스키마 버전 필드, TSK-02-01 data-model)에 저장하고 시작 때 복원한다. Dock 의 직렬화 형식을 그대로 저장하지 않는다(라이브러리 버전이 바뀌어도 파일이 깨지지 않게).
- 복원할 때 등록되지 않은 도구 창 ID(플러그인 제거 등)는 건너뛰고, 새로 등록된 도구 창은 자기 기본 위치에 추가한다. 그 위치에 묶음이 있으면 묶음 안에서 자기 순서(`Order`) 자리에 넣는다(맨 뒤가 아니라 기본 배치와 같은 자리).
- `view.resetLayout` = 기본 배치로 되돌림.
- 이름 붙인 레이아웃(Toad Desktop Layout·PL/SQL Developer 레이아웃 저장처럼): 창 메뉴의 `window.saveLayoutAs`·`window.applyLayout`·`window.deleteLayout`. 도구 창 배치만 저장·적용하고 열린 문서(작업 공간)는 그대로 둔다(`{data}/layouts/{id}.json`, data-model 2.5).
- 시작 시간(D-006): 첫 프레임에는 문서 영역·스키마 브라우저 틀만 그린다. 숨겨진 도구 창의 View 는 처음 보일 때 만든다(지연 생성).

규칙:
- 도구 창 ID = `oranda.panel.<camelCase>`. 그 도구 창을 보이는 명령 = `oranda.view.<같은 이름>`(문서 종류는 위 표의 명령).
- 도구 창 등록 정보: ID, 이름(리소스 키), kind, 기본 위치, 기본 크기, 여러 개 허용, 아이콘, 순서, ViewModel 형식. 특성(attribute)으로 달고 셸이 어셈블리를 스캔한다(TSK-02-05). **셸 파일을 고치지 않고** 도구 창이 늘어난다.
- 접속에 묶인 도구 창(출력·메시지·계획·이력·컴파일 오류)은 **활성 문서의 접속**을 따라 내용이 바뀐다. 모니터는 자기 전용 세션(CONN-07)을 가진다.
- 접속은 여러 개 동시에 연다(CONN-06, TSK-03-08). SQL 탭마다 자기 접속을 갖고, 새 탭은 그때의 「지금 접속」 을 물려받는다. 「지금 접속」 = 활성 SQL 탭의 접속(SQL 탭이 활성이 아니면 마지막으로 고른 접속)이고, 스키마 브라우저·객체 상세·PL/SQL 편집기·DB 정보·도구·표 정의서·열 순서·모니터 기본값은 이를 따른다. 세션 고르기는 `SessionRouter` 한 곳에서 한다.
- 탭의 접속이 닫혔으면(끊기, 작업 공간 복원 — 복원 때 자동 접속 안 함) 콤보에 「접속 안 됨(프로필 이름)」, 상태 표시줄에 「접속 없음」 을 보이고 테두리를 그리지 않는다. 그 탭에서 실행하면 「다시 접속 / 지금 접속(X)으로 바꾸기 / 취소」 를 묻는다.
- 접속 끊기는 보이는 접속 하나만 닫는다(미커밋이면 묻는다). 앱 종료 때 미커밋 확인은 접속마다 한다. 끊긴(broken) 접속의 미커밋은 묻지 않고 서버가 되돌렸다고 알린다.
- 스키마 브라우저에서 객체 열기(SCH-01): 객체 노드를 누르면 종류에 맞는 문서로 연다. PL/SQL 단위는 `oranda.panel.plsqlEditor`(서버 소스), 그 밖은 `oranda.panel.objectDetail` 이다(종류 나누기는 DB 객체로 이동과 같다). 열기 규칙은 `SchemaObjectOpener` 한 곳에 둔다.
  - 미리보기 탭(VS Code 방식): 한 번 누르기, 또는 키(방향키·Home·End·PageUp·PageDown·글자 찾기)로 다른 노드를 고르고 250 ms 멈추면 미리보기 탭으로 연다(누르고 있는 동안은 계속 미룬다). 미리보기 탭은 문서 영역에 하나뿐이고 머리글이 기울임꼴이다. 다음 미리보기는 그 탭 자리에 새 탭을 넣고 옛 탭을 닫는다(`DockWorkspace.OpenPreviewDocument`). 옛 탭을 닫을 때의 정리(데이터 탭 커서 닫기)와 읽기 취소가 그대로 돈다. 키보드 포커스는 트리에 남는다.
  - 고정: 두 번 누르기·Enter(연 문서로 포커스를 옮긴다. PL/SQL 은 글 편집 영역, 객체 상세는 구역 목록), 미리보기 탭 머리글 두 번 누르기, PL/SQL 글 고침, 데이터 탭 편집 켬. 고친 내용이 남은 미리보기는 바꿔 끼우지 않는다. 미리보기 동안은 창으로 떼어 내기를 끈다. Dock 은 탭 머리글을 두 번 누르면 창으로 떼어 내는데, 미리보기 탭에서는 그 동작이 고정이어야 하기 때문이다(고정 탭은 지금처럼 떼어 낸다).
  - 같은 접속(DbKey)의 같은 객체(소유자·이름·유형. 패키지와 패키지 본문은 다른 객체)가 이미 열려 있으면 새로 열지 않고 그 탭을 앞으로 낸다. 스키마·범주·「더 보기」·열·메시지 노드는 열지 않는다. 표·뷰 노드를 두 번 눌러도 트리 펼침은 바뀌지 않는다.
  - 코드가 고른 선택(트리에서 찾기·필터 다시 읽기·오른쪽 단추)은 미리보기를 열지 않는다. 설정 `schemaBrowser.singleClickPreview`(설정 창 「일반」, 기본 켬)를 끄면 한 번 누르기는 속성 창만 바꾼다. 접속이 없거나 세션이 실행 중·끊김이면 열지 않고 스키마 브라우저 상태 줄에 알린다.
- DB 객체로 이동(`oranda.nav.quickOpenObject`, TSK-04-06)은 도킹하지 않는 작은 창이다. 명령 팔레트와 같은 모양(입력칸·객체 목록(유형 아이콘·`소유자.이름`·유형)·상태 줄)이고 Enter 열기·Alt+Enter 스키마 브라우저에서 찾기·Esc 닫기. 스키마 브라우저에서 찾기(`oranda.schema.reveal`)는 스키마 브라우저 도구 창을 앞으로 내고 트리 노드를 고른다.
- 템플릿 창(`oranda.panel.templates`, 오렌지 Template·SQL Developer Snippets 창처럼)은 위에서부터 찾기 칸, 종류 단추 줄과 「새 조각」, 종류별 묶음 목록, 나누기 막대, 미리보기, 상태 줄이다.
  - 종류 단추: 전체·조각·힌트·함수·의사 열. 좁은 도구 창에 맞게 아이콘만 그리고 이름은 도움말 풍선·낭독기 이름으로 낸다. 라디오 묶음이라 늘 하나가 켜져 있다(빈 칸 없음).
  - 목록: 종류별 묶음 머리(아이콘·종류 이름·개수, 접기 가능, 찾으면 모두 편다) 아래 촘촘한 행(`TreeView.compact`). 행 = 종류 아이콘, 줄임말(편집기 글꼴), 흐린 짧은 설명(설명 → 줄임말과 다른 이름 → 본문 첫 줄 순, 줄임말을 두 번 보이지 않는다). 찾은 낱말은 굵게·강조색. 도움말 풍선에 이름과 설명 전체. 사용자 조각은 조각 묶음 맨 앞(찾을 때는 줄임말이 맞는 순서).
  - 미리보기: 이름·설명 한 줄과 삽입될 SQL(자리 표시자는 기본값). 편집기와 같은 렉서 강조·글꼴 설정을 쓰는 읽기 전용 보기(`SqlCodeView`)이고 줄 번호 없이 줄을 꺾는다. 머리 줄 오른쪽에 삽입·복제 단추, 사용자 조각이면 편집·지우기 단추.
  - 동작: Enter·두 번 누르기 = 활성 편집기에 삽입(조각은 자리 표시자 탭 이동, 삽입 뒤 편집기로 초점), 편집기로 끌어 놓기 = 자리 표시자를 기본값으로 푼 글자 삽입. 찾기 칸에서 ↓ = 목록 첫 항목, Enter = 고른(없으면 첫) 항목 삽입, Esc = 찾는 글 지우기. 목록에서 F2 = 편집, Delete = 지우기(확인), Esc = 찾기 칸. 오른쪽 클릭 = 삽입·본문 복사·사용자 조각으로 복제·편집·지우기(편집·지우기는 사용자 조각만).
  - 사용자 조각은 편집 대화상자(줄임말·이름·설명·본문)로 만들고 고친다. 본문 칸은 SQL 편집기와 같은 강조를 쓰고 아래에 `$1`·`${1:기본값}`·`$0` 안내를 둔다. 줄임말은 영문·숫자·밑줄만(편집기에서 Tab 으로 펼칠 수 있는 글자), 다른 사용자 조각과 겹치면(대소문자 무시) 저장하지 않는다. 기본 조각과 같은 줄임말은 막지 않고 「기본 조각 대신 이 조각이 Tab 으로 펼쳐진다」 알림을 보인다. 기본 제공 항목은 고칠 수 없고 「사용자 조각으로 복제」만 된다(복제는 기본·사용자 조각과 겹치지 않는 줄임말 `원래_2` 를 제안).
  - 내장 항목의 영어 이름·설명은 `Oranda.Language` 의 내장 목록 옆 영어 표에 두고, 묶음 이름·상태 글·메뉴는 `strings-*.json` 의 `Templates.*` 키로 화면 언어를 따른다.

## 4. 환경 라벨 규칙 (SAFE-01, CONN-06)

### 4.1 라벨과 색

라벨 값은 접속 프로필의 `environment`(data-model 2.2, `ConnectionEnvironment { Development, Test, Production }`)다.

| 라벨 값 | 표시 글자 | 밝은 테마 | 어두운 테마 | 사용자 색 변경 |
|---|---|---|---|---|
| `Production` | 운영 | `#C42B1C` | `#FF6B5E` | **불가**(항상 빨강) |
| `Test` | 테스트 | `#B65A00` | `#F0A04B` | 가능 |
| `Development` | 개발 | `#107C10` | `#6CCB5F` | 가능 |

- 「지정 안 함」 값은 없다. 프로필 파일에 `environment` 가 없으면 기본값 `Development`(개발)로 읽어 개발 라벨을 보인다. 접속 관리자(TSK-03-04)는 새 프로필에서 셋 중 하나를 고르게 한다.
- 라벨이 없는 경우는 **접속이 없는 문서**(접속을 고르지 않은 편집기, 설정 등)뿐이다. 이때 테두리·칩 없이 테마 기본 색을 쓴다(4.2 「접속 없음」 열).
- 알 수 없는 값(미래 버전 파일 등)은 안전 쪽으로 `Production` 으로 다룬다(빨강·확인 대화상자).

- 사용자 지정 색은 「빨강 계열(색상 각도 345°~15°, 채도 50% 이상)」을 고를 수 없다 — 빨강은 운영만 뜻한다. 접속 관리자(TSK-03-04)가 막는다.
- 색만으로 구분하지 않는다(7.5 접근성): 항상 라벨 글자를 함께 보이고, 운영은 방패 아이콘을 붙인다. 화면 낭독기 이름에도 「운영 접속」을 넣는다.
- 대비: 라벨 칩 글자와 바탕 대비 4.5:1 이상(두 테마 모두). 위 색은 흰 글자(밝은 테마)·검정 글자(어두운 테마) 기준으로 맞춘 값이다.

### 4.2 표시 위치

| 위치 | 운영 | 테스트·개발 | 접속 없음 |
|---|---|---|---|
| 창 테두리 | 창 안쪽 가장자리에 3 DIP 빨강 틀 | 3 DIP 라벨 색 틀 | 없음 |
| 문서 탭 | 탭 위쪽 3 DIP 빨강 띠 + 「운영」 칩 + 방패 아이콘 | 띠 + 칩 | 없음 |
| 상태 표시줄 | **표시줄 전체 바탕 빨강**, 글자 흰색 | 1번 구간에 칩만 | 1번 구간에 「접속 없음」 |
| 실행 확인 대화상자 | 머리 띠 빨강 + 접속 이름·사용자·서비스 크게 | — | — |
| 툴바 접속 콤보 | 항목마다 칩 | 칩 | — |

- **창 테두리·상태 표시줄은 활성 문서의 접속을 따른다.** 운영 문서에서 개발 문서로 탭을 바꾸면 테두리도 바뀐다. 활성 문서가 접속 없는 문서이면 테두리 없음.
- 창 테두리는 OS 창 장식을 칠하지 않고 **창 내용 안쪽에 그린다**(Windows·macOS 같은 동작, 최대화·전체 화면에서도 보임).
- 운영 접속 문서가 하나라도 열려 있으면 창 제목에 `[운영]` 을 붙인다(다른 앱 위에서 작업 표시줄만 보여도 알 수 있게). 접속이 여러 개면 활성 문서가 개발 접속이어도 운영 접속이 열려 있는 동안 붙인다.
- 떠 있는(floating) 도구 창은 자기 내용의 접속 라벨로 테두리를 그린다.

### 4.3 실행 확인과의 관계

- 라벨은 **표시**, 확인 여부는 **정책 관문**(`IExecutionPolicy`, TRD 4.9)이 정한다. 관문은 프로필의 `EnvironmentLabel == Production` 값을 보며 **색을 보지 않는다**. 그래서 사용자가 색을 바꿔도 안전장치는 약해지지 않는다.
- 운영 + DML/DDL → `Confirm`, WHERE 없는 UPDATE/DELETE → 모든 접속에서 경고, 위험 명령 → 이름 재입력(옵션). 대화상자 모양은 TSK-06-02 소유, 라벨 색·문구는 이 절을 따른다.
- 확인 대화상자의 기본 단추는 「취소」다(Enter 로 바로 실행되지 않음). 운영 확인은 실행 단추에 포커스를 두지 않는다.
- 같은 규칙이 그리드 반영(TSK-06-04)·모니터 Kill(TSK-09-01)·확장 패널(TSK-10-03)에도 적용된다(모두 `IExecutionService` 경유).

## 5. HiDPI 배율 100~250% 레이아웃 기준

Avalonia 는 모든 크기를 DIP(1/96 인치) 단위로 다루고 배율을 자동 적용한다. 아래는 「배율 250% 에서 잘리지 않는다」(TSK-03-01 수락 기준)를 지키는 규칙이다.

| 항목 | 기준 |
|---|---|
| 단위 | XAML·코드 모두 DIP. 물리 픽셀 계산은 그리드 그리기(`RenderScaling`)에서만 |
| 메인 창 최소 크기 | 960 × 600 DIP. 화면 작업 영역(DIP)이 이보다 작으면 최소 크기를 작업 영역으로 줄이고 최대화로 연다(예: 1920×1080 화면 250% = 768×432 DIP) |
| 첫 실행 창 크기 | 작업 영역의 80%, 1280 × 800 DIP 상한 |
| 대화상자 | 최소 크기만 두고 내용에 맞춰 늘어난다(`SizeToContent`). 작업 영역보다 크면 본문을 스크롤 영역에 넣고 단추 줄은 항상 보이게 고정 |
| 글자 있는 컨트롤 | 고정 `Width`/`Height` 금지. `MinWidth` + 자동 크기. 잘릴 수 있는 칸(탭 머리·상태 표시줄·트리)은 `TextTrimming=CharacterEllipsis` + 도움말 풍선에 전체 글자 |
| 단추·레이블 폭 | 한국어·영어 중 긴 쪽 기준(영어가 1.3~1.6배 길다, TSK-10-02). 단추 최소 폭 80 DIP |
| UI 글꼴 | Inter + 한글 대체(Windows 맑은 고딕, macOS Apple SD Gothic Neo), 기본 13 DIP, 설정에서 12~16. 모든 크기는 테마 리소스 키(`OrandaFontSizeBase` 등)에서 받는다 |
| 에디터·그리드 글꼴 | 사용자 지정(기본: Windows `Cascadia Mono`→`Consolas`, macOS `SF Mono`→`Menlo`, 한글 대체 위와 같음), 기본 13 DIP. 글자 크게/작게(`view.zoomIn/Out`)는 에디터·그리드·출력에 같이 적용, 8~32 |
| 행 높이 | 고정 픽셀 금지. 그리드·트리 행 높이 = 글꼴 줄 높이 + 위아래 여백(각 3 DIP) |
| 아이콘 | **벡터만**(`PathIcon`/`StreamGeometry`, 16 DIP 격자, 툴바 16, 도구 창 탭 14). 비트맵 아이콘 금지. 앱 아이콘만 다중 해상도(ico 16~256, icns) |
| 선 두께 | 1 DIP 선은 250% 에서 2.5 픽셀이 되어 흐려질 수 있다 → 테두리·분할선은 `UseLayoutRounding=true`(기본) 유지, 그리드 격자선은 물리 픽셀 1 로 스냅해 그린다 |
| 그리드 텍스트 캐시(D-008) | `GlyphRun`/`TextLayout` 캐시 키에 배율을 넣고, 창이 다른 배율 모니터로 옮겨지면(`ScalingChanged`) 캐시를 비운다 |
| 다중 모니터 | 모니터별 배율 다름(Windows Per-Monitor V2 매니페스트 — 이미 `app.manifest`) — 옮길 때 다시 배치만 하고 글자 크기는 DIP 그대로 |
| 시험 | Headless 시험에서 배율 1.0·1.5·2.0·2.5 로 메인 창·설정·접속 관리자·실행 확인 대화상자를 960×600 에 띄워 「글자 영역이 부모 경계를 넘지 않음」을 검사(TSK-03-01, TSK-10-02) |

## 6. 테마

| 항목 | 규칙 |
|---|---|
| 기본 테마 | Avalonia `FluentTheme` + `Dock.Avalonia.Themes.Fluent` |
| 모드 | 밝게 / 어둡게 / OS 따르기(기본). `RequestedThemeVariant` = `Light`/`Dark`/`Default` 로 바꾼다. 재시작 없이 즉시 적용 |
| 색 정의 | 앱 색은 `ThemeDictionaries` 의 `Light`·`Dark` 두 벌에 리소스 키로만 둔다(`OrandaEnvProductionBrush`, `OrandaUncommittedBrush` 등). 코드에 색 값 직접 쓰기 금지 |
| 에디터 색 | 구문 강조 색표는 테마별 2벌(Light·Dark). 사용자 색표 변경은 1.0 범위 밖 |
| 그리드 | 홀짝 행 바탕, 선택, NULL 표시 색, 편집 불가 열 색, 변경 셀 색 — 모두 테마 리소스 |
| 단추·숫자 입력 | 일반 `Button` 은 `OrandaButtonBackgroundBrush`·`OrandaButtonBorderBrush` 로 1 DIP 테두리·높이 28 로 그린다. accent 단추는 Fluent 모양을 따르고, `.toolbar`·`.tool`·`.palette-box`·`.start-item` 과 Dock 의 `PART_*` 단추는 제외한다. `NumericUpDown` 은 `ButtonSpinner` 템플릿을 교체해 ▲▼ 를 세로로 쌓고, 한계값에서 disabled 가 되면 흐린 글리프만 남긴다. 색은 Light·Dark 리소스 키만 쓴다 |
| 강조색 | Fluent 기본 강조색(OS 강조색 따르지 않음 — 빨강 강조색이 운영 라벨과 헷갈리지 않게) |
| 고대비 | Windows 고대비 모드에서는 OS 시스템 색을 쓰고, 환경 라벨은 테두리 두께 3 DIP + 글자로만 구분 |

## 7. 기능 Task 가 지킬 것 (요약)

1. 메뉴·툴바·단축키를 따로 만들지 말고 명령을 등록한다(commands.md).
2. 도구 창은 2.2 표의 ID·기본 위치로 등록한다. 새 도구 창이 필요하면 이 표에 행을 더하는 요청을 낸다.
3. 크기는 DIP·자동 크기, 색은 테마 리소스 키, 아이콘은 벡터.
4. 접속에 묶인 화면은 환경 라벨을 4.2 대로 보인다. 확인 여부는 정책 관문에 맡긴다.
