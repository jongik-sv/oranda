# Oranda 0.1.22

## 새 기능

- **「대상에 테이블이 없으면 만들기」가 딸린 객체도 만듦**: 시퀀스·트리거 등 원본 테이블에 딸린 객체를 함께 만듭니다.
  - 원본 테이블에 딸린 시퀀스(열 `DEFAULT 시퀀스.NEXTVAL`, 트리거가 쓰는 시퀀스)가 대상에 없으면 먼저 만듭니다. 대상에 이미 있으면 건드리지 않고, 현재값이 키 최댓값보다 작으면 경고합니다.
  - 트리거(적재 뒤 생성), 함수 기반 인덱스, 대상에 있는 사용자·롤에 주는 권한도 함께 만듭니다. 인덱스·PK·UK는 적재가 끝난 뒤 만듭니다.
  - 시노님, 파티션, 압축, 테이블스페이스·저장 속성은 만들지 않습니다.
- **같은 시점 읽기와 여러 테이블 동시 복사를 함께 사용**: 「같은 시점으로 읽기」를 켠 채로도 「동시 테이블」을 2 이상으로 둘 수 있습니다. 시작할 때 시점 번호(SCN) 하나를 잡아 모든 테이블을 그 시점으로 읽습니다.
  - 번호는 작업 로그와 실행 화면의 「읽기 시작」 옆에 나옵니다.
  - 사전 점검에 「시작 SCN으로 읽음」 항목과 다른 계정 테이블의 `FLASHBACK` 권한 검사가 생겼습니다.
  - 시점 데이터를 읽지 못하면 현재 데이터로 바꿔 읽지 않고 그 테이블을 실패로 둡니다. 원본 UNDO가 모자라면 복사를 멈춥니다.
  - 동시 복사는 지우기를 먼저 확정합니다. 사전 점검이 이를 알립니다.
- **외부 적재 도구**: 테이블 규칙의 적재 방식에서 SQL*Loader를 고를 수 있습니다. 전체 기본값과 테이블별 값이 있고 기본은 꺼짐입니다.
  - 도구는 앱에 들어 있지 않습니다. 설정 > 「드라이버」 탭에서 경로를 지정하고 **도구 확인**으로 확인합니다. 설치 안내도 설정 화면에 있습니다.
  - 비밀번호는 명령줄·파일·로그에 남기지 않습니다.
  - 도구가 실패하면 그 테이블만 기본 방식으로 다시 넣습니다.
  - 측정에서는 기본 방식이 더 빨라서 기본값을 꺼 두었습니다. 쓰기 전에 실제 서버에서 두 방식을 재 보세요.
- **사전 점검에서 바로 고치기**: 사전 점검이 찾은 문제 가운데 규칙을 바꿔 풀 수 있는 것은 체크한 뒤 **선택한 것 처리**로 한꺼번에 고칩니다. 처리하면 작업을 저장하고 점검을 다시 합니다.
  - 처리 예: 없으면 만들기 켜기, 그 열 빼고 복사, 대상 처리를 PK 기준 MERGE로 바꾸기, 복사하는 동안 트리거·자식 FK 끄기, 시퀀스 연결, 한 테이블씩 복사, 같은 시점 읽기 끄기.
  - 처리가 바꾼 칸은 테이블별로 따로 바꾼 것으로 표시되어 규칙 편집에서 되돌릴 수 있습니다.
  - 사전 점검 중에는 대상에 문장을 보내지 않습니다.
- **「대상에 열 추가」**: 원본에는 있고 대상에 없는 열을 `ALTER TABLE … ADD`로 더한 뒤 복사합니다. 열은 NULL 허용, 기본값 없이 더하고, 개발 접속에서만 됩니다. 미리 보기에 보인 문장 그대로 보냅니다.
- **규칙 편집에 다녀와도 점검 결과 유지**: 사전 점검 뒤 규칙 편집에 다녀왔을 때 작업 내용·기간·접속이 그대로면 다시 점검하지 않고 결과로 돌아갑니다(「n분 전 점검」). 고쳤으면 「다시 점검 필요」가 나오고 실행이 막힙니다.
- **패키지·타입을 한 노드, PL/SQL 탭 하나로**: 스키마 브라우저의 「패키지 본문」·「타입 본문」 범주가 없어졌습니다. 「패키지」·「타입」 아래에 객체마다 노드 하나가 있고, 이름 옆에 「명세 정상/오류」·「본문 정상/오류/없음」 표시가 붙습니다.
  - PL/SQL 탭도 객체마다 하나입니다. `Ctrl+Shift+B`나 편집기 위쪽 「명세 | 본문」 단추로 같은 탭 안에서 오갑니다. 쪽마다 글·되돌리기·고침 표시(`*`)가 따로 있습니다.
  - 본문이 서버에 없으면 「본문 만들기」로 명세의 프로시저·함수마다 빈 구현을 둔 뼈대를 만듭니다.
  - 컴파일: `F5`는 보이는 쪽만, **`Shift+F5`(PL/SQL Developer 키맵은 `Shift+F8`)는 명세 다음 본문**을 컴파일합니다. 명세가 막히면 본문을 보내지 않습니다.
  - 컴파일 오류 창에 줄마다 「명세」·「본문」이 붙고, 고르면 그 쪽의 그 줄로 갑니다.
  - 편집기 왼쪽에 접을 수 있는 「구성원」 목록이 생겼습니다.
  - 저장해 둔 필터·유형 선택·즐겨찾기의 본문 유형은 명세 범주로 옮겨집니다.
- **복사 속도 개선**:
  - 한 테이블 안에서 읽기와 쓰기를 겹쳐 처리합니다(기본 켬). 측정에서 Oracle→Oracle이 약 6.7만 행/초에서 7.4~9.8만 행/초가 되었습니다.
  - LOB 열이 있는 테이블: 읽을 때 LOB 값을 행과 함께 미리 받고, 쓸 때는 LOB 열을 배열로 한꺼번에 넣습니다(측정에서 약 14배).
  - 테이블마다 읽기·변환·쓰기 시간과 초당 행 수를 로그에 남깁니다.
  - 속도 수치는 로컬 DB 한 대에서 잰 값입니다. 원격 DB에서는 다를 수 있습니다.
- **복사가 멈춘 이유 보기**: 읽기·쓰기가 오래 응답하지 않으면 테이블 행과 로그에 「배치 n 쓰는 중 · m분째 대기」처럼 표시합니다. 대상 대기가 30초를 넘으면 대기 원인(대기 이벤트, 막고 있는 세션의 사용자·프로그램·컴퓨터)을 보입니다. 이 원인 조회는 서버 조회 권한이 있을 때만 되고, 없으면 끝에 한 번 알립니다. 새 옵션 「테이블당 대기 한도」(기본 꺼짐)로 한도를 넘은 테이블을 취소하고 실패로 둔 채 다음 테이블로 갈 수 있습니다. 로그 파일은 줄마다 바로 기록합니다.
- **개발 접속은 실행 확인 생략**: 환경이 「개발」인 접속에서는 위험 명령(`DROP`, `TRUNCATE`, `PURGE`, `ALTER SYSTEM`, 세션 Kill)과 `WHERE` 없는 `UPDATE`/`DELETE`가 확인 창 없이 바로 실행됩니다. SQL 편집기 실행 로그에 「개발 접속이라 확인 생략」이 남습니다. 시험·운영 접속은 예전처럼 묻습니다. 읽기 전용 접속 등 거부는 개발 접속에서도 그대로 거부합니다. [알려진 한계](#알려진-한계)를 꼭 읽으세요.
- **데이터 복사 사용 편의**:
  - 복사 창 위쪽에 규칙·대상 처리·「없으면 만들기」의 전체 기본값이 생겼습니다. 테이블을 추가할 때 이 값으로 채워지고, 테이블별로 따로 바꾼 값이 우선합니다.
  - 규칙 목록에서 여러 줄을 골라(`Ctrl`·`Shift` 클릭, `Ctrl+A`) 한꺼번에 지울 수 있습니다. 확인 창은 한 번만 뜨고 다음 줄이 선택됩니다.
  - 복사 진행률이 실제로 쓴 행 수를 따릅니다. 마무리 단계는 「마무리 중」으로 표시합니다.
- **연결 관리자 직접 정렬**: 정렬 상자에서 「직접 정렬」을 고르면 같은 폴더 안에서 접속과 폴더를 끌어 순서를 정합니다. 순서는 `connections.json`에 저장됩니다. 접속 테스트가 성공하면 확인 중 나온 안내도 함께 보입니다.
- **탐색기에서 SQL 파일 끌어 놓기**: Windows 탐색기나 macOS Finder에서 SQL 파일을 끌어 놓으면 SQL 탭으로 열립니다.

## 고친 점

- PL/SQL 편집기에서 `Ctrl+C`(와 `Ctrl+X`, `Ctrl+Z`, `Ctrl+Y`)가 동작하지 않던 문제를 고쳤습니다. 이제 선택한 글을 복사할 수 있습니다.
- 이름을 다시 입력하는 확인 창에서 이름을 맞게 쳤는데도 `Enter`가 취소로 처리되던 문제를 고쳤습니다. 이제 글이 맞으면 `Enter`로 실행됩니다.
- 스키마 메타데이터 캐시를 새로 고칠 때 세션이 바쁘면 목록 갱신이 끝나 버리던 문제를 고쳤습니다. 백그라운드 갱신은 사용자 명령보다 앞서지 않습니다. 유형 폴더에서 `F5`를 누르면 그 유형만 다시 읽고, 캐시 초기화 명령이 생겼습니다.
- 복사 진행률이 마지막 배치 뒤에도 100% 아래에 머물던 문제를 고쳤습니다. 실제 건수가 예상보다 많으면 예상을 늘려 99%에 멈추지 않습니다.
- 「테이블 다시 만들기」에서 만들기가 실패해 휴지통에서 옛 테이블을 되살렸을 때, 함께 돌아온 트리거와 권한을 「되살리지 못함」으로 알리던 문제를 고쳤습니다. 이제 돌아오지 않은 FK만 알립니다.
- 환경 표시(칩, 머리 띠, 주 창 테두리)의 색이 접속의 라벨 색 규칙을 따릅니다(사용자가 정한 색이 먼저, 운영은 항상 빨강).
- 화면 문구와 메시지에서 DB 테이블을 「표」가 아닌 「테이블」로 부르도록 통일했습니다.

## 알려진 한계

- **개발 접속은 위험 명령을 확인 없이 바로 실행합니다.** `DROP`, `TRUNCATE`, `PURGE`, 세션 Kill, `WHERE` 없는 `DELETE`/`UPDATE`가 묻지 않고 실행됩니다. 환경을 따로 정하지 않은 접속은 기본값이 「개발」이라 똑같이 동작합니다. **운영·시험 DB 접속은 반드시 환경을 「운영」이나 「시험」으로 정하세요.**
- 「대상에 열 추가」로 더한 열은 복사가 실패해도 지워지지 않습니다. 결과 알림에 「대상에 열을 더했습니다」가 남으니 필요하면 `ALTER TABLE … DROP COLUMN`을 직접 실행하세요.
- 작업 공간 저장 파일(PL/SQL 작업 공간 JSON)의 형식 버전이 올라갔습니다(1 → 2). 이 버전에서 저장한 파일은 0.1.21 이하에서 읽기 전용으로 열립니다. 예전 파일은 읽을 때 명세 탭과 본문 탭을 한 탭으로 묶습니다.
- 복사 작업 파일에 「대상에 추가할 열」 칸이 생겼습니다. 이 칸은 예전 버전 앱이 무시하므로, 예전 앱으로 같은 작업을 실행하면 그 열을 빼고 복사합니다. 읽기·쓰기 겹치기와 대기 한도 같은 새 옵션도 예전 앱은 모르는 키로 보고 무시합니다.
- 복사 작업 파일에 전체 기본값과 테이블별로 따로 바꾼 표시가 들어가며(형식 버전 4 → 5), 예전 파일은 모든 테이블을 「따로 바꿈」으로 열어 현재 값을 유지합니다. 이 버전에서 저장한 파일은 0.1.21 이하에서 열 수 없습니다.
- 「대상에 테이블이 없으면 만들기」와 「대상에 열 추가」는 개발 접속을 대상으로 할 때만 쓸 수 있습니다.
- 동시 테이블 복사는 로컬 DB 한 대에서 잰 결과 기본(1)보다 나은 점이 없었습니다. 원격 DB에서는 다를 수 있어 기본은 1입니다.
