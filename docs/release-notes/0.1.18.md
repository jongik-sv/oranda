# Oranda 0.1.18

## 새 기능

- 데이터 복사에 **작업 변수**가 생겼습니다. 규칙 편집의 **변수** 칸에서 이름, 형식(문자·숫자·날짜), 값을 정하면 직접 조건과 추가 조건에서 `:이름`으로 씁니다. 변수는 작업에 함께 저장됩니다.
  - 값이 하나면 `ORDER_NO = :ORDER_NO`처럼 씁니다.
  - 값이 여러 개면 `COIL_NO IN (:COILS)`처럼 씁니다. 값은 줄바꿈이나 쉼표로 나누며, 엑셀 열을 그대로 붙여 넣을 수 있습니다. 한 변수에 1만 개까지 넣을 수 있고, 1000개를 넘어도 Oracle 11g에서 실행됩니다.
  - 원본 조회, 대상 지우기, 건수 비교에 같은 값이 쓰입니다. 정의하지 않은 `:이름`, 형식에 맞지 않는 값은 사전 점검 전에 알립니다.
- 데이터 복사 규칙 편집에서 테이블 이름을 적으면 원본의 테이블과 시노님을 이름으로 찾아 목록으로 보여 줍니다. `계정.`을 먼저 적으면 그 계정에서 찾습니다. 테이블 이름은 대소문자를 가리지 않습니다.

## 바뀐 점

- 데이터 복사 창의 작업 이름 칸이 단계 표시줄(규칙 편집 › 사전 점검 › 실행·검증) 위로 올라갔습니다. 테이블 입력 칸은 「테이블 규칙」 표 바로 위로 옮겼습니다.
- 「테이블 다시 만들기」처럼 테이블을 지우는 문장이 있을 때, 다시 입력할 대상 접속 이름을 안내 글에 그대로 보여 줍니다. 대소문자는 가리지 않고, 아직 맞지 않으면 「복사 실행」을 누를 수 없는 이유를 옆에 보여 줍니다.
- 데이터 복사 조건에 정의하지 않은 `:이름`을 쓰면 실행 중 ORA-01008로 실패하는 대신 사전 점검 전에 알립니다.

## 알려진 한계

- 작업 파일 형식이 바뀌었습니다(schemaVersion 3). 기존 작업은 처음 열 때 백업한 뒤 새 형식으로 다시 씁니다. 0.1.17 이하 버전에서는 새 형식 작업이 읽기 전용으로 열립니다.
- 작업 변수, 테이블 자동 완성, 바뀐 다시 입력 칸은 실제 앱으로 확인하지 않았습니다.
- 사전 점검의 SQL 미리 보기와 스크립트 저장에는 변수 값이 아니라 `:COILS_1` 같은 바인드 이름이 나옵니다.
