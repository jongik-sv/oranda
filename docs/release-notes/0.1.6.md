# Oranda 0.1.6

## 새 기능

- 스키마 브라우저에 DB 안의 Java 저장 객체가 「Java 소스」·「Java 클래스」·「Java 리소스」 폴더로 보입니다(이름은 `com/example/Util` 같은 긴 이름, INVALID 는 빨갛게). Java 소스는 객체 상세의 DDL 탭에 소스 글(`CREATE OR REPLACE AND COMPILE JAVA SOURCE …`)이 보이고, Java 클래스는 메서드·필드·구현 인터페이스·내부 클래스 표와 컴파일 오류를 보이며 그 클래스를 만든 소스가 같은 스키마에 있으면 「소스 열기」로 갑니다. 객체 검색은 유형에서 Java 를 고를 때 찾습니다. 읽기만 하며, 서버에 Java(JVM)가 없으면 폴더가 생기지 않습니다.
- Java 소스를 고쳐 DB 에 컴파일·적용할 수 있습니다. SQL 편집기에서 `CREATE [OR REPLACE] [AND COMPILE] JAVA SOURCE NAMED … AS <Java 코드>` 를 실행하면 Java 코드 안의 `;`·`{}`·문자열·주석에서 끊지 않고 `/` 단독 줄까지 한 문장으로 보내며(포맷은 그 글을 고치지 않습니다), 컴파일 오류는 PL/SQL 처럼 컴파일 오류 창에 보입니다. 객체 상세에는 「다시 컴파일」(Java 소스 = `ALTER JAVA SOURCE … COMPILE`, Java 클래스 = `ALTER JAVA CLASS … RESOLVE`, 확인한 뒤 실행하고 상태를 새로 읽음)과 Java 소스의 「편집기로 열기」(DDL 을 새 SQL 탭에, 실행은 직접)가 생겼고, 「INVALID 객체 일괄 컴파일」도 INVALID Java 소스·클래스를 함께 컴파일합니다. 서버에 JVM 이 없거나 읽기 전용 접속이면 단추가 막히고 이유가 보입니다. 클래스 파일·jar 올리기(loadjava)는 아직 없습니다.

## 고친 것

- 실행 중지 단추의 툴팁과 SQL 메뉴에 단축키가 「Ctrl+Cancel」 로 보이던 것을 「Ctrl+Break」 로 고쳤습니다. 누르는 키(Ctrl+Break)와 키맵 파일 표기(`Primary+Cancel`)는 그대로입니다.

## 바뀐 것

- 접속 관리자 「사용자 지정」 칸에 tnsnames.ora 에 있는 형식 그대로 여러 줄 접속 기술자를 넣을 수 있습니다. `별칭 = (DESCRIPTION = …)` 항목을 주석·들여쓰기째 붙여 넣어도 되고(이름이 비어 있으면 별칭을 이름으로 제안), 다시 열면 적은 모양 그대로 보입니다. 괄호 짝이 맞지 않으면 칸 아래에 알려 줍니다.
