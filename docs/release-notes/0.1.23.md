# Oranda 0.1.23

## 새 기능

- **되돌리기 지점**: 쓰기 문장(`UPDATE`, `DELETE`, `INSERT`)을 커밋한 뒤에도 실행 직전 데이터로 되돌릴 수 있도록 실행할 때 미리 기록을 남깁니다. 설정 > 「되돌리기」 탭에서 켜고 끌 수 있습니다.
  - **원복 스크립트**(운영 접속만): 실행한 문장을 거꾸로 되돌리는 SQL을 만듭니다. `UPDATE`는 이전 값으로 되돌리는 `UPDATE`, `DELETE`는 지운 행을 다시 넣는 `INSERT`, 한 행 `INSERT`는 넣은 행을 지우는 `DELETE`가 됩니다. 운영 접속의 실행 확인 창에서 문장마다 끌 수 있고, 예상 행 수가 상한(처음 값 100,000행)을 넘으면 만들지 않습니다.
  - **실행 직전 시점**(모든 접속): 쓰기 문장을 보내기 직전의 시점 번호(SCN)를 기록합니다. 원복 스크립트가 없는 실행은 이 시점과 지금 데이터를 비교해 되돌립니다.
  - 원복 스크립트에는 실제 데이터가 들어가므로 이 PC에 암호화해 보관하고, 보관 기간(처음 값 30일)이 지나면 지웁니다. 만들기에 실패해도 사용자 문장은 그대로 실행됩니다.
  - 되돌리기는 자동으로 실행하지 않습니다. 미리 본 뒤 커밋하지 않은 상태로 반영하고, 커밋이나 롤백은 직접 합니다. 그 뒤 다른 사람이 다시 바꾼 행은 덮어쓰지 않습니다. 되돌린 것도 다시 되돌릴 수 있습니다.
  - `TRUNCATE`, `ALTER TABLE … DROP COLUMN`, `DROP TABLE … PURGE` 앞에서는 테스트·운영 접속의 실행 확인 창이 먼저 백업 테이블을 만들지 권합니다. 고르면 `CREATE TABLE … AS SELECT`로 복사한 뒤 원래 문장을 보내고, 백업이 실패하면 원래 문장은 보내지 않습니다.
  - 커밋하기 전에 잠근 행 수와 실행한 행 수가 다른 문장이 있으면 알려 줍니다.
- **변경 일지에서 커밋 묶음 보기**: 도구 > 변경 일지에 커밋 한 번에 묶인 문장들이 시간 순서로 나옵니다. 묶음마다 확정·불완전·무효·만들지 않음·확인 필요 상태를 보입니다.
  - 고른 묶음의 원복 스크립트를 새 탭에서 열고, 「원복 실행 (커밋 안 함)」으로 실행할 수 있습니다. 운영 접속에서는 한 번만 묻고, 끝나면 되돌린 행·0행·충돌·오류 수를 요약합니다.
  - 아래 칸에 실행한 문장이 바인드 변수를 값으로 바꾼 모습으로 나오고, 원복 스크립트를 미리 볼 수 있습니다. 보여 주기만 바꾼 글이고 실행한 문장은 그대로입니다. 비밀 값은 가립니다.
- **「이 실행 전과 비교」**: 원복 스크립트가 없는 실행(개발·테스트 접속, 상한을 넘은 실행, 대상이 아닌 문장)은 기록한 실행 직전 시점과 지금 데이터를 비교해 되돌립니다. 바뀐 행, 그 뒤 다른 사람이 다시 바꾼 행(충돌), 만들어질 `DML`을 보여 주고, 새 편집기로 열거나 커밋 없이 반영할 수 있습니다.
- **플래시백 결과에서 「이 행 상태로 되돌리기」**: `VERSIONS BETWEEN`, `AS OF` 같은 플래시백 조회 결과에서 행을 골라 그 모습으로 되돌릴 수 있습니다. 지금 행이 있으면 `UPDATE`, 없으면 `INSERT`, 같으면 아무것도 하지 않습니다. 반영 전에 미리 보고, 커밋은 직접 합니다.
- **이력 결과에서 바뀐 칸 표시**: 한 테이블의 `VERSIONS BETWEEN` 결과(행 변경 이력 조회나 직접 쓴 조회)에서 같은 키의 이전 버전과 값이 달라진 칸의 배경색이 다르게 칠해집니다.
- **여러 표의 열 폭 조정**: 변경 일지, 바인드 변수, 잠금 트리, 대기 이벤트, 튜닝 도우미, 컴파일 오류, 실행 계획 비교, DDL 대상, 객체 검색 같은 표의 머리글 오른쪽 경계를 끌어 열 폭을 바꿉니다. 경계를 두 번 누르거나 머리글 오른쪽 단추 메뉴의 「열 폭 처음으로」를 고르면 처음 폭으로 돌아갑니다. 바꾼 폭은 화면마다 저장됩니다.
- **작업 공간을 닫을 때 저장 확인**: SQL 작업 공간을 닫거나 탭을 모두 닫을 때 고친 탭마다 「저장 / 저장 안 함 / 취소」를 묻습니다. 취소하면 작업 공간이 그대로 남습니다. 앱을 끝낼 때는 예전처럼 묻지 않고 다음 시작에 복원합니다.
- **매뉴얼**: 데이터를 바꾼 뒤 되돌리기 안내 쪽이 새로 생겼습니다.

## 고친 점

- 운영 접속에서 그리드로 직접 고쳐 반영할 때 미리 보기 창과 실행 확인 창이 연달아 뜨던 것을 실행 확인 창 한 번으로 줄였습니다. 이 창에 모든 문장과 바인드 값, 커밋 안내가 함께 보이고, 한 번 답하면 같은 반영의 나머지 문장에도 적용됩니다. 취소하면 아무것도 실행하지 않고 고친 내용을 그대로 둡니다. 개발 등 다른 접속은 미리 보기 창만 나옵니다.
- 그리드 편집 도구 막대의 행 추가·복제·삭제 아이콘이 테이블 전체가 아니라 행 작업으로 읽히도록 바꿨습니다.
- 변경 일지의 「원복 스크립트 열기」가 항상 실패하던 문제를 고쳤습니다.
- 변경 추적이 `undo_retention`보다 긴 최근 기간 때문에 `ORA-30052`로 실패하던 문제를 고쳤습니다. 읽을 수 있으면 기간을 `undo_retention`의 90%로 줄이고 안내를 남깁니다.
- 앱을 처음 켤 때 내부 저장소(`oranda.db`)를 준비하는 과정이 겹쳐 가끔 시작에 실패하던 문제를 고쳤습니다.
- 시점 비교, 행 되돌리기, 변경 일지 비교가 Oracle 접속에서 「이 DBMS는 시점 비교를 쓸 수 없습니다」로 막히던 문제를 고쳤습니다.
- 도구 창을 켜고 끌 때 화면 전체가 다시 그려지며 깜빡이던 문제를 고쳤습니다. 이제 그 창만 움직입니다. 보기 메뉴의 체크 표시는 메뉴를 열 때마다 실제 배치를 따르므로, 뜬 창을 닫은 뒤에도 켜진 것으로 남지 않습니다.
- 핀으로 접어 둔 도구 창이 다시 시작하거나 배치를 바꾸면 사라지던 문제를 고쳤습니다. 핀으로 접은 창 그룹이 높이 0으로 저장되어, 다시 시작한 뒤 그 그룹에 켠 도구 창이 보이지 않던 문제도 고쳤습니다.
- 도구 창이 「문서로 도킹」되어 문서 탭 사이에 끼었다가 다시 시작하면 사라지던 문제를 고쳤습니다. 이제 도구 창은 문서로 도킹하지 않습니다.
- 데이터 복사에서 접속 이름(TNS 별칭)이나 프록시로 연 복사 세션이 「접속이 바뀌었다」로 잘못 판정되던 문제를 고쳤습니다.
- 데이터 복사 규칙 화면의 위쪽 기본값 막대가 규칙 패널 밑으로 들어가던 문제를 고쳤습니다.
