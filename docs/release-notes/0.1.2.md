# Oranda 0.1.2

## 새 기능: 같은 DB에 세션 여러 개

- 워크스페이스마다 자기 세션을 씁니다. 같은 DB를 연 워크스페이스 둘이 서로의 실행·트랜잭션에 막히지 않습니다. 세션은 그 워크스페이스에서 처음 실행할 때 열립니다.
- 설정 > 일반 「워크스페이스마다 새 세션」으로 끌 수 있습니다. 끄면 예전처럼 접속 하나에 세션 하나를 함께 씁니다.
- 접속 콤보에 세션 목록과 「새 세션」이 생겼습니다. 같은 DB에 세션을 최대 8개까지 열 수 있고, 비밀번호는 이미 연 접속의 것을 메모리에서만 다시 씁니다.
- 연 세션은 직접 닫을 때까지(「세션」 창의 「세션 닫기」 또는 접속 끊기) 열려 있습니다. 다른 세션으로 옮겨도 닫히지 않으므로 콤보에서 여러 세션을 오가며 고를 수 있습니다.
- 상태 줄에 지금 세션이 보입니다: 「워크스페이스 세션」, 「공유 세션 · 다른 워크스페이스 N개와 함께」, 「새 세션 · 첫 실행 때 연결」.
- 함께 쓰는 세션이 다른 워크스페이스에서 실행 중일 때 실행하면 안내 막대가 뜹니다. [새 세션에서 실행] 또는 [기다리기]를 고릅니다. 기다리는 쪽의 취소 단추는 남의 실행을 취소하지 않습니다.
- 「세션」 도구 창이 왼쪽에 생겼습니다. 세션이 2개 이상이면 나타나고, 세션마다 SID와 쓰는 워크스페이스 수가 보입니다. 우클릭으로 이 세션 쓰기, 커밋, 롤백, 세션 닫기를 할 수 있습니다.
- 커밋하지 않은 변경이 있는 세션을 닫거나 옮기면 먼저 묻습니다. 탭이 하나도 없는 작업 공간을 닫을 때도 묻습니다.
- 가져오기는 그 워크스페이스의 세션에 씁니다. 다른 워크스페이스의 커밋하지 않은 작업과 섞이지 않습니다.
- 도움말 > 새 기능(릴리스 노트)에서 설치된 버전의 릴리스 노트와 이전 버전 노트를 다시 볼 수 있습니다. 업데이트를 받은 뒤에도, 오프라인에서도 열립니다.

## 고친 것

- 처음 실행할 때 자기 세션을 여는 워크스페이스에서 접속 콤보와 상태 줄이 실제로 실행하지 않을 기본 세션을 보이던 문제를 고쳤습니다. 이제 「새 세션(첫 실행 때)」으로 보이고, 그때 기본 세션을 고르면 그 세션을 함께 씁니다. 「세션」 창은 지금 워크스페이스가 쓰는 세션에 「◀ 이 워크스페이스」를, 곧 쓸 세션에 「사용 예정」을 보이며, 세션 번호 「(n)」은 앞 세션을 닫아도 바뀌지 않습니다. 닫힌 접속 콤보에서 화살표·휠로 세션이 하나씩 바뀌지 않고(화살표는 목록을 펼칩니다), 여러 워크스페이스가 함께 쓰는 세션을 커밋·롤백하면 함께 확정되는 워크스페이스를 밝혀 먼저 묻습니다. 문서 영역을 나눈 화면에서 도구 창을 눌러도 마지막으로 보던 문서의 접속이 유지됩니다.
- 접속(기본 세션)을 닫거나 끊으면 그 접속을 쓰던 워크스페이스가 묻지 않고 같은 DB의 다른 세션(다른 워크스페이스가 남긴 커밋하지 않은 변경이 있을 수 있음)으로 옮겨 가던 문제를 고쳤습니다. 이제 그 워크스페이스는 「접속 안 됨」이 되어 다시 고릅니다. 끊긴 접속을 다시 열면 지금처럼 새 세션을 따릅니다. 툴바 「접속 끊기」는 그 DB의 세션을 모두 끊고(커밋하지 않은 세션마다 묻습니다), 끊긴 추가 세션은 저절로 닫혀 다시 고를 수 있습니다. 「새 세션에서 실행」을 두 번 눌러도 세션 하나·실행 한 번이고, 기본 세션에 커밋하지 않은 변경을 둔 채 워크스페이스를 닫으면 먼저 묻습니다.
- 같은 DB에 세션이 여럿일 때 쓰기 작업이 다른 워크스페이스의 트랜잭션에 섞이던 문제를 고쳤습니다. 결과를 만든 세션과 지금 탭의 세션이 다르면 그리드 반영을 멈추고 다시 조회하라고 알립니다. 이력 「다시 실행」은 지금 워크스페이스의 세션에서 돌고, 가져오기는 커밋하지 않은 변경이 있으면 먼저 묻고 실패하거나 취소해도 그 전의 변경은 남깁니다. 그리드 반영·가져오기·LOB 저장·이력 다시 실행·PL/SQL 실행 창이 도는 동안 그 세션은 「실행 중」으로 보이고, 세션을 닫을 때는 커밋하지 않은 변경을 되돌린 뒤 닫습니다.
- 접속 콤보나 「세션」 창에서 같은 DB의 다른 세션을 고르면 콤보가 빈 「접속 안 됨」으로 보이던 문제를 고쳤습니다. 이제 고른 세션이 콤보에 보입니다. 「세션」 창에서는 줄을 두 번 누르거나 Enter를 눌러도 지금 작업 공간(SQL·MyBatis)이 그 세션을 씁니다.
- SQL 탭이 줄에 다 들어가지 않으면 탭 줄 아래에 가로 스크롤 막대가 보입니다. 막대를 끌거나 양 끝 화살표로 앞뒤 탭으로 갑니다.
- 설정 > 결과 그리드 「한 번에 가져올 행」이 적용되지 않고 늘 500행씩 가져오던 문제를 고쳤습니다. 같은 화면의 「메모리 한도(MB)」와 「LOB 미리 읽기(바이트)」도 이제 적용됩니다. 바꾼 값은 다음 실행부터 쓰입니다.
- 설정 > 이력·캐시 「바인드 값 저장」을 켜도 이력에 바인드 값이 남지 않던 문제를 고쳤습니다. 비밀 값은 `***`로 가립니다.
- 설정 > 이력·캐시 「메타데이터 캐시 보관 일수」가 지난 캐시를 지우지 않던 문제를 고쳤습니다. 앱을 시작한 뒤와 값을 바꿀 때 정리합니다.
