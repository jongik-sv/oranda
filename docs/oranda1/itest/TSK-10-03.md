# TSK-10-03 스크립트 찾기·여러 행·결함 수정 통합테스트 결과서

이번 회차(scripts-find)의 기능·결함 Task 8개(TSK-10-01 스크립트 검색, 10-02 새 스크립트, 11-01 결과 격자 여러 행, 12-01 INVALID 검색, 12-02 실행 창, 12-03 내보내기 바인드, 12-04 접속 콤보, 13-01 DDL 대상 미리보기)와 12-05(시작 회귀)가 dev 에 들어온 뒤,
먼저 **전체 시험을 안정화**(불안정 시험의 원인을 찾아 고침)하고, 두 Oracle(26ai·11.2)에서 통합 시험을 돌리고, 미룬 시간을 재고, 화면을 Headless 로 떠서 확인했다.

## 범위와 규칙

- 실앱 실행·SendKeys 는 하지 않았다. 눈으로 봐야 하는 것은 아래 「실앱 눈 확인 목록(사람 몫)」 에 모았다.
- 제품 코드는 고치지 않았다. 고친 것은 모두 시험 파일이다(불안정 시험 6건의 원인 제거, 통합 시험 11g 확장 2건, 측정·흐름 시험 추가).
  이번 통합에서 찾은 제품 결함 2건(이번 회차 전부터 있던 것)은 「발견 결함」 에 적었다 — Task id 는 조정자가 정한다.
- 비밀번호는 컨테이너 환경 변수(`ORACLE_PASSWORD`)에서 환경 변수로만 넘겼고 출력·저장하지 않았다. 새 이미지는 받지 않았다.

## 발견 결함 (조정자 등록 대기)

둘 다 이번 회차 전 커밋 e4ad09c 에서도 같은 시험이 실패한다(`git archive e4ad09c` 로 따로 빌드해 확인) — 이번 회차가 만든 회귀가 아니다.

1. **F9(편집 모드로 실행)를 DUAL·공용 동의어(ALL_TABLES)에 누르면 예외.** `DeveloperFlowTests.S3_4`: `GridEditSession.PlanAsync` 가 소유자를 현재 사용자로 잡아 `GetTableAsync(ORA_IT_x.DUAL)` 을 부르고, 열이 없으면 `InvalidOperationException("테이블 또는 뷰를 찾을 수 없습니다")` 가 그대로 올라온다. 기대 = 「편집 불가」 안내 막대. 제안: 대상을 못 찾으면 편집 불가 계획(이유 문구)으로 돌려준다.
2. **결과 편집 「반영(커밋 안 함)」 뒤 세션이 미커밋으로 표시되지 않는다.** `DeveloperFlowTests.S3_1` 이 `rig.Session.HasPendingTransaction` 을 30 초 기다리다 실패. 실행 엔진 경로만 `DBMS_TRANSACTION.LOCAL_TRANSACTION_ID` 로 미커밋을 갱신하고(OracleExecutionService.TrackTransactionAsync) 행 편집 반영 경로는 갱신하지 않는 것으로 보인다 → 커밋·롤백 단추·탭 닫기 경고가 그 변경을 모를 수 있다.

## 실앱 눈 확인 목록(사람 몫)

레인 보고와 이번 확인에서 모은 것. Headless 로는 판단할 수 없는 움직임·실제 글꼴·OS 창 동작이다.

1. 스크립트 창: 내용 검색 결과 줄을 두 번 눌러 열면 그 줄로 커서가 간다(TSK-10-01).
2. 스크립트 창: 라이트 테마에서 「내용」 토글이 켜짐/꺼짐으로 구분되어 보인다.
3. 결과 격자: 편집 모드가 꺼진 결과에서 행 삭제(Ctrl+Delete)를 누를 때 자동 편집 모드 전환이 깜박이지 않는다(TSK-11-01).
4. 인자 없는 프로시저를 스키마 브라우저·편집기 두 경로로 열면 실행 창이 「인자가 없습니다」 와 호출 블록을 보인다(TSK-12-02, v0.1.0 설치본에서 빈 화면이던 것).
5. 실행 창 배경·테마: 다크·라이트에서 창 바탕과 표 머리가 테마를 따른다.
6. DDL 일괄 추출 대상 탭: 머리글 체크(모두 켬/끔), Space 로 줄 체크, F5 새로 고침(TSK-13-01).
7. 접속 콤보 4가지: SQL 탭·PL/SQL 문서·미커밋 탭(확인 창)·실행 중 탭에서 콤보로 바꾼 뒤 다음 실행 DB 와 콤보·상태 줄이 맞는다(TSK-12-04). 두 접속(26ai·11.2)으로 본다.
