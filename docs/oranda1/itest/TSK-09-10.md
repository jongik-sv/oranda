# TSK-09-10 사용 복잡도 통합테스트 결과서

WP-09(사용 복잡도 줄이기, PRD 13·TRD 11·D-015~D-023)가 모두 dev 에 들어간 뒤, **실제 FeatureGate** 로 앱 전체를 조립해 Role 구성마다 메뉴 너비를 다시 세고(TRD 11.11 의 7개 숫자), 새 설치부터 「모든 기능」 으로 되돌리기까지의 주 흐름을 끝까지 돌렸다.
비교 기준은 조사 `docs/oranda1/research/usage-complexity.md` 1장(기준 커밋 413a33d)이다. 같은 측정 도우미를 413a33d 스냅숏에도 넣어 「같은 기준 재계산 값」 을 얻었고, 그 값이 조사 1.1 표의 숫자(메뉴 항목 274/209/…, 툴바, 그리드, SQL 탭 보이는 항목, 도구 창)와 모두 같은 것을 확인했다.

## 범위와 규칙

- 실앱 실행·SendKeys 는 하지 않았다. 화면 확인은 Headless 까지이고, 눈으로 봐야 하는 것은 아래 「실앱 눈 확인 목록(사람 몫)」 에 이번 회차 전체를 모았다.
- 제품 코드는 고치지 않았다. 고친 것은 빠진 문구 1건(`docs/design/commands.md` 의 `runScenario` 기본 키)과 시험 파일 1건(`BottomPanelTableTests` 메시지 로그 격리)뿐이다. 발견한 제품 결함은 WP-09 defect Task(TSK-09-11·TSK-09-12)로 등록했다.
- 비밀번호는 컨테이너 설정에서 환경 변수로만 넘겼고 출력·저장하지 않았다. 새 컨테이너·이미지는 만들지 않았다.

## 숫자 비교 (TRD 11.11)

구성: 모든 기능(`allFeatures: true`), 고르지 않음(settings.json 없음 = D-013 R1), R1~R6, R1+R4, Role 0개(`roles: []`).
「조사」 는 조사 1.1 표(413a33d). 「재계산」 은 같은 도우미로 413a33d 를 센 값이고, 표기와 다를 때만 적었다(조사의 「15개 넘는 메뉴」 는 항목 총수 기준이라 한 단계 줄 수 기준과 다르다, PRD 13.3).
「지금」 은 게시본과 같은 모양(개발 빌드 전용 「확장 시험」 도구 창을 뺀 값)이다. Debug 빌드에서는 보기 > 도구 창 ▸ 에 한 줄이 더 있어 메뉴 항목 총수가 1 크고, 모든 기능의 「15줄 넘는 메뉴」 에 `보기/도구 창=16` 이 하나 더 잡힌다(`Dev_build_adds_only_the_extension_test_toggle`). 조사 1.1 주5 도 이 창을 뺐다.

- 이번 전체 실행(App.Tests 3,444건) 결과: 4개 Headless 시험이 모두 통과했고 걸린 시간이 12.5 s·13.8 s·20.8 s·28.8 s 로 나왔다(같은 실행의 다른 Headless 시험도 30 s 대가 많다). 같은 시험을 따로 돌리면 13건 전체가 10 s 안(시작 포함)에 끝난다.
- 원인: `HeadlessHost` 는 프로세스에 Avalonia UI 스레드 하나(`AvaloniaTestIsolationLevel.PerAssembly`)를 두고 모든 Headless 시험 본문을 그 스레드의 대기열로 보낸다. 대기열은 본문을 하나씩 끝까지 돌린다 — 실험으로 확인: 한 시험이 UI 배율 1.5 로 바꾸고 8초 기다리는 동안 4초 뒤 들어간 다른 Headless 시험은 그 본문이 끝난 뒤에야 돌았고(9 s), 배율 1.0 행 높이(24)를 보았다. 그래서 xunit 이 적는 「시험 시간」 에 앞 시험들을 기다린 시간이 들어가고, 부하 때 그 대기열이 길어져 18~57 s 가 된다. 본문이 섞여 돌지 않으므로 앞 시험의 배율·테마 변경이 끼어드는 경합은 아니다.
- 이번 회차에 이 시험의 실패 기록·메시지는 받은 것이 없고 이 PC 의 두 번 전체 실행에서도 실패하지 않았다. 남는 공유 상태는 하나였다: `new MessagesViewModel()` 이 버스 없이 프로세스 공용 대체 로그(`ExecutionLog.For(null)`)를 쓴다. 다른 시험이 그 로그에 줄을 남기면 「2줄」 단정이 깨질 수 있어, 그 시험에만 자기 버스를 주도록 고쳤다(시험 파일 1줄 + 주석). 시간 숫자는 그대로 크게 나오는 것이 정상이다.
