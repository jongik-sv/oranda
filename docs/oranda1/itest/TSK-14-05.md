# TSK-14-05 같은 DB 여러 세션 통합 확인 결과서

PRD 16.3 수락 기준을 `Category=Integration` 시험과 Headless 화면 시험으로 확인한다. 이 문서는 뼈대이며, Oracle 실행 수치는 아직 비어 있다.

## 상태 (2026-10-26)

- 시험 코드: 작성했고 빌드(`-warnaserror`)는 통과했다. Oracle 에 붙는 통합 시험은 **맥에서 실행하지 않았다**.
- 이유: 맥의 `oracle-26ai-free`(1521)는 dmes-standard 와 같이 쓰는 DMES DB 라 DDL·DML·GRANT 가 금지이고, 통합 픽스처(`ItDb`)가 `CREATE USER`·`GRANT` 를 한다. 컨테이너 환경 변수에서 비밀번호를 꺼내 쓰는 것도 금지다. 시험 전용 컨테이너(`oranda-ft`) 기동은 사용자 결정 대기다.
- 아래 수치 칸은 「맥 미실행(공유 DB 쓰기 금지), win144 확인 몫」 이다. 컨테이너가 정해지면 같은 명령으로 채운다.
- 11.2(win144 XE): 맥은 11g 를 돌리지 않는다. 전부 **win144 확인 몫**이다.

## 실행 명령 (컨테이너가 정해진 뒤)

```
dotnet test tests/Oranda.App.Tests -c Debug --filter "Category=Integration&FullyQualifiedName~WorkspaceSessionFlowTests"
```

11.2 는 `dbms_session.sleep` 이 없고 `dbms_lock` 권한을 SYSTEM 이 줄 수 없어 `dbms_utility.get_time` 바쁜 반복으로 5초를 만든다(`SleepSql`, 서비스 이름 XE 일 때).

## 화면 흐름 확인 (Oracle 없이 Headless 로 한 것)

- 「세션」 도구 창(TSK-14-04): 목록·우클릭 4명령·기본 숨김·세션 2개 이상에서 보임. 시험 `tests/Oranda.App.Tests/Features/Sessions/*`(24개). 라이트·다크 PNG 는 `ORANDA_RENDER_DIR` 로 저장소 밖에 만든다(커밋하지 않음).
- 콤보·상태 줄·안내 막대·설정 확인란(TSK-14-03): dev-jji-mac d341080 에 머지됐다. 그 화면 시험은 14-03 소유(ms-core)이며, 이 문서에는 실앱 확인 목록만 올린다.

## 실앱 확인 목록 (사람 몫, GUI 자동화 금지)

1. 접속 하나로 워크스페이스 둘을 열고 각각 실행한 뒤, 왼쪽 「세션」 탭이 둘째 세션을 연 순간 나타나는지(스키마 브라우저 탭을 가로채지 않는지).
2. 「세션」 탭 항목의 SID 가 세션 모니터의 같은 세션 SID 와 같은지.
3. 한쪽이 오래 도는 동안(5초 이상) 다른 워크스페이스에서 질의가 바로 도는지, 상태 줄·점 색(주황 = 실행 중)이 맞는지.
4. 항목 우클릭: 이 세션 쓰기(미커밋 확인 창), 커밋, 롤백, 세션 닫기(미커밋 확인 한 번, 쓰던 워크스페이스가 「접속 안 됨」 으로 바뀌는지).
5. 「세션」 탭을 사용자가 닫은 뒤 세션을 더 열어도 다시 열리지 않는지(앱을 다시 켜기 전까지).
6. 공유 세션 실행 중 막힌 워크스페이스의 안내 막대(TSK-14-03).
7. 11.2: 위 1~4 를 11.2 접속에서(win144).
