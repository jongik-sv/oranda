# PRD - Oranda MyBatis 작업 공간

> version: 1.0
> date: 2026-10-23
> 상위 제품: Oranda(Orange 대체 Oracle 클라이언트). 상위 PRD = `docs/PRD.md` — 이 폴더의 문서는 상위 PRD 를 고치지 않고 이 기능만 다룬다.
> 화면 시안: https://claude.ai/artifact/JeoMQCGye8RCEqGmGVPKEa (시안 A 채택, `decisions.md` D-001). 내려받은 사본 = `docs/oranda1/mockups/`

## 1. 배경과 목표

지금 Oranda 는 MyBatis 매퍼(.xml)를 읽기만 한다. 열 때 동적 태그를 「실행할 수 있는 모양」으로 줄여 SQL 탭에 넣고, 저장은 Markdown 작업 공간으로만 한다. 그래서 다음을 할 수 없다.

- 매퍼를 고쳐 다시 매퍼로 저장하기
- `<if>`·`<choose>`·`<foreach>` 가 실제 값에 따라 어떤 SQL 이 되는지 값을 넣어 보고 실행하기
- 일반 SQL(작업 공간 탭)을 매퍼 문장으로 바꾸기

목표: 개발자가 매퍼를 IDE 로 옮기지 않고 Oranda 안에서 **편집 → 값으로 시험 → 저장** 을 끝낸다. 일반 작업 공간도 MyBatis 작업 공간으로 바꿀 수 있다.

## 2. 범위

범위 안:
- MyBatis 3 매퍼 xml(루트 `<mapper>`)의 select·insert·update·delete 문장, sql 조각
- 동적 태그 if, choose/when/otherwise, where, set, trim, foreach, include, bind
- Oracle 실행(기존 Oranda 실행 경로)

범위 밖:
- resultMap·cache·parameterMap 편집(목록에만 보인다)
- 어노테이션 매퍼(@Select 등), MyBatis-Plus 의 자동 문장, iBatis 2 형식
- Java 코드(매퍼 인터페이스)와의 연결, 실행 결과를 Java 객체로 매핑하기

## 3. 사용자와 주요 흐름

사용자 = MyBatis 를 쓰는 업무 시스템의 개발자.

1. 매퍼 열기: 매퍼 .xml 을 연다 → 문서 탭 하나 = 매퍼 하나, 문장 하나 = 탭 하나.
2. 편집: 문장 탭에서 동적 태그가 남은 원문을 고친다.
3. 시험: 오른쪽 창에서 파라미터 값 묶음(시나리오)을 고른다 → 이번 값으로 빠지는 부분이 흐려지고 펼친 SQL 이 보인다 → 실행한다.
4. 검사: 조건을 켜고 끄는 조합을 펼쳐 문법이 깨지는 조합을 찾고 자동 고침을 쓴다.
5. 저장: 바뀐 부분을 확인하고 바뀐 문장만 매퍼에 쓴다.
6. 바꾸기: 일반 작업 공간을 MyBatis 작업 공간으로 바꾼다.
7. 로그: MyBatis 로그를 붙여 넣으면 그 문장을 찾아 열고 로그 값을 시나리오로 저장한다.

## 4. 기능 요구사항

| ID | 요구사항 | 우선 |
|----|----------|------|
| MB-01 | **매퍼 원문 모델**: 매퍼를 읽어 요소마다 원문 범위(요소 전체·안쪽 본문)·종류·id·속성을 가진다. 주석·CDATA·엔티티·공백·인코딩(xml 선언·BOM)·줄 끝은 원문 그대로 둔다. 문장 본문 바꾸기·새 문장 추가·지우기·id 바꾸기는 원문 조각 바꾸기로 하고 바꾸지 않은 부분은 바이트까지 같다 | P0 |
| MB-02 | **동적 SQL 계산**: 문장 원문과 파라미터 값으로 동적 태그를 계산해 펼친 SQL·바인드 목록·치환 목록·켜진/꺼진 블록 범위를 낸다. `#{x}` → 바인드 `:x`, `${x}` → 값 글자. test 식은 OGNL 부분집합(비교·논리·null·리터럴·속성·size/isEmpty/length/trim/equals)이고, 계산 못 하는 식은 위치와 함께 알리며 사용자가 켬·끔을 고를 수 있다 | P0 |
| MB-03 | **MyBatis 작업 공간 화면**: .xml 을 열면 MyBatis 작업 공간이 된다. 왼쪽 「문장」 도구 창(종류별 묶음, 수정·새 문장·조합 오류 표시, 새 문장·id 바꾸기·지우기), 가운데 문장 원문 탭(종류 표시, 수정 점), XML·파라미터·SQL 강조. 「문장」·「파라미터 · 시나리오」 도구 창은 MyBatis 문서에서만 보인다 | P0 |
| MB-04 | **파라미터 · 시나리오**: 문장에서 파라미터(`#{}`·`${}`·test 식·foreach·bind)를 찾아 이름·쓰인 곳·타입·값·null 로 보인다. 값 묶음을 시나리오로 저장·고르기·복제·지운다. 시나리오는 앱 데이터에 매퍼 경로 + namespace + 문장 id 기준으로 둔다(매퍼 폴더에 파일을 만들지 않는다). 비밀 이름(pass·pwd·secret·token) 값은 저장하지 않는다 | P0 |
| MB-05 | **펼친 SQL·실행**: 이번 값으로 빠지는 블록을 흐리게, if·when 머리 줄에 켬·끔 표시. 아래 「펼친 SQL」 쪽에 펼친 문장과 바인드·치환 목록. 「시나리오 값으로 실행」은 기존 실행 경로(정책 관문·탭 접속)로 실행한다. 실행 계획, 펼친 SQL 복사. `${}` 가 있으면 운영 접속에서 실행 전 확인한다 | P0 |
| MB-06 | **매퍼에 저장**: 바뀐 문장만 쓴다. 쓰기 전 「바뀌는 부분」 창(문장 체크, diff, 검사: XML 형식·id 겹침·밖에서 바뀜). 파일 감시: 밖에서 바뀌면 안 고친 문장은 반영하고 양쪽이 고친 문장만 고르게 한다. 지워짐·읽기 전용·쓰기 오류 처리. 저장 안 한 문장이 있는 매퍼를 닫으면 묻는다 | P0 |
| MB-07 | **조합 검사**: 조건 켬·끔 조합을 펼쳐(조건 8개 이하 전부, 넘으면 하나씩 끄기 + 모두 켬 + 모두 끔) Oranda 구문 분석으로 검사하고, 고르면 실행 계획으로도 확인한다(문장은 실행하지 않는다). 자동 고침: SET 뒤 if → `<set>`, WHERE 뒤 if → `<where>` | P1 |
| MB-08 | **일반 작업 공간 → MyBatis**: 대화 상자에서 대상(새 매퍼 / 기존 매퍼에 추가), namespace, 탭별 문장 id·종류, 바꾸는 방법(`:x` → `#{x}`, `&x` → `${x}`, jdbcType, `<where><if>` 감싸기, CDATA)을 고르고 미리 본다. 탭 바인드 값은 첫 시나리오가 된다. 원래 작업 공간 파일은 그대로 둔다 | P1 |
| MB-09 | **로그로 문장 찾기**: MyBatis 문서에서 로그를 붙여 넣으면 logger 이름(namespace.id)으로 문장을 찾아 열고 Parameters 값을 파라미터에 맞춰 새 시나리오로 저장한다 | P1 |
| MB-10 | **매퍼 폴더 열기**: 폴더 아래 매퍼를 폴더 > 파일 > 문장 트리로 보이고, 다른 파일의 sql 조각 include 를 펼치며, namespace.id 로 문장을 찾는다 | P2 |

## 6. 비기능 요구사항 (NFR)

- 성능: 문장 3,000줄·매퍼 1MB 를 열어 문장 목록이 보일 때까지 1 s 이하. 값·원문을 고친 뒤 펼친 SQL 다시 계산은 디바운스 300 ms 뒤 50 ms 이하. 조합 검사 조합 256개 구문 분석 3 s 이하(백그라운드, 취소 가능)
- 정확성: 바꾸지 않은 문장의 바이트 보존 100%. 펼친 SQL 은 MyBatis 3.5 실제 출력과 공백 정규화 후 같다
- 보안: test 식 계산은 정해진 연산·메서드만 쓴다(임의 코드 실행 없음). DTD·외부 엔티티를 읽지 않는다. 비밀 이름 파라미터 값은 저장하지 않는다. 모든 실행은 정책 관문을 거친다
- 호환: Windows·macOS, Oracle 11.2 이상(상위 PRD 와 같음)

## 7. 제약 사항

- 상위 문서(`docs/PRD.md`·`docs/TRD.md`·`docs/wbs.md`·`docs/decisions.md`)는 고치지 않는다. 이 기능의 문서는 `docs/oranda1/` 에 둔다
- 스택은 Oranda 그대로: .NET 10, Avalonia 12, MVVM(CommunityToolkit.Mvvm), ODP.NET Core. Oranda.Core·Oranda.Language 는 Avalonia·ODP.NET 을 참조하지 않는다
- 매퍼 쓰기에서 XDocument 직렬화로 파일 전체를 다시 쓰지 않는다
- 새 도구 창·명령은 같은 Task 에서 진입점(메뉴·단축키·도구 창 등록)까지 끝낸다
- 지금의 `WorkspaceFiles.ReadMyBatis`(읽기 전용 펼치기)는 MB-02 계산기로 옮기고 중복 코드를 남기지 않는다

## 8. 수락 기준

- 표본 매퍼를 열어 아무것도 바꾸지 않고 저장하면 파일이 바이트까지 같다
- 문장 2개를 고쳐 저장하면 git diff 에 그 문장 안쪽 줄만 나온다
- 시안의 selectEmpList 시나리오 4개(이름 검색·부서 목록·전체 조건·조건 없음)에서 흐린 줄·펼친 SQL·바인드가 시안과 같고, 실행 결과가 같은 SQL 을 일반 SQL 탭에서 실행한 결과와 같다
- 시안의 updateEmpSal 에서 조합 검사가 오류 2개를 내고, `<set>` 자동 고침 뒤 4개 조합이 모두 통과한다
- IDE 에서 다른 문장을 고쳐 저장한 뒤 Oranda 에서 저장해도 IDE 의 고침이 남는다
- 탭 4개 일반 작업 공간을 바꿔 연 매퍼에서 각 문장을 첫 시나리오로 실행하면 원래 탭 결과와 같다

## 11. 튜닝 메뉴와 쿼리 튜닝 (2026-10-24 추가)

배경: Oranda 는 예상·실제 계획, 계획 비교, Top SQL, 바인드 캡처, 문장별 세션 통계, 세션 트레이스 켜기를 이미 갖췄다. 다른 도구(Toad SQL Optimizer·TKProf, SQL Developer Autotrace·Tune SQL·Monitor SQL, PL/SQL Developer, OEM 어드바이저·SPM)와 비교해 빈 곳을 채운다. 원칙: 팩 없는 읽기 전용. DB 에 쓰는 일은 스크립트 문안까지만 만들고 실행은 사용자 몫. 팩이 필요한 기능은 라이선스 관문(SAFE-07) 뒤.

| ID | 요구사항 | 우선순위 |

## 12. Role 기반 메뉴·기능 구성 (2026-10-25 추가)

배경: 기능이 늘어 주 메뉴 11개·명령 281개·도구 창 33개·상태 칸 10개·시작 작업 14개가 모든 사용자에게 같이 보이고 같이 돈다. 조회만 하는 사람에게 튜닝·DBA·MyBatis 메뉴가 보이고, MyBatis 를 쓰지 않는 사람의 PC 에서도 매퍼 감시·작업 공간 배선이 시작 때 돈다. 사전 조사 = `docs/oranda1/research/role-features.md`(기준 커밋 a507d81). 결정 = `decisions.md` D-002~D-012.

### 12.4 수락 기준

- 설정 파일에 `features` 가 없는 사용자는 명령·도구 창·상태 칸·시작 작업 수가 지금(a507d81)과 같다.
- R6 만 고르면 주 메뉴에 「모니터」「튜닝」 최상위 메뉴가 없고, 23ai·11g 컨테이너에서 `UPDATE`·`CREATE`·익명 PL/SQL 블록이 거부되며 `SELECT` 는 실행된다. R6 와 R1 을 함께 고르면 거부되지 않는다.
- R1 만 고르면 MyBatis 시작 작업 4개·MyBatis 상태 칸·PL/SQL 작업 공간 복원이 돌지 않고, 블로커 칸은 남는다.
- 설정 창에서 R4 를 더하면 창을 닫는 즉시 「튜닝」 메뉴가 나타나고, MyBatis 를 켜면 「재시작하면 적용됩니다」가 보인다.
- PL/SQL 을 끈 상태에서 스키마 브라우저의 패키지를 열면 읽기 전용 SQL 탭이 열린다. MyBatis 를 끈 상태에서 매퍼를 열면 문장마다 SQL 탭이 생기고 매퍼 파일은 바뀌지 않는다.
- 성능 비교 결과서(`docs/oranda1/itest/TSK-07-07.md`)가 있고 어셈블리 분리 판단 기준(D-003)에 따른 결론이 적혀 있다.
