2차 시안 — 파티션 · 저장 속성/LOB · 형식 변경 자동 변환

셋 다 제 제안입니다. 첫판과 같은 규칙(✎ 편집 → 고치기 → 아래 DDL, ✖ 막음 / ⚠ 알림, 반영 묶음 연동)을 따릅니다.

⑥ 파티션 페이지

지금 읽기 전용 「파티션」 페이지에 편집을 켭니다. 위에서 방식과 키 열을 고르고, 표에서 파티션 줄을 고칩니다. 「경계 채우기…」는 「2026-01 부터 매월 12개」처럼 줄을 한꺼번에 만듭니다.

  • 나누기(SPLIT)·합치기(MERGE)는 줄을 고르고 단추로, 인덱스는 늘 UPDATE INDEXES 를 붙여 UNUSABLE 이 안 되게 합니다.
  • 하위 파티션(복합 파티션)은 보여 주기만 하고 편집은 다음으로 미루는 것을 제안합니다.

  • MOVE 가 필요한 변경(테이블스페이스·압축·LOB 저장)은 한 문장으로 모으고, 인덱스는 UPDATE INDEXES 로 살립니다. ONLINE 이 안 되는 곳은 MOVE 뒤 ALTER INDEX … REBUILD 를 덧붙입니다.
  • 새 테이블에서는 이 페이지 값이 CREATE TABLE 의 저장 절이 됩니다. BASICFILE → SECUREFILE 바꾸기는 MOVE 로 합니다.

⑧ 열 형식 변경 자동 변환

데이터가 있는 열의 형식을 바꾸면(예: VARCHAR2 → NUMBER) 첫판은 ✖ 로 막습니다. 2차는 그 ✖ 옆에 「변환해서 바꾸기…」를 두고, 아래 창에서 방법과 변환식을 고릅니다.

변환해서 바꾸기 — SAMPLE.ORDERS.ORDER_NO VARCHAR2(20) → NUMBER(12)개발
방법열 바꿔치기테이블 다시 만들기열 바꿔치기: 빠름, 열이 맨 뒤로 감 · 다시 만들기: 열 순서 유지, 오래 걸림
변환식TO_NUMBER(ORDER_NO)✖ 변환 안 되는 행 3건그 행 보기
1ALTER TABLE … ADD (ORDER_NO$N NUMBER(12))
2UPDATE … SET ORDER_NO$N = TO_NUMBER(ORDER_NO) ⚠ DML · 1,240,000행 · 커밋은 이 단계 끝에 한 번
3ALTER TABLE … DROP COLUMN ORDER_NO ⚠ 되돌릴 수 없음
4ALTER TABLE … RENAME COLUMN ORDER_NO$N TO ORDER_NO
5NOT NULL · 기본값 · 주석 · 이 열의 제약/인덱스 다시 만들기 (4문장)
6이 열을 쓰는 뷰·PL/SQL 다시 컴파일 (2개)
✖ 가 없어질 때까지 실행 막음 · 중간에 실패하면 끝난 단계까지 표시하고 「남은 단계 스크립트」를 줍니다묶음에 넣기스크립트 저장…실행
  • 변환 검사는 실행 전에 VALIDATE_CONVERSION(Oracle 12.2+) 또는 행 단위 시험 질의로 「변환 안 되는 행」을 셉니다. 1건이라도 있으면 ✖.
  • 「테이블 다시 만들기」는 이미 있는 열 순서 바꾸기의 다시 만들기 스크립트에 변환식을 끼워 넣어 재사용합니다.
  • 걸리는 점: 2단계 UPDATE 는 DML 입니다. 의뢰 스크립트는 지금 「DDL 만」이라, 이 변환을 묶음·의뢰에 넣으면 DML 이 섞입니다.

확인하고 싶은 것

  • ⑥ 하위 파티션 편집은 미루고, 파티션 지우기·비우기(데이터 사라짐)는 ⚠ 와 함께 편집기에서 허용 — 괜찮나요?
  • ⑦ 저장 속성과 LOB 을 「저장」 한 페이지에 두는 것, 괜찮나요?
  • ⑧ 자동 변환은 UPDATE(DML)가 들어갑니다. 이 변환만 예외로 의뢰 스크립트에 DML 을 넣을까요, 아니면 이 변환은 묶음·의뢰에서 빼고 개발·테스트 실행 전용으로 둘까요? (제 추천: 예외로 넣되 스크립트 안에 「-- DML 포함」 머리 표시)
