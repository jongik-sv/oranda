# AI 튜닝과 대화

설정 > AI 모델 에서 쓸 모델을 고른다. 「선택 안 함」 이면 AI 기능을 쓰지 않는다. 「직접 선택」 에서는 아래 중 하나를 고른다.

| 종류 | 필요한 것 |
|---|---|
| Claude Code | 이 PC 에 로그인된 `claude`. 키·주소가 필요 없다 |
| 내 프로필 (Anthropic 형식: Anthropic, Z.AI, 직접 입력) | `claude` 실행 파일, 주소, 모델, 필요하면 API 키 |
| 내 프로필 (OpenAI 형식: OpenAI, Google Gemini, Ollama, LM Studio, 직접 입력) | 주소, 모델, 필요하면 API 키. `claude` 는 필요 없다 |

드롭다운에서 Codex CLI 와 Antigravity CLI 도 고를 수 있다. PC 에 설치하고 로그인해 두어야 한다.

- 실제 로그인으로 끝까지 시험하지 못한 상태로 켠 기능이다. Windows 의 잠금(토큰·파일 권한)도 확인하지 못했다.
- 운영 접속에서도 쓸 수 있다. 접속의 AI 허용 수준과 운영 리터럴 가림은 다른 모델과 같게 적용되며, 가린 뒤의 대화 내용도 CLI 폴더에 남는다.
- 시스템 CLI 의 한 차례 실행은 최대 6시간이다. 벤치마크 제한이 0 이어도 이 제한은 적용된다.
- 대화는 CLI 자기 폴더(`~/.codex`, `~/.gemini/antigravity-cli`)에 남으며 Oranda 가 지울 수 없다.
- Antigravity 는 전역 MCP 설정에 서버가 있거나 사이드카 설정이 있으면 실행하지 않는다. 이미지는 Codex 만 보낼 수 있다.

## 프로필 만들기

1. 설정 > AI 모델 > 「프로필 관리」 (또는 드롭다운의 「새 프로필 만들기」).
2. 프리셋 카드를 고르고 주소·API 키·모델·최대 입력/출력 토큰·프로필 이름을 넣는다. 「모델 새로고침」 으로 서버의 모델 목록을 받는다.
3. 「연결 테스트」 로 확인한 뒤 「프로필 저장」. 저장은 설정 창의 확인과 별개로 바로 기록된다.

- API 키는 Windows 는 DPAPI, macOS 는 키체인에 저장되고 설정 파일에는 쓰이지 않는다. 프로필을 지우면 키도 지운다. 쓰고 있던 프로필을 지우면 Claude Code 로 되돌아간다.
- 주소가 `http://` 이고 localhost 가 아니면 SQL 과 이미지가 암호화 없이 전달된다는 안내가 뜬다.
- 프로필 경로는 프록시 설정을 따르지 않고 입력한 주소로 직접 연결한다. OpenAI 형식 프로필의 실행과 연결 테스트·모델 새로고침은 HTTP 리다이렉트도 따르지 않는다(Anthropic 형식 프로필의 실행은 `claude` 실행 파일이 연결하므로 Oranda 가 정하지 않는다). 프록시로만 외부에 나갈 수 있는 PC 에서는 클라우드 프로필이 연결되지 않을 수 있다. Claude Code 경로는 예전과 같다.
- 모델이나 주소를 바꾸면 앞 대화는 이어 말할 수 없다. 새 대화로 시작한다.

## 일반 대화

AI 대화 창은 튜닝을 시작하지 않아도 처음부터 쓸 수 있다. 활성 문서가 지금 접속의 SQL 탭이고 커서 아래에 문장이 있으면 그 문장 범위에서 DB 도구를 쓴다. 활성 문서가 SQL 탭이 아니거나(PL/SQL 편집기, 객체 상세) 다른 접속의 탭이면 문장과 DB 도구를 쓰지 않고 답한다. 접속의 AI 허용 수준이 「끔」 이면 DB 도구를 쓰지 않는다. 도구를 쓸 때는 그 문장도 함께 보낸다(가리는 대화는 값을 가려서). 「새 대화」 단추로 처음부터 다시 시작한다.

운영 접속이거나 설정에서 리터럴 가림을 켠 대화는 SQL 문장과 도구 결과의 값만 가린다. 입력한 글과 이미지는 가려지지 않으므로, 글은 대화당 한 번, 이미지는 새로 보낼 때마다 확인 창을 거친다.

## 이미지 첨부

대화 입력칸에 붙여 넣기(`Primary+V`), 끌어 놓기, 파일 선택으로 이미지를 붙인다. 한 번에 5장, PNG·JPEG·WebP·GIF 이며 큰 이미지는 줄여서 보낸다. 프로필이 이미지를 지원하지 않는다고 표시돼 있으면 첨부할 수 없다. 이미지 안의 값은 가려지지 않는다.

## 레포트와 계획

- 튜닝이 끝나면 대화 창에서 결과를 Markdown 이나 HTML 레포트로 저장할 수 있다. 가린 대화는 가려서 보낸 자리표시(`:v1` 등)가 그대로 남는다.
- 실행 계획 창은 SQL 탭마다 자기 계획을 보여 준다.
- 「실행하고 실제 계획(A-Rows)」(`Primary+Alt+Shift+E`, 툴바·튜닝 메뉴·계획 창 단추): 일반 실행(`Primary+Enter`)과 같이 선택 영역이 있으면 그 글을, 없으면 커서 아래 문장을(「빈 줄로 문장 나누기」 를 켠 때만 빈 줄로도 나눈다. 선택 영역에 문장이 여러 개면 실행하지 않고 안내한다) 힌트를 넣은 사본으로 실행해 모든 행을 읽고 A-Rows 가 있는 실제 계획을 연다. 조회(SELECT)만 되고 `FOR UPDATE`, DML, WITH 뒤에 오는 DML 은 거부된다. 받은 계획이 실행한 글과 다르면 열지 않는다. 편집기 글은 바뀌지 않는다.

## 튜닝 명령

AI 튜닝 단추(툴바)의 ▾ 목록에서 고른다. SQL 탭에서 쓰며, 설정에서 AI 모델을 골랐고 접속의 AI 허용 수준이 「끔」 이 아니어야 한다. 아래 세 명령은 문장을 실행하지 않는다.

| 명령 | 하는 일 | 쓸 수 있는 때 |
|---|---|---|
| 실행 계획 해설 | 커서 아래 문장의 실행 계획을 풀어서 설명한다. 계획 창에 이 문장의 계획이 떠 있으면(「실행하고 실제 계획」 으로 연 계획 포함) 그 계획을 읽고, 아니면 예상 계획을 읽는다. 읽을 계획이 없으면 안내만 한다 | 접속의 AI 허용 수준이 「계획」 이상 |
| SQL 설명 | 커서 아래 문장이 하는 일을 설명한다. 필요한 테이블·열의 구조만 읽는다 | AI 허용 수준이 「끔」 이 아닐 때 |
| 오류 고치기 | 마지막 실행 오류가 난 문장을 오류와 함께 보내 고친 문장을 받는다 | 실행 오류가 있을 때 |

- 오류 고치기는 고친 문장을 실행하지 않는다. 비교 창에서 확인하고 적용하면 원래 탭은 그대로 두고 「원래 탭 이름 (수정)」 새 탭에 넣는다. 오류가 난 탭이 지금 탭이 아니거나, 문장이 바뀌었거나, 접속을 바꾼 뒤이면 보내지 않고 안내한다. PL/SQL 실행 창의 오류는 고치지 않는다.
- 가리는 대화(운영 접속 포함)에서는 오류 문구를 보내지 않고 ORA 번호와 위치만 보낸다.
- 오류 앞에 한글 같은 멀티바이트 글자가 있으면 오류 위치가 실제보다 뒤로 표시될 수 있다.

## 조인 문법

설정 > AI 모델 의 「AI 가 쓰는 조인 문법」 에서 Oracle(기본) 또는 ANSI 를 고른다. Oracle 은 쉼표로 나열한 FROM, WHERE 의 조인 조건, 외부 조인의 `(+)` 이고, ANSI 는 `JOIN … ON` 이다. 대화 중에 바꾸면 다음 요청부터 따른다.

- 튜닝의 재작성 제안은 고른 문법으로 쓴다. 원래 문장이 다른 문법이어도 바꾸며 결과 집합은 같아야 한다. FULL OUTER JOIN 처럼 고른 문법으로 쓸 수 없는 조인은 다른 문법으로 두고 이유를 적는다. 한 쿼리 블록에 ANSI 와 `(+)` 를 섞지 않는다.
- 오류 고치기는 조인 안의 오타처럼 작은 오류는 그 조인의 문법(ANSI 든 Oracle 이든)을 유지하고 그 자리만 고친다. 조인을 새로 넣거나 구조를 다시 써야 할 때만 고른 문법으로 쓴다.
- 이 규칙은 AI 에 주는 지시이며, 결과가 규칙대로인지 Oranda 가 검사하거나 바꾸지는 않는다. 적용 전에 비교 창에서 확인한다.

## 벤치마크 제한 시간

설정 > AI 모델 의 「운영 벤치마크 제한 시간(초)」 은 운영 접속에서 AI 벤치마크가 문장 하나(반복 전체)에 쓸 수 있는 시간이다. 기본 30초이고 5~3600초 또는 0 을 입력한다. 0 은 제한 없음으로, 사용자가 중지할 때까지 운영 DB 에서 실행하므로 시작 창에 경고가 뜬다.

- 튜닝 시작 창(운영 접속에서 벤치마크를 켰을 때)에서 이번 실행만 바꿀 수 있다. 이 값은 설정에 저장되지 않고 이어 말하기에도 쓴다. 개발·테스트 접속은 항상 제한이 없다.
- 일반 대화는 시작 창 경고가 없으므로 설정이 0 이어도 30초를 쓴다.
- 호출 1건은 「제한 × 변형 5개」 까지 걸릴 수 있다. 그동안 다른 호출은 2분 기다린 뒤 `busy` 를 받는다.
