# Tibero 사용 안내 (사내 배포용)

이 쪽은 Tibero 에 접속하려는 사용자를 위한 안내입니다. 공개 사용 설명서와 공개 릴리스 노트에는 싣지 않습니다(결정 D-046·25).

## 지원 범위

- 대상 서버: Tibero 6 이상. 시험은 6.2.15 로만 했고 Tibero 7 은 서버가 없어 확인하지 못했습니다.
- 접속·SQL 실행·취소·결과·DBMS_OUTPUT 을 쓸 수 있습니다. 스키마 브라우저·실행 계획·모니터·튜닝은 단계적으로 열립니다.
- 아직 만들지 않은 영역의 메뉴는 숨기지 않고 회색으로 두며, 마우스를 올리면 「Tibero 에서는 아직 지원하지 않음」 이유가 보입니다.
- Tibero 에 없는 기능(SQL 모니터 보고서·AWR·ASH·세션 트레이스·TKPROF·옵티마이저 트레이스·Java 소스)은 「Tibero 에서는 지원하지 않음」으로 보입니다.
- TLS·지갑·Autonomous 접속은 Oracle 전용입니다.
- 상태 표시줄에는 서버가 `Tibero 6.2` 처럼 보이고, 오류는 `TBR-nnnn` 번호로 나옵니다.

## 드라이버 받기와 지정

Tibero 드라이버(TDP.NET Core, `Tibero.DataAccess.dll`)는 TmaxTibero 라이선스라 앱에 들어 있지 않습니다. tibero.com 기술지원에서 TDP.NET Core(1.1.x, 확인된 버전 1.1.35)를 받으세요.

1. 받은 `.nupkg` 를 풀거나 그대로 둡니다. 압축을 풀었다면 `lib/net5.0/Tibero.DataAccess.dll` 이 드라이버입니다.
2. 설정 > 「드라이버」 탭(또는 명령 팔레트의 「Tibero 드라이버 지정…」)을 엽니다.
3. 칸에 dll 파일·dll 이 든 폴더·`.nupkg` 중 하나의 경로를 적거나 [찾아보기…]·[폴더…]로 고릅니다.
4. [확인]을 눌러 상태 줄을 봅니다.
   - 「Tibero.DataAccess 1.1.35 — 사용 가능」: 쓸 수 있습니다.
   - 「시험하지 않은 버전이지만 사용할 수 있음」: 1.x 의 다른 버전입니다. 동작은 하지만 확인된 버전이 아닙니다.
   - 「.NET Framework 용 TDP.NET(2.x)은 쓸 수 없음」: TDP.NET Core 1.1.x 가 필요합니다.
   - 「Tibero 드라이버가 아님」·「파일 없음」: 경로를 다시 확인하세요.
   - 「쓸 수 없음(없는 멤버: …)」: 파일은 맞지만 필요한 기능이 없는 버전입니다.
5. 설정 창의 「저장」을 누릅니다. 이미 드라이버를 읽은 뒤에 경로를 바꾸면 「다시 시작하면 적용」으로 보입니다.
- [지우기]는 칸을 비우고 바로 저장합니다.
- 개발·시험용으로 환경 변수 `ORANDA_TIBERO_DRIVER` 에 dll 경로를 두면 설정보다 먼저 쓰입니다.

## 접속

접속 관리자에서 DBMS 를 Tibero 로 고르고 호스트·포트(기본 8629)·DB 이름을 적습니다. 드라이버가 지정되지 않으면 접속 대화 상자에 안내 띠가 나오고 [연결]·[접속 시험]은 꺼집니다.

## Oracle↔Tibero·Tibero↔Tibero 복사

데이터 복사(「데이터 복사」 창)로 Oracle 과 Tibero 사이, 그리고 Tibero 끼리 테이블 데이터를 옮길 수 있습니다. 사내 전용 기능이며 공개 설명서에는 싣지 않습니다. 설계는 `docs/design/cross-dbms-copy.md` 에 있습니다.

### 되는 것

- 쌍: Oracle→Tibero, Tibero→Oracle, Tibero→Tibero. 그 밖의 다른 DBMS 쌍은 「복사할 수 없습니다」 안내가 나오고 막힙니다.
- Tibero→Tibero 는 같은 DBMS 끼리라 값을 바꾸지 않고 그대로 옮깁니다. Oracle→Oracle 복사 동작도 바뀌지 않았습니다.
- 「없으면 만들기」: 대상에 테이블이 없으면 원본 구조로 만든 뒤 넣습니다(양방향 범위).
- 「테이블 다시 만들기」: **Tibero→Oracle 만** 됩니다. Oracle→Tibero 는 막힙니다. 옛 테이블을 지운 뒤 새 테이블을 만들지 못하면(이름 충돌 등) 그 자리에서 휴지통에서 되살려 옛 테이블과 데이터를 그대로 돌려놓고 결과에 알립니다(같은 DBMS 끼리의 다시 만들기도 같습니다).
- 한 번에 읽고 쓰다가 배치가 실패하면 한 행씩 다시 넣는 방식, 실패 행 기록·재시도, 중지는 같은 DBMS 복사와 같습니다.

### 바뀌어 옮겨지는 형식

상대 DBMS 에 같은 형식이 없으면 가장 가까운 형식으로 바꿉니다. 바뀌는 열은 사전 점검 「형식 바꿔 옮김」에 테이블마다 한 줄로 나옵니다.

| 원본 | 대상에서는 | 비고 |
|---|---|---|
| Oracle BINARY_FLOAT·BINARY_DOUBLE | NUMBER 글자로 보내 Tibero 가 BINARY_* 로 바꿈 | NaN·무한대 값은 그 행이 실패합니다 |
| Oracle TIMESTAMP WITH TIME ZONE 의 시간대 지역 이름 | 그 시각의 UTC 오프셋(±HH:MM) | 지역 이름은 잃습니다 |
| Tibero TIMESTAMP WITH TIME ZONE | 오프셋만 옮김 | Tibero 대량 읽기가 지역을 주지 않아 지역은 잃습니다 |
| Tibero VARCHAR2 > 4000 | CLOB | 테이블을 만들 때만. 이미 있는 대상 테이블은 「대상 열이 좁음」으로 알립니다 |
| Tibero NVARCHAR2 > 2000·NCHAR > 1000 | NCLOB | Oracle 4000바이트 한도 때문 |
| Oracle RAW > 2000(EXTENDED) | BLOB | 테이블을 만들 때 |
| Tibero LONG / LONG RAW | CLOB / BLOB | Oracle 원본의 LONG 은 아래 「빠지는 열」 |
| Oracle IDENTITY 열 | 일반 열 | 테이블을 만들 때. Tibero 에 IDENTITY 가 없어 값만 옮깁니다 |
| 길이 0 인 Oracle BLOB | Tibero 에서 NULL | Tibero 가 길이 0 BLOB 을 NULL 로 저장합니다. BLOB 열이 있으면 사전 점검 「빈 BLOB 은 NULL」로 알립니다 |

그 밖의 NUMBER·FLOAT·CHAR·VARCHAR2·NCHAR·NVARCHAR2·CLOB·NCLOB·BLOB·RAW(≤2000)·DATE·TIMESTAMP·INTERVAL 은 그대로 옮깁니다. 숫자는 글자로 옮기며 Tibero 가 39자리 이상은 반올림해 저장합니다. Tibero 의 BINARY_FLOAT·BINARY_DOUBLE 은 Oracle 로 그대로 옮깁니다.

### 빠지는 열

대상으로 옮길 형식이 없는 열은 오류가 아니라 복사에서 **빠집니다**.

- 양방향: TIMESTAMP WITH LOCAL TIME ZONE, ROWID·UROWID, BFILE·XMLTYPE·객체·모르는 형식.
- Oracle 원본만: LONG·LONG RAW, JSON·VECTOR·BOOLEAN(23ai)·컬렉션·SDO_GEOMETRY.
- Tibero 원본만: TIME·GEOMETRY.

빠지는 열은 사전 점검 「형식 때문에 뺀 열」(`ColumnDropped`)로 열마다 알리고 확인을 받으며, 실행 로그에도 「… 로 옮길 형식이 없는 열을 빼고 복사합니다」 한 줄이 남습니다. 대상 테이블을 원본에서 만드는 경우 그 열은 만들지도 않습니다.

- 빠지는 열이 기본키·기간 조건·부모 키 연결 열이면 「옮길 수 없는 키 열」(`KeyColumnDropped`) 오류가 되어 그 테이블을 규칙에서 빼야 합니다. 키가 없어져 행을 구별할 수 없기 때문입니다.
- 빠지는 열이 이미 있는 대상 테이블에서 NOT NULL 이고 기본값이 없으면 「필수 열 값 없음」 오류가 그대로 납니다.

### 사전 점검·실행 로그 안내

| 점검 이름(코드) | 등급 | 뜻 |
|---|---|---|
| 형식 때문에 뺀 열(`ColumnDropped`) | 확인 | 위 「빠지는 열」 |
| 옮길 수 없는 키 열(`KeyColumnDropped`) | 오류 | 키·기간 조건·부모 키 연결 열이 빠짐 |
| 형식 바꿔 옮김(`TypeConverted`) | 확인(값이 바뀌는 열이 있을 때) 또는 통과 | 위 「바뀌어 옮겨지는 형식」. BINARY_*→NUMBER·시간대 지역→오프셋처럼 값에 닿는 변환이 있으면 확인, 테이블 만들기에만 해당하는 변환(IDENTITY·RAW→BLOB·긴 문자열→LOB 등)만 있으면 통과 |
| 대상 문자셋 안내(`CrossCharset`) | 확인 | Oracle→Tibero 에 문자 열이 있으면 작업 전체에 한 번. 대상 DB 문자셋이 원본보다 좁으면 그 밖 글자가 실패하거나 바뀔 수 있습니다. 앱은 대상 문자셋을 조회하지 않고 늘 같은 안내를 냅니다 |
| 빈 BLOB 은 NULL(`BlobEmptyToNull`) | 통과 | Oracle→Tibero 에서 BLOB 열이 있을 때 |
| 문자열 바이트 한도(`CrossStringBytes`) | 확인 | Tibero→Oracle 에서 `VARCHAR2(n CHAR)` 열이 Oracle 의 4000바이트 한도를 넘을 수 있을 때. 열은 그대로 두고, 넘는 값이 있는 행만 실패합니다 |
| CHAR 뒤 공백(`CharPadDiffers`) | 통과 | Oracle→Tibero 에서 CHAR 열이 있을 때. 뒤 공백 수가 달라질 수 있습니다 |
| 시퀀스 함께 만듦(`SequenceCreated`) | 확인 | 테이블을 만들 때 원본 테이블에 연결된 시퀀스(열 `DEFAULT 시퀀스.NEXTVAL`, 그 테이블 트리거가 쓰는 시퀀스)가 대상 스키마에 없으면 테이블보다 먼저 원본 속성으로 만듭니다. START WITH 는 원본 다음 값이고, 적재 뒤 키 최댓값이 그 이상이면 그 위로 맞춥니다 |
| 시퀀스 기본값 뺌(`SequenceDefaultDropped`) | 확인 | 시퀀스를 만들 수 없거나(CREATE SEQUENCE 권한 없음·원본 속성을 못 읽음·다른 계정의 시퀀스) 대상이 Oracle 11g 이면(시퀀스는 만듦) 그 기본값만 빼고 만듭니다 |
| 대상 시퀀스가 키보다 뒤(`SequenceBehind`) | 확인 | 대상에 이미 있는 같은 이름 시퀀스는 건드리지 않습니다. 그 다음 값이 원본 키 최댓값 이하이면 알립니다 |
| 함께 만드는 객체(`CompanionObjects`) | 통과 또는 확인(빼는 것이 있을 때) | 새 테이블에 적재 뒤 함께 만드는 원본 트리거·권한·함수 기반 인덱스·작업 밖 부모 FK 와 만들지 않는 것 |
| 외부 도구로 적재(`ExternalLoad`) | 확인 | 적재 방식이 외부 도구인 테이블마다. 도구(SQL*Loader·tbLoader)와 버전, direct path 인지 일반 경로인지, 정리를 적재 전에 확정한다는 것, 실패하면 기본 방식으로 다시 넣는지 |
| 기본 방식으로 적재(`ExternalLoadFallback`) | 통과 | 외부 도구로 골랐지만 못 쓰는 테이블마다 그 이유(도구 없음·MERGE·「모두 끝난 뒤 한 번」 커밋·열 형식·인증 방식) |

### 제약과 주의

- 값 하나가 변환에 실패하면(NaN·무한대, 기원전 날짜, 모르는 시간대 지역 등) **그 행만** 실패로 기록됩니다. 열 전체를 빼지 않으며, 실패 행은 같은 DBMS 복사처럼 기록·재시도할 수 있습니다. 실패 이유에는 값을 싣지 않습니다.
- 시각 앞의 부호가 음수이고 시가 0 인 오프셋(`-00:30` 처럼 `-00:MM`)은 같은 시각을 `+00:00` 으로 바꿔 옮깁니다(Tibero 가 부호를 잃기 때문). 원본에 이미 `-00:MM` 으로 저장된 Tibero 값은 읽을 때 이미 부호가 틀려 있습니다.
- 테이블을 만들 때 가상 열은 만들지 않습니다. 함수 기반 인덱스·DESC(내림차순 열) 인덱스는 원본 인덱스 식을 읽어 적재 뒤 만들고, 식이 대상에 맞지 않거나 옮기지 않는 열을 쓰면 빼고 알립니다. 옮기지 않는 열이나 LOB 로 바뀐 열을 쓰는 제약·인덱스도 만들지 않습니다.
- 새로 만드는 테이블(없으면 만들기·다시 만들기)은 PK·UK·인덱스를 적재가 끝난 뒤 만듭니다(넣는 동안 인덱스를 고치지 않아 빠릅니다). 적재한 행의 키가 겹쳐 PK·UK 를 만들지 못하면 그 테이블은 실패로 끝나고 문장이 안내됩니다.
- 「없으면 만들기」 테이블에는 원본 트리거(적재 뒤, 컴파일 오류면 꺼 둔 채 남김)·원본 테이블 권한(대상에 받을 사용자·롤이 있을 때)도 만듭니다. 「다시 만들기」는 대상에 있던 트리거·권한을 되살립니다. 시노님·파티션·압축·테이블스페이스·저장 속성은 만들지 않습니다(대상 기본값). 이런 것은 사전 점검 「없으면 테이블 만들기」 안내와 실행 결과에 적힙니다. Oracle 23ai 의 도메인과 INVISIBLE 은 지우고(보이는 일반 열로) 만듭니다.
- 테이블을 만들 때 원본의 CHECK 조건·DEFAULT 식은 글 그대로 보냅니다. 대상이 받지 않으면 그 테이블의 만들기가 실패합니다(테이블 단위 실패).
- Tibero 의 CREATE TABLE 은 앞서 열린 트랜잭션을 **묵시 커밋**합니다. 테이블 만들기는 대상 트랜잭션을 열기 전에 하며, 넣기가 실패하면 만든 테이블을 휴지통 없이 지웁니다(`DROP TABLE … PURGE`).
- Tibero 원본의 외래 키는 지연(DEFERRABLE) 여부를 카탈로그로 알 수 없어, Tibero→Oracle 로 테이블을 만들 때 지연 FK 도 즉시 검사 FK 로 만들어집니다.
- Tibero 의 읽기 전용 트랜잭션은 쓰기를 막지 않습니다. 원본 보호는 앱의 정책 관문(읽기 전용 접속 등)이 합니다.
- Tibero 의 BLOB·큰 CLOB 은 한 행씩 쓰므로 Oracle→Tibero 대용량 복사는 느릴 수 있습니다.
- 시험은 Tibero 6.2.15(UTF-8 DB)에서만 했습니다. CP949 DB 로 옮길 때의 글자 손실은 확인하지 못했습니다.
- 문자 길이 단위: Oracle `CHAR(n CHAR)` 는 바이트로 채우고(CHAR(2000 CHAR) 는 2000바이트) Tibero 는 글자로 채워, 한글처럼 여러 바이트인 값은 뒤쪽 공백 수가 달라집니다(값 자체는 같음). 사전 점검 안내로 알리며 값을 맞추지 않습니다.
- 다바이트 값과 Oracle 4000바이트 한도: Tibero `VARCHAR(n CHAR)`(n ≤ 4000)를 Oracle 로 만들면 `VARCHAR2(n CHAR)` 열 그대로 만들어지고, 값이 4000바이트를 넘는 행은 그 행만 실패합니다(ORA-12899). 사전 점검이 안내합니다.
- 시퀀스를 DEFAULT 로 쓰는 열(`DEFAULT 시퀀스.NEXTVAL`): Tibero 카탈로그는 시퀀스 이름을 소유자·따옴표 없이 저장하므로 Oracle DDL 에서는 대상 계정의 같은 이름 시퀀스를 가리킵니다. 대상에 그 시퀀스가 없으면 테이블보다 먼저 원본 속성으로 만들고(만들 수 없으면 그 DEFAULT 만 빼고 안내), 적재 뒤 키 최댓값 위로 맞춥니다. 적재에 실패해 테이블을 지우면 이번에 만든 시퀀스도 지웁니다. 대상이 Oracle 11g 이면 열 기본값으로 쓸 수 없어(12c 부터 가능) 시퀀스는 만들되 DEFAULT 는 빼고 안내합니다.

## 외부 도구로 적재(tbLoader)

> 실험 기능: tbLoader 적재는 아직 실제 Tibero DB 에서 시험하지 않았습니다(설정·적재 방식 화면에 「실험」으로 표시). 중요한 작업은 기본 방식으로 넣거나 결과를 확인하세요.

데이터 복사의 테이블 규칙에서 「적재 방식」을 「외부 도구」로 고르면 Tibero 대상 테이블은 tbLoader 로 넣습니다(이번 실행이 만든 테이블은 direct path, 이미 있는 테이블은 일반 경로)(Oracle 대상은 SQL*Loader, 공개 설명서 「데이터 복사 > 외부 도구로 적재하기」). 작업 전체의 기본값을 정하고 테이블마다 따로 바꿀 수 있습니다.

- 앱이 원본을 읽어 임시 폴더에 데이터 파일·제어 파일을 쓰고 tbLoader 를 실행한 뒤, 로그·bad 파일을 읽어 넣은 행 수와 실패 행을 결과에 넣습니다. 임시 파일은 끝나면(실패·중지해도) 지웁니다.
- 비밀번호는 명령줄·파일에 남기지 않고 표준 입력으로 넘깁니다.
- 외부 도구로 넣는 테이블은 대상 정리(DELETE)를 적재 전에 확정합니다. 적재가 실패해도 지운 행은 돌아오지 않습니다.
- MERGE(키로 맞추기) 테이블과 「모두 끝난 뒤 한 번」 커밋은 기본 방식(앱의 배열 INSERT)으로 넣습니다.
- 도구가 없거나 실패하면 그 테이블은 기본 방식으로 다시 넣습니다. 도구가 없는 것은 사전 점검에서 알립니다.

### tbLoader 설치와 지정

tbLoader 는 TmaxTibero 라이선스라 앱에 들어 있지 않습니다.

1. Tibero 클라이언트 설치본(또는 서버 설치본)을 설치합니다. tbLoader 는 `TB_HOME\client\bin\tbloader.exe` 에 있습니다.
2. 환경 변수 `TB_HOME` 이 있으면 설정 칸을 비워 두어도 자동으로 찾습니다. 없으면 설정 > 「드라이버」 탭 「외부 적재 도구」 묶음의 「tbLoader (Tibero 대상, 실험)」 칸에 `tbloader.exe` 경로나 그 폴더를 적거나 [찾아보기…]로 고릅니다. 칸이 비어 있으면 찾은 위치가 칸 안에 흐리게 보입니다.
3. [도구 확인]을 눌러 「사용할 수 있음 — 경로」와 버전 줄이 보이는지 확인합니다.
4. 설정 창의 「저장」을 누릅니다(`drivers.tbLoaderPath`, 비우면 자동으로 찾기).

- 「설치 방법」을 펼치면 설정 화면에서도 같은 안내를 볼 수 있습니다. tbLoader 줄은 Tibero 가 들어 있는 빌드에서만 보입니다.
