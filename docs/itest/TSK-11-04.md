## 3. 경로별 안전장치 표

접속 모드 4가지: **개발**(라벨 개발·읽기 쓰기), **운영**(라벨 운영), **읽기 전용**(개발 라벨 + 읽기 전용), **운영+읽기 전용**.
칸의 값은 기대한 정책 결과와 실제로 같았는지다. 모든 칸이 **통과**다(불일치 0). 「거절」 은 확인 창에 아니오, 「승인」 은 예.

| # | 경로 (진입점) | 개발 | 운영 거절 | 운영 승인 | 읽기 전용 | 운영+읽기 전용 | 되돌림 확인 |
|---|---|---|---|---|---|---|---|
| 1 | 편집기 실행 (`oranda.exec.runStatement`, 엔진 `Source=Editor`) | 통과: 물음 없이 실행, 미커밋 | 통과: 확인 1번, 「취소되었습니다」, 변경 없음 | 통과: 실행 뒤 커밋으로 확정 | 통과: 「거부됨」·읽기 전용 안내, 확인 창 없음 | 통과: 같음 | 롤백 명령으로 미커밋 해제 확인 |

SQL 문장 형태 25가지 × 모드 4가지(편집기 경로와 같은 엔진)도 모두 일치했다: INSERT·UPDATE·DELETE·MERGE, 소문자·줄 주석·블록 주석·힌트가 앞에 붙은 문장, PL/SQL 블록(동적 DDL 포함)·DECLARE 블록·CALL·EXEC·@파일, CTAS·ALTER·COMMENT·GRANT·TRUNCATE·DROP·PURGE·FLASHBACK·RENAME, 분류 불가 문장(`FOO BAR`), LOCK TABLE, ALTER SESSION, ALTER SYSTEM. 같은 문장·접속이면 요청한 기능(편집기·그리드·스크립트·모니터·확장)이 달라도 판단이 같다(`Policy_gate_result_is_the_same_whatever_feature_asks`).

### 알려진 한계 (결함 아님, 동작을 시험으로 고정함)

| 한계 | 시험 | 판단 |
|---|---|---|
| 분류가 틀려 정책 관문을 지난 **DDL** 은 서버 읽기 전용 트랜잭션이 막지 못한다(DDL 은 암묵 커밋으로 트랜잭션을 끝낸다). DML·`SELECT … FOR UPDATE` 는 막는다(ORA-01456). | `Observed_misclassified_ddl_is_not_stopped_by_the_server_read_only_transaction`, `Server_read_only_transaction_also_blocks_misclassified_changes` | 이중 방어가 DML 에만 유효. 분류기는 42문장 표(DDL 20여 형태 포함)에서 한 번도 틀리지 않았으므로 지금은 문제 없음 |
| 읽기 전용 프로필에서 `SELECT 자율트랜잭션함수 FROM dual` 은 DB 에 쓴다(문장은 질의, 별도 트랜잭션은 읽기 전용이 아님). | `Observed_autonomous_function_in_a_select_writes_even_on_a_read_only_profile` | 클라이언트가 막을 수 없다. 진짜 읽기 전용이 필요하면 DB 쪽 읽기 전용 계정을 써야 한다(사용자 문서에 적을 것) |
| `LOCK TABLE` 은 서버 읽기 전용 트랜잭션이 막지 않는다. | (정책 관문이 DML 로 분류해 거부함 — 매트릭스 `lock-table`) | 정책 관문이 막으므로 문제 없음 |

## 4. 평문 비밀번호 검색 결과

검색 방법: 시험이 실제로 만든 **데이터 폴더 전체**(`connections.json`, `settings`, `credentials/`, `oranda.db`·`-wal`·`-shm`, `logs/`, 충돌 보고)를 파일 바이트 단위로 훑어 비밀번호를 UTF-8 과 UTF-16LE 두 인코딩으로 찾았다. 앞뒤 두 단계로 했다: (a) DB 없이 합성 비밀을 넣은 입력으로, (b) 실제 Oracle 에 접속해 비밀번호 변경·`CONNECT`·권한 없는 `CREATE USER`·틀린 비밀번호 접속까지 일으킨 뒤. (b)는 시험 사용자의 비밀번호 3개(현재·바꾼 것·틀린 것)와 `#` 뺀 변형을 찾았다.

| 대상 | 방법 | 평문 건수 |
|---|---|---|
