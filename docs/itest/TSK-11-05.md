### 이번 시험의 한계: 실제 앱 화면 조작은 하지 못했다

시험 PC 화면이 잠겨(LogonUI) 있어 스크린숏이 완전히 검정이었다. 그래서 Task 가 요구한 「실제 앱에서 손으로 확인」 은 하지 못했다. 대신 아래로 대체했다.

- 단위·Headless(Avalonia 가상 화면) 시험이 화면의 뷰모델·컨트롤 동작을 거친다.
- 통합 시험이 실제 Oracle(26ai·11g)에 붙어 실행·취소·편집·트랜잭션을 거친다.
- 눈으로만 판정되는 항목은 5장 「사용자 확인 목록」 으로 넘긴다. 스크린숏 경로는 없다.

기능 ID 마다 「실제 앱 한 번 실행」 이라는 acceptance 는 **충족하지 못했다**. 5장의 확인이 끝나기 전에는 wbs 를 닫을 때도 이 한계를 note 에 적는다.

## 4. 시험 약함·없음 정리

7장 표의 「부분 통과」 25개와 「시험 없음」 1개는 메모 칸에 빠진 부분이 적혀 있다. 대표적인 것: CONN-03 실제 TLS/mTLS 핸드셰이크, CONN-08 NLS 가 접속 때 실제로 적용되는지, CONN-12 Keep Alive 호출, EDIT-07 열 선택, GRID-08 NULL 색, EXEC-08 화면, APP-05 서명 검증·오프라인 설치 파일. 이들은 결함이 아니라 시험 보강 후보다.

## 6. 실행 방법

```
ORANDA_IT_ADMIN_PASSWORD=<26ai 비밀번호> ORANDA_IT_SYSTEM_PASSWORD=<같은 값> \
ORANDA_IT_11G_DATASOURCE=127.0.0.1:1522/XE ORANDA_IT_11G_SYSTEM_PASSWORD=<11g 비밀번호> ORANDA_IT_11G_DISABLE_OOB=1 \
dotnet test tests/<프로젝트> --no-build --filter "Category!=Perf&Category!=Integration"   # 단위
dotnet test tests/Oranda.App.Tests --no-build --filter "FullyQualifiedName~Oranda.App.Tests.Integration"   # 앱 통합
dotnet test tests/Oranda.App.Tests --no-build --filter "(Category=Integration|Category=Perf)&FullyQualifiedName!~Oranda.App.Tests.Integration"   # 분류 시험
dotnet test tests/Oranda.Oracle.IntegrationTests --no-build   # Oracle 통합
```

기능 ID 와 시험 이름의 대응은 `trx` 결과와 자동으로 대조했다(시험 이름 → 통과/실패). 시험 이름이 클래스 묶음 표기인 몇 개 ID 는 사람이 방법 이름으로 확인했다.
